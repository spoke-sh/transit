## Question

Which concrete interaction and evidence rules should the first shared renderer
implement from the Atlas, Console and Grammar explorations?

## Proposal

Use one monochrome Transit shell and one versioned declaration graph. Workspace
contains the Atlas, Explore, definitions and Activity; Operations exposes the
installation's authorized foundations and separately admitted change review.
At the 1440-pixel reference width, use the selected 56-pixel header, 208-pixel
navigation and 32-pixel content spacing. Narrow screens collapse navigation into
an explicit labeled control. Comfortable and compact themes change spacing and
type tokens; identities, bounds, labels and authority stay identical.

The fixed component artifacts interpret the declaration; SQL, forms and diagram
editing all return to the owning Zig validator. No JavaScript SQL parser or
second configuration database can publish a different meaning. Changing a theme,
representation or route never submits a query or administrative operation.

Atlas summaries use the public bounded acquisition and preserve independent cuts.
Unknown members cannot affect displayed aggregates. A denial removes the old
contribution; a renderer cannot retain it as a visual convenience. Associations
describe participation and never ownership or permission. Quantitative encodings
use labels and a disclosed scale; themes cannot change their numeric meaning.

Live is a deliberate read-session action with a finite starts budget and one
coalesced latest draft. Compile complete supported read queries before admission.
Keep earlier-draft and exact results visibly distinguishable; a candidate becomes
exact only after complete verification. Existing M21 owners retain uncertain
controls across route changes, and renew independently of source/result reads.
No freshness prediction is selected without measured evidence.

Operator editing is separate from shared inspection and query identities. Review
shows the current operator, application, exact base revision/digest, proposed
definition and permitted operation before submission. Uncertain submission offers
recovery of the frozen operation; a known conflict requires a new reviewed plan.
Bootstrap/recovery credentials remain outside editable interface definitions.
No OIDC provider is selected by this profile.
