# M30 — Interactive queries and storage amplification

[Roadmap](README.md)

Status: **In progress**. Follows [M29](M29.md), before [protocol consolidation](M31.md).
The accepted workload priorities live in the public [workload model](../../reference/workloads.md)
and [performance analysis](../../reference/performance.md).

## Scope and owners

1. Repeatable query measurements: empty/populated Tables, repetition and retained
   history, explicit cache controls, first output/completion, CPU/resident memory,
   native attempts and provider I/O. Separate instrumented measurements and idle
   polling; record executables and fixture provenance.
2. A neutral interactive contract: a fresh snapshot/session per SELECT, current
   permission at every disclosure, bounded leases and quotas, cancellation on
   exit, completion races and incomplete output. Durable jobs retain their own
   explicit submission/recovery contract.
3. Generic leased resource snapshots in the authority; client-side Zig Fuze and
   bounded native Arrow presentation above the public client boundary. Qualify
   Table, KV and Document before switching the console default.
4. Reduce shared read amplification with bounded metadata/range reads, descriptor
   reuse and verified immutable caches. Never cache permission as an access grant.
5. Reduce write amplification with bounded tree update batches, then generic bulk
   immutable publication and workload-specific Table blocks/pruning. Preserve
   final atomic publication, retained versions, quotas and uncertain recovery.

The snapshot profile belongs to the native protocol/core/client. Query budgets,
source policy, SQL, execution and presentation stay in Query/Fuze/CLI. Provider
layout and immutable page caching remain in the Ursula adapter. Each change owns
its contract, focused tests, public explanation and logical commit.

## Qualification

Measure the real owned disk-backed installation; do not alter existing developer
data or compare differently built executables as an isolated optimization.
Exercise lost responses, restart-invalid sessions, principal epoch changes,
revocation after a prefix, resource retirement/expiry, concurrent source writes,
lease exhaustion, bounded memory and output failure. Preserve durable query
recovery and the accepted state/authority proofs. New storage formats require
explicit compatibility and crash/uncertainty evidence.

Record executed commands and limits in [the proof ledger](../../../tests/README.md).
An incomplete or skipped check is not passing evidence. No latency SLO is selected.


## Implemented profile and evidence

- Measurement runners cover empty/default local execution, populated Table/KV/
  Document sources, repeated queries, retained history, disabled/bounded cache,
  native/provider attempts, first stdout, completion and sampled memory/CPU.
- The neutral snapshot contract and generic native operations are implemented.
  Each statement gets a fresh cut; current authorization, bounded admission,
  renewable/hard deadlines, explicit completion and cancellation remain required.
- Console execution defaults to client-side Fuze and native Arrow for all three
  source kinds. Explicit durable mode retains saved-intent/recovery semantics.
- Combined snapshot acquisition/data/current validation and final release,
  descriptor reuse, 64-entry/32-KiB range prefetch and eight-key Document chunk
  batches reduce shared read work. Older snapshot operations remain supported.
- Exact-root immutable control records have a separate bounded cache; scan data
  cannot evict all principal/process/resource/grant metadata. Current authorization
  and final journal barriers remain mandatory; unrelated writes during captured
  data materialization need only refresh final current validation.
- Growing node/gateway connections reuse bounded sockets, reserve data/control
  admission separately and keep network reads/writes outside serialized authority
  work. Queue/engine/page-cache observations and native/provider attempt timing
  expose remaining costs. Local worker/courier idle polling backs off to one second.
- Resource-entry mutations share tree paths; sibling immutable pages use bounded
  provider batches with independent acknowledgement validation. Table primary-key
  equality/range access avoids unrelated source pages.

Executed evidence is in the [proof ledger](../../../tests/README.md#fresh-interactive-console-execution)
and [public performance reference](../../reference/performance.md). The measured
empty local query is 15–18 ms across eight uninstrumented samples in the latest
control, with three console native reads in the separate instrumented fixture;
populated interactive queries issue no durable updates. Public measurements distinguish
proxy overhead, background polling and concurrent qualification.

The selected page-batch primitive keeps format 2 and the existing authority
commit. It does not expand application inline values or turn budgets. Persistent
columnar Table blocks, block-statistics pruning and a larger application payload
publication contract remain in the broader storage scope above; they are not
prerequisites for using the implemented interactive profile and are not claimed
as completed by its tests. Physical page reclamation remains unsupported.


Issue [#19](https://github.com/rupurt/rey/issues/19) adds prompt reuse after Ctrl-C
in both console execution profiles. Durable queries reconcile frozen intent,
observe closure and release the active slot. Interactive queries stop local
evaluation and release their leased snapshot. Explicit durable query shells
retain their existing recovery semantics. Qualification is recorded in the proof
ledger with the implementation.
