# M23 — Board grammar and declarative reactive applications

[Roadmap](README.md)

Status: **Complete for the selected profiles**; follows [M22](M22.md), building
on the qualified profiles of [serving M19](M19.md), [reactive APIs M20](M20.md) and
[reactive interfaces M21](M21.md). Precedes [Transit CLI M24](M24.md), which
reuses the shared grammar/catalog assistance, then [publication M28](M28.md)
and [clustered execution M29](M29.md).

Scope: implement the Board design explorations as a coherent monochrome reactive
UI, connect the SQL and visual grammars through shared typed definitions, and
prove reuse through a small downstream reactive application. Include explicit
definition publication, a checked application development workflow and recoverable
migrations. [Board grammar D1](../design/board-grammar/D1.md) opens the design
review; [reactive applications](../REACTIVE_APPLICATIONS.md) owns the proposed
system model. Design acceptance and runtime qualification remain separate.

The first implementation slice adds `transit-station-app`: bounded neutral types,
complete SQL/JSON validation, canonical SQL, a reflected structural schema and an
offline compiler. Independent ANTLR/model round-trip and allocation-failure tests
cover this slice. The conditional publication owner now composes immutable bodies,
current per-operator policies and exact receipts within four mutations; independent
binary fixtures and owner tests cover races, denial and retained revision growth.
Signed native publication now passes three worker kills with node/disk restart,
exact lost append/activation replies, stale-generation rejection and current denial.
The real handler now receives bounded native upload commands and validates the
complete assembled program before publication; it records explicit denials.
Native administrative HTTP ingress and the declared shell/editor browser proofs
now pass. The Table Live draft browser now proves finite admission, coalescing and exact
saved recovery across reload; parser acceptance grants no rights. The actual
work-item data owner now qualifies two-row Table copying, complete verification,
conditional activation and explicit write release through fresh-key worker and
node/disk recovery. The generated native browser now qualifies three-page results,
schema/interface switching and original-query recovery. Compose and reference
also pass the physical replacement schedule. All 59 ordinary tasks pass across
five isolated clean lanes at `21089bb`; the
[proof ledger](../../../tests/README.md#m23-and-m24-final-clean-qualification) records
coverage, costs and limits. The native worker migration run measured 15.75 seconds.

## Entry gates

Carry M19/M20's executed limits into composition: four live sessions per service,
two per caller, one subscription per session and a maximum 30-second lease in the
initial profile. These are aggregate deployment limits, not entitlements for
each generated panel. Share the M21 scheduler and keep accepted-operation recovery
outside disposable render state. Physical restart may require explicit session
reopening while the original operation remains recoverable. Add KV/Document
bindings only after their watch adapters are qualified; a finite query adapter
does not supply change notifications. Validate streaming envelopes and their
decoded content separately. M22's client/type matrix remains independent of
the browser matrix and must constrain generated Flight bindings.

Carry M21's implementation findings into generated bindings: metadata inspection
and value-read permission are separate; complete result replacement requires a
bounded coverage pass and a current-authority visible reread. Account for clock,
renewal and attachment history alongside finite query results. The initial Follow
owner budgets eight selected intents per explicit generation; generated draft
execution needs its own explicit budget policy, not an unbounded reset of Follow.
Same-origin Web Locks coordinate preparation of shared native caller sequences;
they are neither durable query admission nor coordination across origins/hosts.

The final M21 Compose/reference browser runs measured about 7.6/6.2 seconds from
the mutation trigger to the counter snapshot and 127/155 seconds to a completely
verified 20-row query refresh. Those single-run measurements include observation and verification;
they are not sustainable-rate or percentile targets. Do not infer interactive
draft execution from finite Follow correctness. Measure compile, admission,
capture, delivery, full verification and visible reread separately before
selecting automatic draft scheduling or speculative preview budgets.

## Implementation sequence

1. Finalize the monochrome design and a semantic vocabulary shared by Atlas,
   Console and downstream applications. Specify theme tokens separately from
   quantitative encodings, state labels and authority. Retain flat/keyboard paths.
2. Define versioned neutral types and independent fixtures for the selected
   declarations, capability map, publication and migration ledger. Implement
   bounded Zig validation and public-operation lowering. Extend the reference
   grammar and differential corpus only for statements with specified semantics.
3. Implement interface renderers and typed runtime validation in strict
   TypeScript/Vite+. Deliver the shared shell, Atlas, Explore, definitions,
   Operations and Activity using the inventory and qualified public reads.
   Queries keep Fuze semantics; business decoders remain outside Board inspection.
4. Compose M20/M21 clients for live views. Add D4 Live draft sessions as an
   explicit bounded read-only capability, with fair admission and correct result
   provenance. Add search, profiles and timings only from qualified evidence.
5. Implement conditional interface publication and recoverable migration steps.
   Provide generators and a runnable non-trading application following declare,
   bind, compose, migrate/observe. Use existing launchers and package boundaries;
   Board must consume the same shared primitives the example uses.
6. Qualify semantic agreement, authority boundaries, failure schedules, responsive
   and accessible UI, downstream reuse and measured costs. Record runtime evidence
   in [tests](../../../tests/README.md), usage beside the components and design
   decisions in the owning reviews.

## Exit criteria

Carry forward M21's control-dependency finding: source/schema discovery and
multi-page verification cannot block lease maintenance. Own and join renewal,
stream and candidate tasks independently of rendering, with one control owner
and bounded state. Exercise real route remounts while admission is uncertain;
keeping a hidden component mounted is not that recovery proof.

- [x] Every inventory row has an explicit selected implementation profile and
  evidence; unresolved design/contract gates stay open. Broader excluded work
  is named and receives separate milestone scope before implementation.
- [x] Board's supported shell, routes, sources, queries and actions can be
  reconstructed from a versioned declaration program plus referenced component
  and handler artifacts. The same typed definitions drive SQL, forms, diagrams,
  CLI and SDK surfaces. No second authoritative UI configuration store exists.
- [x] Shared fixtures prove semantic SQL → model → visual edit → SQL round-trip;
  invalid, unsupported and partially understood statements remain explicit.
  Reference-parser acceptance is never advertised as executable capability.
  Generated wire declarations/runtime validators derive from owning public types.
- [x] Queries lower to the existing qualified Fuze plans. Declarations and controls
  lower to their owning current-authority operations; no renderer, route, theme,
  name, association or generated file supplies an access grant.
- [x] Atlas and Console use the monochrome visual grammar. All selected semantics
  survive at least two presentation-token variants without using color as the
  sole cue. Keyboard, reduced motion, 320 px narrow view, zoom, focus, text contrast
  and a flat alternative are exercised in the real browser.
- [x] Stable atlas identities, hierarchy and aggregates stay bounded as retained
  cardinality grows. Filter before aggregation, preserve independent source bases,
  remove denied contributions and avoid double-counting resources/associations.
  Missing count/byte/age/history evidence stays unavailable. Publish measured
  populations and resident/scan/render budgets, with no billion-scale claim from
  the drawings. Growth cases never become observed facts or automatic scaling.
- [x] Reactive views use qualified M20/M21 adapters: no-gap acquisition, explicit
  reset, complete-result replacement, late-generation rejection, dirty-during-
  refresh convergence, pause/hide/close, denial clearing and cross-tab fairness.
  Missing KV/Document watches cannot inherit Table qualification. M22 adapters
  retain their own source/type/client matrix.
- [x] Live draft execution is explicitly admitted and bounded. Exact results,
  earlier-draft results and speculative candidates remain distinguishable and
  tied to their query/source basis and budget. Editing an administrative definition
  cannot execute it. Continuous Stream is unavailable in this profile.
- [x] Search/completion expose only authorized metadata with capability-aware
  suggestions. Profiles and charts bind to the same verified result; execution,
  readiness, data freshness and predicted readiness have separate provenance.
  Estimates never imply truth, authority or an unmeasured freshness guarantee.
- [x] Administrative Board actions require attributable, current scoped authority
  and exact revision review. Preserve M2 read-only inspection and M13 query
  separation; test cross-principal caches, revocation, bootstrap/recovery paths,
  lost replies, conflicting drafts and external unknown outcomes. Secrets remain
  references in SQL, diagnostics and transcripts.
- [x] Publication conditionally activates one immutable compatible interface
  revision. Real old/new clients handle upgrades without mixing binding/schema
  generations or losing accepted-operation recovery; reverting presentation
  cannot restore revoked rights or retired data.
- [x] Migration plans preserve exact step identity and digest through accepted-
  but-lost replies, coordinator restart, concurrent plans, schema conflicts,
  denial and partial completion. Reapply recovers receipts rather than redoing
  completed work. Unsupported changes fail before their admission.
- [x] Demonstrate compatible interface publication and one selected data evolution
  with bounded resumable backfill, explicit concurrent-write policy, verification
  and consumer switch. Prove no mixed schema/result publication. Rollback reports
  compatibility/inverse/compensation limits; it cannot undo external effects,
  permanent retirement or reclaim history implicitly. No cross-resource atomicity
  is claimed; retention remains unlimited by default.
- [x] A real generated non-trading application exercises declare → bind → compose
  → migrate/observe using the same shared packages as Board. Run the actual example
  binaries, browser/client and restart/lost-reply scenarios in native, Compose
  and reference placements. A scaffold or static preview alone does not pass.
- [x] Focused proofs, normal checks and clean committed-HEAD qualification are
  reproducible through real `just` tasks. Record source/protocol/placement coverage,
  per-step runtime cost and hosted CI limits under M10; skipped checks remain
  outstanding, and ordinary PR lanes do not silently acquire an unmeasured budget.

## Generated application evidence

`just test::work-items-browser` now runs the standalone generated work-item
frontend with actual, separately authorized native data/publication/requester
workers and disk-backed history. Nineteen rows cross three verified result pages.
The fixture copies/verifies/activates the target Table, updates query policy,
conditionally publishes revision 2 and only then releases normal writes. The
browser restores an accepted-but-lost upload through gateway replacement, retries
its exact bytes, refuses continuation under the changed source contract, cancels
that original work and explicitly runs against the new schema. Current read
denial clears protected data; two densities, narrow layout, keyboard and axe
checks pass. Compose and reference repeat the browser schedule while replacing
all owners, gateway, node and disk store, with fresh worker keys/generations.
The physical runs measured 164.23 and 383.26 seconds, including image work;
the [test ledger](../../../tests/README.md#m23-application-declaration-boundary)
records isolation, TLS, operator-placement and read-contention limits.

## Outside the selected profile

Incremental continuous SQL, arbitrary joins/windows or user-code plugins, generic
lossless event processing, automatic effects on edit/publication, cross-resource
transactions, universal schema evolution, implicit multi-realm federation and
production population/latency promises. OIDC or another human identity provider
must be explicitly selected and qualified, not inferred from the Operations
wireframes. M29 retains clustered authority movement, physical runtime portability
and disaster-recovery migration; M23's application workflow does not close those
gates. Completed M1–M22 scopes and evidence are not expanded retroactively.

Carry M21's control-cost finding into worksheet scheduling: draft/session controls
do not themselves constitute query demand. Schedule only qualified dirty work,
and measure retained wakeup/delivery cost separately from actual query starts.
A repeated recorded clock sample cannot authorize a later lease. Receipt polling
must not change the sampling interval or require the whole mailbox to empty.

M22 metadata qualification found a valid zero-body Arrow RecordBatch that the
pinned reader rejected. Generated worksheets and exports must preserve typed
empty results through the same native/independent readers; empty data is not an
access-denied fallback. Flight SQL metadata's union/list/map schema does not
expand the application SQL type profile. Keep capability discovery separate
from executable plans and test the exact installed client path.

Use the selected host deadline as an input to consumer timeout policy. M21's
five-second stream timeout was shorter than the host's thirty-second joined
request budget and caused attachment/control churn. A generated view must keep
renewal independent of data reads, allow legitimate slow reads to finish and
retain exact closure intent through transient capacity, without extending leases.

Recovery includes startup controls: an accepted open/subscribe/follow may lose its
reply before a view reaches its stream loop. Generated owners must reconcile the
frozen control from that point, preserve lease headroom before reattachment and
wait for an advancing committed clock when needed. The qualified reference
20-row query refresh took 155 seconds; do not present Follow as instantaneous
or select speculative refresh rates from counter-update timings.

Flight's installed ADBC path is a concrete compatibility boundary: the pinned
driver attempts preparation, then uses the qualified unprepared fallback. Keep
an explicit durable sequence with the SQL operation across process loss. A fresh
access ticket for the same retained query does not authorize a new execution.
The first Flight result types remain nullable int64 even though standard metadata
uses unions/lists/maps. Exports and generated bindings must select those profiles
explicitly, rather than inheriting unrelated M18 source or type coverage.

Carry terminal control outcomes through generated bindings. A lost HTTP reply
retains exact pending bytes; a committed rejection is settled and must observe
current scope for reset, expiry or denial. The final M21 multi-tab proof caught a
renewal loop that confused those cases. Generated renderers must not turn a
known terminal disposition back into repeated reconnect or implicit reopening.


The native M23 editor now composes the shared compiler and publication owner over
actual signed ingress. SQL/Form/Canvas edits, exact reviewed base/body/digest,
route-remount recovery of a lost admission reply, disk/worker restart and current
read denial have executable browser evidence. Draft editing is separate from the
retained reviewed proposal. Interface-driven shell replacement, migrations and
the generated application's physical placements have separate passing proofs
recorded above; the editor proof alone does not qualify those boundaries.


The selected [migration ledger contract](../../../contracts/APPLICATION_MIGRATION_V1.md)
reserves two of each normal step's four mutations for progress and its exact
receipt. The work-item evolution uses a deliberate write pause, distinct source
and target Tables, two-row backfill steps and a separate complete verification
pass. Interface activation stays a separate conditional owner; its existing
four-write publication cannot absorb a cross-resource schema switch. This is an
implemented selected evolution, qualified by the generated application and
physical-placement proofs. It does not provide a generic migration executor.

The finite draft budget now lives in the native v2 requester. Conditional explicit
generations freeze up to eight intents and source/result limits; each start debits
the same four-write commit as its query call. Cross-instance exact retry, budget
exhaustion, closed replay and current source denial pass for Table. The browser
scheduler now passes the separate Table browser schedule, including saved draft
recovery and current denial. KV/Document Live scheduling remains outside that profile.
