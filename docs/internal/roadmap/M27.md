## Selected scope

Both local server command names start and supervise a separate `transit-board`
process by default, with frontend assets bundled inside that executable.
`--no-ui` disables its process and listener for one invocation. Version 3
configuration pins the Board executable and loopback origin/port independently
of this option. No browser query or administrative credential is enabled.

Provision a separate retained inspection identity through exact public native
operations. Built-in resources and explicitly declared application inspection
scopes have recorded grant receipts; ordinary restart and replacement cannot
renew revoked grants. Bound startup, checks, restarts, diagnostics and joined
shutdown through the existing Linux manager. Package frontend assets and the
matching executable without a runtime source checkout or frontend toolchain.

## Exit criteria

- [x] Both aliases, default startup, headless initialization and UI toggling preserve history and identity.
- [x] Authorized atlas readiness, embedded assets, exact Host/Origin and public ready records pass.
- [x] Declared application resources remain inspectable after replacement; revocation survives restart.
- [x] Interrupted provisioning and lost replies recover exact operations and receipts.
- [x] Listener conflicts, incompatible artifacts, child/upstream failure and manager death have bounded outcomes.
- [ ] Nix packaged consumer, existing headless recovery, repository checks and committed clean qualification pass.
