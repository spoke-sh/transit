# M3 — Local and Compose development launchers

[Roadmap](README.md)

Status: implemented and qualified on Linux x86_64. Native and Docker Compose
profiles make the completed [Board slice](M2.md) usable as persistent development
systems for humans and agents.

## Outcome and scope

Provide a local grounding point and a container waypoint before Kubernetes
qualification. Both profiles run disk-backed Ursula, Transit, maintenance, the
counter example and Board through shared public-protocol provisioning. Launchers
manage development services; they add no runtime authority or Station behavior.

The [launcher guide](../../../launchers/README.md) owns commands, configuration,
credentials and operating limits. [M4](M4.md) adds service instrumentation;
[M6](M6.md) adds identified builds, targeted updates, a persistent reference
application and same-PID workload upgrades.

## Completed criteria

- [x] Start, inspect, stop and resume named installations with persistent realm,
  PID, mailbox, committed state and credentials.
- [x] Use shared provisioning and public client operations, separate Board read
  credentials, private installation files and explicit storage initialization.
- [x] Admit duplicate-safe example input and replace its worker with fresh,
  fenced ownership while retaining the PID and pending input.
- [x] Refuse to bootstrap over missing established storage, adopt occupied
  ports or reactivate a retired PID.
- [x] Provide configurable Board host, port and public origin for local or
  remote development while preserving authentication and origin checks.
- [x] Keep local and Compose `up` in the foreground with service/lifecycle
  output; interruption stops owned services and preserves durable data.

## Evidence and limits

`just launchers::local::test` and `just launchers::compose::test` qualify the real
services in isolated installations. The
[test guide](../../../tests/README.md#launcher-qualification) records recovery,
retry, fencing, foreground and configuration evidence.

These are trusted development profiles, not Substrate isolation proofs. Moving
between profiles does not migrate a live realm or its storage. Native code runs
as the developer; Compose uses ordinary container networking. Reference recovery
and adversarial isolation retain their separate qualification requirements.
