# M11 — Idiomatic language SDKs

[Roadmap](README.md)

Status: Qualified on Linux x86_64 with the pinned runtimes and Nix native
closures; follows [M10](M10.md), before [M12](M12.md).
All target languages have separate raw Transit and Station SDKs, typed
application codecs, scoped state/Table/query helpers, explicit recovery policies,
installable artifacts and executable service/requester examples. The
[SDK design](../SDK.md) records the shared contracts; package guides own usage.
M9's low-level interfaces and conformance proofs remain available.

Each public SDK passes the shared authority/recovery schedule, including all
mutation gates, callback failures, caller loss and cleanup, exact retry after
host/node/store restart, current authorization, fencing/retirement, retained
Tables and owned original query IPC. Optional PyArrow, Arrow JavaScript and
Arrow Rust adapters have separate ownership checks. Both Erlang and Elixir use
public behaviours and tagged results through supervised native-port workers.

The public interoperability ring covers ten different-language pairs, with every
target acting as service and requester. Installed counter CLIs resume durable
replies after requester restart; Table/query handlers preserve nullable signed
extremes, full-width integers and complete source metadata. This is a bounded
ring, not all 100 ordered pairs. The [test guide](../../../tests/README.md#public-sdk-interoperability)
records the platform/artifact matrix, shared scenarios and qualification limits.

The [local cost record](../../../tests/verification/results/m11-sdk-2026-09-26.json)
measures consumer installation and the public ring. It excludes artifact builds,
other SDK failure suites and CI setup/cache transfer. No new hosted CI budget
result is claimed; M10's accepted budgets and deferred runner optimization remain
separate. Publishing, portable native distributions and foreign Substrate workers
remain outside this milestone.

Scope: language-native programming interfaces for **C/C++, Rust, Python, Ruby,
Node.js/TypeScript, Java, .NET, and Elixir/Erlang** over the shared Zig client
and Station implementation. A programmer writes handlers, uses associated state,
exchanges typed messages and consumes Arrow results without manually pumping
the ABI or constructing its JSON actions. Preserve the existing Zig reference
caller and low-level bindings for conformance and explicit advanced use.

The [caller design](../CLIENT.md#idiomatic-language-sdks) owns the SDK boundary;
[Station](../STATION.md#languages-and-bindings) owns handler composition. M9
qualified interoperability, host ownership and failure behavior. M11 adds the
public programming experience without duplicating protocol semantics in each
language or expanding the bounded runtime profile implicitly.

## Entry gates

M10 must qualify the state-growth, capability and compatibility contracts first.
Do not freeze the legacy 32-key/four-resource catalog ceilings into public SDKs
or require retention opt-in merely to keep ordinary applications running.
SDKs expose per-operation budgets and explicit quotas while accessing durable
collections through bounded reads. Reuse the [testing strategy](../TESTING.md)
and shared scenarios rather than multiplying every protocol proof by every
language pair.

Design small equivalent applications in Python, TypeScript and Rust before
fixing the API. Review both service and requester code, including recovery and
error handling. Then adapt those concepts to the other language conventions;
matching method signatures across runtimes is not an acceptance criterion.

| Gate | Required decision / evidence |
| --- | --- |
| API ownership | Separate the shared Zig implementation, generated ABI/wire declarations and language-native public API; keep raw Transit usable without Station |
| Typed contracts | Define process/resource references, messages, receipts, errors and result types; specify versioned application codecs and runtime validation without hand-maintained wire schemas |
| Handler lifecycle | Define initialization, scoped turn access, handler return/failure policy, commit observation, shutdown and use-after-turn rejection; returning from a handler is not proof of commitment |
| Durable calls | Distinguish admission, turn commitment and reply completion; specify recoverable operation identities, exact pending requests, durable wait resumption and explicit cancellation |
| Runtime integration | Bound workers, ports, queued work and buffers; define sync/async APIs, native stack requirements, cancellation ownership and cleanup without blocking runtime schedulers |
| Data ownership | Map full-width values to host types; define byte/batch lifetime and optional Arrow adapters with complete-result provenance and no implicit lifetime extension |
| Packaging | Fix supported artifacts, native library/host discovery, version compatibility and clean installation on Linux x86_64; loading a package must not discover credentials or start work |
| Compatibility | Document migration from M9 wrappers, retain raw conformance entry points and reject unsupported API/ABI combinations explicitly |

Language SDK code may own dispatch, types, codecs, scheduling and packaging.
Signing, sequencing, proposal recovery, framework transitions and Fuze execution
stay in Zig. Fix missing shared capabilities there rather than adding a second
protocol implementation to a wrapper.

## Language conventions

These are the qualified interface conventions; package guides own exact API names.

| Target | Public interface direction |
| --- | --- |
| Python | Typed models, synchronous/asynchronous clients, context managers, named exceptions, ordinary integers and `bytes` |
| Ruby | Value objects, block-scoped clients/turns, named exceptions, `Integer` and binary `String`; bounded native-port work with explicit cleanup |
| Node.js/TypeScript | Typed service interfaces, discriminated outcomes, promises, explicit disposal, `Uint8Array` and `bigint` for full-width values; runtime validation at boundaries |
| Rust | Typed structs/enums, handler traits, borrowed turn contexts, owned buffers and `Result<T, Error>`; bounded scheduling with documented executor integration |
| C/C++ | Typed C operations and explicit ownership; C++ resource-owning wrappers, typed handlers/results and RAII |
| Java | Typed records/interfaces, closeable clients and bounded asynchronous operations |
| .NET | Typed records/interfaces, `Task`, asynchronous disposal and explicit local versus durable cancellation |
| Elixir/Erlang | Behaviours, pattern matching, tagged results and supervised local bridges; distinguish BEAM processes/PIDs from durable Transit processes/PIDs |

Ruby is a new M11 target, not an M9-qualified binding. Its integration uses the
shared native port, with separate client, Station and native gems. Ruby 3.4.9 and
its packaging tools are pinned. Service/requester, recovery and clean installation
now pass the same shared scenarios; no optional Ruby Arrow adapter is selected.
Python, TypeScript and Rust remain the first API design and implementation group.

## Implementation sequence

1. Write and review the Python, TypeScript and Rust application examples and API
   contracts. Cover happy paths, associated state, unknown outcomes and recovery.
   The linked design drafts cover these paths, including input-derived call
   correlations and persistence before control/turn mutations. Compile and run
   them against the implementation before treating the API gates as proved.
2. Separate generated/raw interfaces from the public SDKs; add typed references,
   versioned payload codecs, errors and recoverable operation objects. Keep exact
   signed retry bytes opaque and intact.
3. Add handler runners and scoped state/message helpers. The runner drives the
   shared poll/finish machine, reconciling an uncertain proposal before another
   handler can run. Supply explicit failure and bounded shutdown policies.
4. Expose Table/query results as owned IPC bytes plus qualified optional native
   Arrow integration. Preserve source revisions, completeness and supported
   schema/capacity limits.
5. Implement the equivalent public concepts for Ruby, C/C++, Java, .NET and both
   Elixir and Erlang. Adapt ownership and errors to each language; qualify both
   service and requester roles across languages.
6. Build installable artifacts with explicit native dependencies, package-local
   guides and runnable examples. Add focused checks to the existing CI lanes,
   retaining the optional foreign-tool shell and bounded cache strategy.

## Exit criteria

- [x] Every target language can implement a Station service, access associated
  KV/Table state, exchange typed messages and consume an Arrow query result
  through the public SDK. Common-path examples contain no manual ABI polling,
  generic JSON actions, hex conversion or repository-relative source imports.
- [x] Callers can use raw Transit independently of Station. Public SDK types and
  generated wire/ABI types have explicit ownership and version boundaries;
  generation rejects schema drift. Document supported M9 capabilities and
  intentional low-level escape hatches.
- [x] Typed application codecs preserve version and full-width values across
  language pairs. Reject malformed or unsupported payloads before handler use;
  define how decoding failures leave or explicitly block the mailbox head.
  Static types cannot substitute for ingress validation or authority checks.
- [x] A runner owns initialization and sequential handler dispatch. Mutations,
  input progress and outputs remain one proposal; no success is reported until
  the required durable outcome is confirmed. Handler failures discard private
  changes under a documented policy; unwinding, shutdown and garbage collection
  never implicitly acknowledge work.
- [x] Turn/resource handles cannot be used after completion or concurrently to
  bypass sequencing. Associated state stays authoritative; worker object fields
  are temporary. Helpers preserve M9 revision, grant, lifetime and transaction
  boundaries and reject unsupported scope.
- [x] Public APIs distinguish admission, committed processing and reply/effect
  completion. Durable call identity and waiting state survive worker loss;
  a future, task, coroutine or suspended stack is not advertised as durable.
  Cross-process waiting closes the current turn and resumes through recorded
  outcomes rather than holding a private turn open indefinitely.
- [x] Typed errors retain rejection, uncertainty, revoked access, stale ownership,
  permanent retirement and unavailable-history distinctions. Recoverable
  operation objects support opaque export/import of exact signed retry material;
  document persistence before dispatch when required and fresh-ownership
  reconciliation when it is lost. Test lost responses and host restart without
  replacing uncertain requests with new identities or duplicating mutation.
- [x] Cancelling a local await cannot imply durable cancellation or rejection.
  Explicit durable cancellation retains its advisory peer semantics. Test
  cancellation during native I/O, callback failure, graceful shutdown and abrupt
  host loss, including a confirmed or uncertain commit at each boundary.
- [x] Runtime tests prove bounded admission, responsive event loops/schedulers,
  documented thread/stack budgets and safe cleanup while work is in flight.
  Buffer and Arrow adapter ownership is checked across normal use, errors and
  disposal; no partial result is returned as complete.
- [x] Every SDK exposes original IPC bytes and result metadata. Qualify the
  optional Arrow adapters selected at the entry gate with independent consumers;
  preserve integer precision, source identity and current result access rules.
  JSON rows are not the sole result interface.
- [x] Install each language's built artifact and native dependencies into a
  clean consumer outside the repository source tree. Run documented examples
  without manual library-path assembly; allow explicit native-path overrides.
  Test incompatible versions and missing artifacts with actionable errors.
- [x] Keep M9's low-level conformance proofs and add the same failure obligations
  through public SDKs, including fencing, revocation, expiry and fresh-worker
  recovery. Type/compile checks and executable documentation examples cover each
  language's intended usage. Map the evidence and limitations in the test guide.
- [x] Document package APIs, installation, failure/recovery semantics and migration
  beside their implementations. Keep foundational documents focused on shared
  guarantees and record the qualified platform/runtime matrix and CI cost.

## Outside this milestone

Documents/CRDTs remain [M17](M17.md); unified KV/Table/Document querying is
[M18](M18.md).
New connectors, SQL/Flight/ADBC, arbitrary suspended-stack recovery, automatic
multi-resource transactions and a second authoritative queue are excluded.
SDK ergonomics do not grant I/O isolation, stronger delivery guarantees or wider
state/result capacity.

The baseline remains Linux x86_64 with explicitly pinned runtimes. Installable
artifacts are required; publishing to public package registries, broad platform
support, browser execution clients and foreign-language Substrate worker images
need separate qualification and release scope. Local supervision of a bridge
never grants Transit ownership or replaces Station's durable supervision.
