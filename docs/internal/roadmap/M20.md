# M20 — Reactive APIs: SSE, WebSocket and API contracts

[Roadmap](README.md)

Status: Qualified initial int64 Table profile following [M19 serving](M19.md),
before [M21 reactive interfaces](M21.md). Durable sessions/subscriptions,
authorized snapshot/watch, bounded SSE/WebSocket and generated OpenAPI 3.2.1 /
AsyncAPI 3.0 are implemented. Independent native TLS, Chromium, Compose and
Substrate/reference recovery proofs pass. The [proof ledger](../../../tests/README.md#m20-qualification)
records measured costs and deterministic versus deployed evidence; the
[compatibility matrix](../../../packages/zig/transit-serving/docs/compatibility.md)
keeps Board/KV/Document watches and reactive SDK wrappers unavailable.

Scope: qualify SSE and a bounded bidirectional WebSocket subprotocol over one
shared typed session/message/subscription contract. Publish accurate OpenAPI
HTTP/SSE and AsyncAPI WebSocket descriptions from the same owning definitions.
[Reactive APIs](../REACTIVE_API.md) owns these semantics; M19 owns base serving
and durable operation admission, while M21 owns live-view refresh and presentation.

## Hosted API surfaces

Hosting a reactive API means publishing a typed, versioned interaction contract
and enforcing it throughout each session. A connection, logical session,
subscription, accepted command and event cursor have separate identities and
lifetimes. Applications can consume this API independently of Board.

| Surface | What Transit hosts |
| --- | --- |
| HTTP with SSE | HTTP commands/control and server-to-client events, with authorized subscriptions and resume or explicit reset |
| WebSocket | Bounded bidirectional commands, receipts/results, subscription control and events under a versioned subprotocol |
| OpenAPI | Generated HTTP/SSE descriptions tied to the accepted service revision, including security, streaming item schemas and errors |
| AsyncAPI | Generated WebSocket channel/message/operation descriptions from the same public types and operation metadata |

Both transport bindings share command identity, authorization and recovery.
If a WebSocket reply is lost, retrying through HTTP recovers the original
accepted command. A notification can trigger an exact snapshot refresh; it does
not imply every intermediate state was delivered or a continuous query was
maintained. M21 owns the view scheduling and presentation that consume this API.

## M18 handoff and first watch profile

M18 supplies [finite source/result readers](../../../packages/zig/transit-query/docs/unified-client.md),
not a change feed. A query's source pin is released when capture completes or
closes; result retrieval still checks current source/request availability.
Neither that pin nor a verified result cursor can be repurposed as a retained
watch position. The [executed source matrix](../../../tests/README.md#m18-qualification)
must remain separate from the new source-by-transport matrix here.

Select the non-trading Table service as the first watch owner. Its public
snapshot/change operation must relate committed data progress to a finite query's
captured basis, including which maintenance/query bookkeeping commits do not
invalidate the data view. Watching every write to the shared resource can make
query capture trigger another query forever. Prove no missed relevant changes
and no self-sustaining refresh loop. Policy, schema and lifetime changes still
require their control/availability outcomes even when data invalidations coalesce.
M21's Board inspection projection needs its
own qualified public adapter; finite KV/Document support does not add watches for
those sources automatically.

Reuse M19's durable operation mapping for cross-transport commands. M18's
prepared signed bytes belong to one logical operation and coordinated principal
sequence; HTTP fallback or a replacement socket must recover that mapping before
preparing anything new. Carry its distinction between input receipt, committed
input, completed result and verified result coverage into the message fixtures.

M18's timeout and expiry regressions also apply: an idle read timeout is transport
interruption, while current denial or retirement ends authorized disclosure.
Session leases must not silently extend a finite Station wait or cancel accepted
commands. Authenticate the timer/lease observer and test duplicate observations;
hard resource expiry must work when notifications cannot be delivered.

## Entry gates

| Gate | Required decision / evidence |
| --- | --- |
| Serving | M19's executed identity, admission, concurrency, response, cancellation and deployment proofs; long-lived responses cannot monopolize control capacity |
| API model | Version sessions, connections/attachments, subscriptions, message directions, operation/event IDs, correlation, codecs, errors and supported delivery classes |
| Provenance and authority | Preserve current service/resource checks per message/read; pin browser and service-client admission, renewal, revocation and replacement-attachment fencing |
| Source/watch owner | Define the Table adapter's missing bounded public snapshot/change handshake, relevant-change coverage and retained resume/reset contract; existing inspection/result cursors are not watch APIs |
| Bindings | Pin SSE and RFC 6455 server profiles, versioned WebSocket subprotocol, framing/compression limits, heartbeats, close behavior and real proxy support |
| Descriptions | Propose OpenAPI 3.2.1 for HTTP/SSE and AsyncAPI 3.0 for WebSocket; qualify pinned validators/generators and compatibility with Board's current OpenAPI 3.1 publication |
| Durability and capacity | Distinguish command acceptance, response writes, event delivery and client processing; specify finite leases, aggregate quotas, replay coverage, coalescing/reset and control reserve |
| Encoding and ownership | Derive per-frame, reassembled-message, decoded-envelope and result-page bounds from actual encodings, including escaped JSON and full-width identifiers; stream references through the existing bounded result reader |

## Implementation sequence

1. Define neutral typed reactive API contracts and independent fixtures before
   adding transport conveniences. Reuse M19's operation identities and Station
   public owners for durable metadata; sockets and local queues are disposable.
2. Qualify one source/watch adapter, including compatible snapshot/change
   acquisition, current reads, retained cursors and explicit reset outcomes.
   Separate source-data changes from the watch/query service's own bookkeeping;
   publish the coverage relation consumed by M21 rather than assuming numeric
   positions from different resources or generations are comparable.
3. Implement SSE with ordinary HTTP commands/control and WebSocket with typed
   bidirectional commands/control/events. Run the same semantic traces against
   both, including exact operation recovery across a transport change.
4. Generate and validate OpenAPI/AsyncAPI descriptions, shared schemas and runtime
   validators. Publish versioned capability/discovery metadata without exposing
   hidden service definitions or silently upgrading existing Board clients.
5. Prove server/peer recovery, authentication, overload and local/Compose/reference
   placement with independent non-UI clients and a minimal browser transport
   harness. Hand M21 an executable API instead of moving protocol design into UI code.

## Exit criteria

- [x] A versioned published API declares operations, messages/directions, codecs,
  source bindings, security, delivery classes, lifecycle and budgets. Accepted
  definitions, observed listeners and draft configuration remain distinct.
- [x] SSE and WebSocket host the same authorized non-trading service: HTTP or
  WebSocket command submission, correlated accepted-stage receipts/results, and
  resumable source invalidations/operation-outcome notifications. A UI is not
  required to exercise or prove the API.
- [x] WebSocket commands reuse M19's stable request identity and canonical meaning
  across reconnect and HTTP fallback. Duplicate admission returns the original
  receipt; conflicting content, stale bindings and expired retry horizons reject.
  No acknowledgement claims durable acceptance before the owning commit.
- [x] Define separate connection, session, subscription, operation and event
  identities. Version open/subscribe/renew/resume/unsubscribe/close and typed
  errors; a connection replacement cannot grant new scope or erase accepted work.
- [x] Prove the snapshot/watch handoff under concurrent commits, policy changes,
  schema changes and retirement. Notifications name exact source/generation and
  covered progress; there is no raw-store tail or invented global ordering.
  Include a commit between acquisition steps, a commit during query capture,
  empty progress pages and bookkeeping-only writes. Repeated status/read/query
  activity alone cannot manufacture an endless chain of data invalidations.
- [x] Resume produces duplicate-safe continuation within retained coverage or an
  explicit reset-required outcome. Reject forged, foreign, future and incompatible
  cursors. Source unavailability, gap, denial, expiry and transport loss differ.
- [x] Reauthenticate new attachments and recheck authority per new command and
  bounded disclosure, including idle sessions. Fence stale attachments at the
  declared boundary; preserve private Board access without adding human sign-in.
- [x] Qualify browser Origin/proxy/TLS and the selected service-client credentials.
  The WebSocket browser bootstrap must work without assuming arbitrary handshake
  headers or putting credentials in URLs/subprotocol names. Bound unauthenticated
  bootstrap and avoid hidden-resource disclosure in discovery, events and errors.
- [x] Independently test SSE UTF-8/framing/event IDs/reconnect and deployed proxy
  buffering/timeouts; test WebSocket upgrade, masking, fragmentation, control
  frames, message decoding, subprotocol negotiation, ping/pong and close races.
  Decline unqualified extensions during negotiation; reject frames that use
  unnegotiated compression and reject unsupported codecs/transports explicitly.
- [x] Bound directional buffers, fragments, messages, connections, subscriptions,
  retained resume work and aggregate per-principal capacity across transports.
  Slow readers/reconnect storms cannot block revocation or other admitted clients.
  Count encoded and decoded bytes separately and test fragmented UTF-8, escaped
  control characters and wide result references against runtime validators and
  generated schemas. A reference notification must not materialize its full result
  in a socket queue. Queued content cannot bypass the declared revalidation boundary.
- [x] Specify which events can coalesce and their covered-through positions;
  messages requiring complete history cannot silently use that policy. Receipts
  and results remain recoverable when an outcome notification is missed. Neither
  TCP credit, pong nor event receipt is durable client-processing acknowledgement.
- [x] Recover session/subscription meaning, accepted commands and event source
  references after gateway/worker/node/store loss. Finite leases bound abandoned
  live work without deleting retained history or silently cancelling commands.
  Keep finite session/wait/resource deadlines distinct; prove authenticated lease
  expiry, unavailable observers, read timeouts and uncertain accepted mutations.
- [x] Generate OpenAPI HTTP/SSE and AsyncAPI WebSocket descriptions from the same
  public definitions used by runtime codecs/validation. Validate examples and
  wire traces against the pinned specifications and independent tooling; prove
  streaming item handling and reject schema drift or unsupported advertised features.
- [x] Publish compatibility, source/message/transport matrices, bounded diagnostics,
  usage/recovery docs and real local/Compose/reference examples. Add reproducible
  `just` proofs and measured costs under M10, with deterministic models for new
  admission/resume/fencing races and actual independent protocol peers.
- [x] Hand M21 qualified API/client primitives, snapshot/watch evidence, reset,
  lifecycle and budgets. M21 chooses views and scheduling; it does not invent a
  second SSE/WebSocket subscription implementation.
  Record Table, Board inspection and any additional source independently for SSE
  and WebSocket, client ownership and placement, marking unqualified adapters
  unavailable until their proofs run. M18's ten SDKs remain regression
  consumers of finite APIs; reactive SDK coverage requires its own executed rows.

## Qualification and handoff

The implementation uses the existing growing Station resource and public current
reads; no independent session database or raw-store tail was added. Active limits
are four sessions/service, two/caller and one subscription/session. Logical leases
are at most 30 seconds; idle authority checks, bounded writes and reserved HTTP
renew/close capacity keep live work finite. Closed histories and accepted operation
outcomes remain separate from these limits.

The first source is an int64 Table with an atomic data-progress entry. Snapshot
acquisition uses one public resource cut, and `TableWatch.covered` relates its
watermark to an identical finite-query contract/schema. Actual `UnifiedCapture`
model transitions prove a concurrent data commit remains dirty while query
bookkeeping cannot start a refresh loop. The native/physical proof rows separately
cover current grants, expiry, transport loss and restart. A failed or expired
attachment never prepares a replacement application command.

The browser harness uses WebCrypto and native browser WebSocket/fetch SSE with
provisioned signing keys, a fixture certificate and origin-scoped loopback
permission. It qualifies the transport boundary, not a reusable SDK or Board UI.
SSE challenge/attach needs brief gateway affinity; durable attachment/cursor
recovery works across gateways. Reference recovery deliberately exercises a lease
that expires while physical components are absent and requires an explicit new
session. HTTP operation recovery remains available independently.

Generated descriptions model complete SSE field objects and their JSON `data`
content, share the WebSocket message definitions, and pass pinned offline schemas
plus actual wire validation. The [M21 handoff](M21.md#m20-handoff) names the typed
owners, lifecycle/budget limits, retained query coverage and unqualified adapters.
M21 still owns shared-principal viewer fairness, reusable host client composition,
visible reset/refresh behavior and bounded complete-result presentation.

## Outside this milestone

Board/application live-view UX, automatic query refresh scheduling, predictive
editing, incremental continuous SQL, exactly-once client consumption, a general
lossless message broker, arbitrary user-defined socket handlers, external-source
polling and general operator sign-in. Domain event-log delivery beyond the stated
invalidation/outcome profile, WebSocket compression/binary codecs/HTTP/2 upgrade,
and other protocols require explicit later qualification. OpenAPI callbacks do
not introduce autonomous webhook dispatch; that remains a connector operation.
