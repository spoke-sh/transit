# M7 — Durable state resources and process associations

[Roadmap](README.md)

Status: Planned; follows the kernel and development/runtime tooling through
[M6](M6.md). Required before [Station M8](M8.md).

Scope: the first versioned KV resource and explicit process associations,
following [State](../STATE.md). Prove that application data can live outside
worker memory and the inline process-state value while remaining governed by
Transit commits, authorization, and lifetimes.

## Bounded profile

Use the existing authority domain and Ursula backend. Support opaque KV keys and
values, bounded lookup/enumeration, one fenced writer PID per resource, and at
most one mutated resource per turn. Multiple processes can associate and read
under explicit grants; other writers request changes through the owning writer's
mailbox. These requests and replies remain distinct process commits.

Support PID-owned and independently owned resources, required/optional
associations, unlimited defaults, opt-in finite resource lifetime and history
retention, keyed checkpoint compaction, and safe tombstone reclamation. Required
resource expiry permanently ends the dependent PID's recovery eligibility.
Independent resource data can outlive its writer; writer transfer is not implied.

Typed Table helpers, workload-scoped ownership helpers, and GenServer APIs
follow in Station. Multi-resource transactions, multiple concurrent writer PIDs,
cross-authority atomicity, per-key TTL, automatic schema migration, and same-PID
recovery after required state loss are outside this profile.

## Implementation sequence

1. **Specify the contract and compatibility path.** Define identities, revisions,
   association changes, read bases, grants, operation identities, lifecycle
   outcomes, and bounded resource budgets through public types and shared
   fixtures. Decide how existing inline-state callers and stored histories
   coexist or migrate; declare version/capability rejection explicitly.
2. **Prove the commit mechanism.** Implement core transitions and the smallest
   real-backend proof that publishes a resource mutation with input progress and
   outputs through one durable decision. Exercise staged-but-uncommitted data,
   lost acknowledgements, lagging indexes, stale owners, and retirement races.
   Do not build Station on an unproved multi-append assumption.
3. **Provide caller APIs and recoverable lookup.** Add KV and association calls
   through `transit-client`, exact-revision reads, bounded enumeration and
   materialization, and a Zig calling example without Station. Measure resident
   memory and catch-up work against a dataset larger than the working buffer.
4. **Enforce lifetime and compaction.** Implement dependency admission/release,
   required-state expiry, checkpoint/trim, tombstones, and resumable reclamation.
   Maintain reserved control capacity under staging, history, and reader pressure.
5. **Expose the model and qualify it.** Replace Board's application counter lens
   with generic resource/association inspection. Update generated contracts,
   launcher examples, and component documentation. Qualify recovery and same-PID
   compatible upgrades locally, in Compose, and on the reference deployment.

## Exit criteria

- [ ] Publish versioned language-neutral resource/association contracts and
  fixtures, generated schemas/client surfaces, and explicit capability/limit
  errors. Prove rejection of unsupported multi-resource mutations and profiles.
- [ ] Prove recoverable creation, initialization, conditional association changes,
  and stable resource identities. No activation with a missing required initial
  resource; no silent retargeting of old turns or retries after association changes.
- [ ] Commit one resource's mutation, consumed input, outputs, and effect intents
  atomically in the declared visibility domain. Inject crashes before/after
  staging and commit, lost responses, competing revisions, and stale activations;
  assert authoritative outcomes, not just eventual displayed values.
- [ ] Enforce current realm/action/resource grants for association, read, write,
  inspection, and lifecycle operations. Prove references do not grant rights,
  revocation fences the next authoritative operation, and foreign/retired IDs fail.
- [ ] Provide stable revision reads and bounded enumeration. Prove snapshot
  expiry/trim returns an explicit outcome and that an uncertain submission never
  silently changes its read basis, proposal, or operation identity.
- [ ] Recover committed data, associations, pending work, and read/replay coverage
  from disk-backed checkpoints/history after worker, node, and index loss.
  Recovery runs no handler or external effect; unavailable historical versions
  cannot be replaced with latest data during replay.
- [ ] Preserve PID-owned state across worker loss, suspension, and compatible
  same-PID upgrades. Prove independent resources survive an associated PID's
  retirement without acquiring a replacement writer automatically.
- [ ] Reject suspension beyond required state availability. Required-resource
  expiry permanently retires the dependent PID; optional expiry is distinct from
  a missing key. Outages and revocation must not masquerade as logical expiry.
- [ ] Prove history compaction preserves unchanged live values older than the
  history window. Exercise delete/recreate of a key, stale writes, old snapshots,
  and readers beyond the retained boundary without value or resource resurrection.
- [ ] Serialize dependency admission against retirement/GC. Reclaim abandoned
  staging, release bounded read dependencies, survive maintenance crashes, and
  preserve control progress at capacity; quota pressure never authorizes data loss.
- [ ] Add authorized Board/API views for associations, resource revisions,
  lifecycle, coverage, and committing-turn evidence. Separate resource/value
  disclosure; hidden resources cannot leak through relationship edges or counts.
  Remove the counter lens and its launcher mapping/configuration, API/UI fields,
  and application-decoding tests through an explicit compatibility change.
- [ ] Run a non-trading Zig example through local, Compose, and reference
  launchers, including worker replacement and same-PID upgrades with state intact.
  Update checks and proof evidence without claiming arbitrary native determinism,
  global transactions, or unmeasured performance guarantees.

## Handoff to Station

[M8](M8.md) builds handler ergonomics, durable waiting, registry tables, and
supervisor state on these public primitives. It must not introduce a second
state authority or bypass turn commits for convenience. Broader distributed
compaction and reader coordination remain in [M10](M10.md); the minimum KV
recovery and retention guarantees above cannot be deferred to that milestone.
