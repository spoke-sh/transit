# M46: General typed Tables and schema lifecycle

Status: implementation in progress; tracked by [issue #75](https://github.com/rupurt/rey/issues/75).
This additional work follows the completed M45 baseline and establishes the
Table foundation required before enabling M34's relational implementation.
Earlier milestones retain their recorded profiles and evidence.

## Outcome and owners

Replace the physical two-column Table assumption with stable schema and row
identities, shared logical types, bounded storage and a coherent CREATE/ALTER/DROP
lifecycle. Generalize INSERT/UPDATE/DELETE and authorized catalog routing over
that same foundation. SQL, typed callers and enabled transports share semantics;
parser acceptance never substitutes for execution or storage support.

Fuze owns pure schemas, values, declaration/mutation compilation and semantic
validation. Station owns Table storage and staged changes over public state
operations. Catalog owns names, immutable definitions, current scoped policy
and attributed outcomes. Query/client owners retain snapshot cuts, bound schema
identity, exact saved work and current disclosure. Hosts own lifecycle and I/O.
The kernel retains its generic one-mutated-resource atomic publication boundary.

## Selected decisions

- Columns default to nullable; PRIMARY KEY implies NOT NULL and is explicit.
  A Table without a declared key has a stable internal row identity, preserving
  duplicates without turning the first column into a constraint.
- Column IDs survive renames and are never reused after removal. Application
  schema revisions are distinct from protocol definitions and resource cuts.
- Reuse all existing Fuze logical type families. Aliases normalize to exact
  descriptors; VARCHAR length, integer width, decimal and temporal parameters
  have explicit semantics. Storage and operator/transport capabilities differ.
- Typed defaults, nullability, single/composite keys, wide rows and nested values
  need shared validation, bounded work and atomic publication. Ordinary Table
  writes cannot persist unresolved source errors/conflicts as successful values.
- Basic ALTER covers add/drop/rename, defaults/nullability and admitted type
  changes. Rewrite old rows through a frozen basis and qualified staged successor;
  never reinterpret a retained snapshot with the newest schema.
- DROP separates live-name removal, write admission, dependencies and retained
  evidence from physical reclamation. Name reuse cannot redirect saved work.
- Incompatible stored/ABI definitions use one coordinated current-v1 cutover,
  mandatory rejection and matching consumers. No fallback decoder or implicit
  reset/conversion of an existing installation is permitted.

## Checkpoints

### Selected admission matrix

This matrix is implementation scope, not a claim that the console admits it.
The pure schema/row/evolution and scalar-name APIs are implemented in the
[Table schema contract](../../contracts/TABLE_SCHEMA_V1.md). Native lifecycle,
routing and caller admission remain separate checkpoints below.

| Family | Selected Table storage and input | Key/comparison boundary |
| --- | --- | --- |
| Signed/unsigned widths, finite floats, decimal, boolean | Exact typed values and scalar literals; checked conversions | Declared scalar keys; shared exact comparison/hash; no expanded generic SUM |
| UTF-8/binary | Typed bytes, string/hex input; VARCHAR counts Unicode scalars | Exact-byte equality; no implicit collation/padding |
| Date/time/civil or UTC timestamp/UUID | Shared typed atoms and qualified literals | Scalar keys; no named-zone or implicit temporal casts |
| Interval | Typed components and explicit constructor | Storage/equality only; no key or ordering |
| Struct/list/fixed array/map/tagged union | Recursive descriptors and typed values/constructors | No primary keys; existing qualified structural traits only |
| JSON | Exact validated JSON value | No primary key, equality, hash, ordering or aggregate inference |

Every family must reach qualified Table read/write and result paths before full
completion. Existing Arrow, local logical SDK, native query and Flight profiles
remain independently admitted; neither a stored descriptor nor parser acceptance
widens their limits. Use existing typed codecs, never an untyped string stand-in.

Selected scalar aliases and parameter behavior are fixed by `SqlTypes`: SQL
INTEGER/INT is int32, BIGINT int64 and Transit INT8 remains eight bits. Decimal
defaults to (38,0), VARCHAR(n) enforces Unicode scalar length and temporal
precision must match native units. Unqualified padding, arbitrary binary lengths,
FLOAT(p), named time zones and unsupported type families reject explicitly.

| SQL capability | Selected implementation | Boundary |
| --- | --- | --- |
| CREATE | General columns, aliases, nullable defaults, typed constant defaults, explicit single/composite/no primary key, IF NOT EXISTS | Existing names report unchanged rather than changing schema; exact operation conflicts still reject |
| INSERT | Named/reordered/omitted columns, DEFAULT/NULL, bounded typed multi-row input | One invalid row/key rejects the complete statement |
| UPDATE/DELETE | Typed constant/default assignments; point selection first, then scalar/state Boolean predicates on a frozen source | Separate matched/changed counts; one final publication; no implicit cross-resource transaction or column-expression evaluator |
| ALTER metadata | Rename column/table, SET/DROP DEFAULT | Stable identities; no rewrite of earlier defaulted values |
| ALTER validation/rewrite | Add/drop column, SET/DROP NOT NULL, exact numeric casts and VARCHAR bounds | Complete old-row validation, source fencing and atomic successor publication |
| DROP | IF EXISTS, default RESTRICT, attributed tombstone and safe name reuse | No implicit CASCADE or physical erasure |
| UNIQUE/CHECK/foreign keys | Explicit rejection and linked M36/M40 work | PRIMARY KEY is the selected uniqueness constraint; no implied cross-resource enforcement |
| Generated/identity/SERIAL, UPSERT/MERGE, RETURNING | Explicit rejection and M36/M40 follow-up | Hidden row IDs are recovery identities, not user identity-column syntax |
| INSERT SELECT, CTAS, TRUNCATE, bulk copy, transaction sessions | Explicit rejection and M36/M40 follow-up | No loop of independently committed commands posing as one statement |

Prepared local plans/cached schemas do not block DROP; later admission rejects
their old object/revision. Already admitted snapshot reads may finish on pinned
cuts under current read authority. Durable configured source/writer/watch or
maintained-relation dependencies require explicit unbinding before RESTRICT can
succeed. Historical/recovery references retain data and receipts, without keeping
the live name bound or authorizing new writes. Unqualified future branch/live
profiles do not acquire implied DROP behavior. Cleanup remains separate and
reference-safe. The runtime must make this distinction executable before T4.

### Delivery checkpoints

1. **Contracts and independent semantics:** schema/row identity, type and alias
   matrix, default/key rules, canonical encoding, ownership and adversarial oracle.
2. **Storage:** bounded immutable schema/value/index representation, exact roots,
   revision-aware reads, wide/nested values and disk-backed failure recovery.
3. **Creation and routing:** shared CREATE, discovery, existing scoped permissions
   and public multi-Table reader/writer resolution without private-file edits.
4. **DML:** typed insert/assignment/delete, point then selected predicate work,
   complete validation, precise counts and durable original-operation recovery.
5. **Schema lifecycle:** ALTER/DROP, prepared/saved work, retained readers,
   concurrent changes, dependency checks and interrupted rewrites.
6. **Qualification:** finish the logical-type matrix, enabled consumers,
   diagnostics, performance controls, documentation and committed-source CI.

Issue #75 retains the full acceptance matrix and links implementation commits.
T0–T4 now have implemented contracts and native recovery evidence. The current
shared-definition cutover includes all enabled consumers; their final clean
qualification remains part of T5. The
[matched mutation campaign](../../tests/mutation_latency/results/2026-10-07/README.md)
finds regressions in narrow, wide/nested and retained-data controls, and the
original interactive Table request ceilings fail. On 2026-10-07 the user
explicitly accepts the documented costs for this scope and requests separate
optimization tracking in [M47](M47.md) / [issue #76](https://github.com/rupurt/rey/issues/76).
The fixture's accepted regression ceilings now follow those measurements; old
failed runs remain failed. The accepted-budget rerun passes; T6 still requires
final clean qualification. #70 records this implemented foundation and the remaining
integrated-intake gates separately.
Initial finite joins require the qualified multi-column/scalar profile, stable
identities, schema-bound snapshots, usable routing/DML and basic lifecycle.
Remaining rich-type operators, advanced constraints and branching need not block
that explicit handoff; they cannot be silently counted as completed here.
