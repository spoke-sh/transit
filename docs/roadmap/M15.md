# M15 — HTTP connector and shared exchange lifecycle

[Roadmap](README.md)

Status: In progress; first connector, following [publication M14](M14.md).
[Connectors](../CONNECTORS.md) owns the design; [gRPC M16](M16.md) must reuse and
qualify the common lifecycle before later abstractions build on it.

Scope: a Zig HTTP/1.1 and HTTPS connector, Station caller helpers and trusted
fetch worker, plus the minimal reusable exchange/capture/reconciliation components
that this concrete connector needs. Documents are not an HTTP prerequisite.
The [shared capture contract](../../contracts/STATION_EXCHANGE_V1.md) fixes the
initial immutable segment/coverage boundary. Exit criteria remain unchecked until
their implementation and executable qualification are complete.

## Implementation progress

The shared [exchange library](../../packages/zig/transit-exchange/README.md)
implements finite segment capture, atomic coverage, frozen kernel intent,
terminal availability and bounded cleanup. The [HTTP package](../../packages/zig/transit-station-http/README.md)
adds typed templates and one-send HTTP/1.1/TLS transport. The initial
[finite worker](../../apps/transit-station-http-worker/README.md) prepares a
committed request, validates endpoint and credential bindings, captures the
response and records its outcome through public growing APIs.

`just test::http-transport` and `just test::http-worker` have local independent-peer
and disk recovery evidence in the [test guide](../../tests/README.md#m15-connector-work-in-progress).
The worker proof includes exact lost-receipt retries, fresh ownership after
SIGKILL, closed unknown without resending, current read revocation and replay
without credential resolution. This remains a finite private-control-mailbox
profile. Public caller admission, linked explicit retries/redirects/reconciliation,
dependency-safe group release, SDKs, Board metadata, launcher/runtime isolation
and measured hosted costs are still required before milestone completion.

## Review of the available foundation

| Available component | Reuse | Remaining obligation |
| --- | --- | --- |
| Growing effect intent, `dispatch`, `observe`, `close_effect` | Stable effect/attempt/executor identity, current authority, unknown outcome and terminal closure | The implemented kernel permits one dispatch attempt per effect. Model a logical exchange's retries/redirects as linked newly committed effects, or qualify an explicit generic extension; never redispatch an authorized effect |
| M14 `Publication` | Immutable chunks, digest, final visibility, quotas and restartable cleanup | A record needs a known length/digest. Unknown-length network bodies require bounded captured segments and an exchange coverage manifest; a sealed segment alone is not a complete response |
| M14 retirement and retained sources | Logical deletion plus protected historical reads | Opaque references acquire no dependencies automatically. Qualify group availability, member lifetimes, replay dependencies and current access separately from physical cleanup |
| M11 growing hosts and SDKs | Scoped handlers, exact signed retry, fresh ownership and native/port ownership | An uncertain Transit write is distinct from uncertain remote HTTP execution. SDK convenience must preserve both |
| M13 query access/delivery | Patterns for current policy checks, source identity and bounded reads | Query result records, the Table schema and the 207-byte plan request are not connector formats or authority |

The M14 proof required explicit history-checkpoint opt-in and bounded reader
progress across turns. Preserve these distinctions: checkpointing is not trim
permission, unlimited retention is not unlimited capacity, and a single large
handler must not hold a view open for an entire exchange.

## Entry gates

| Gate | Required decision and evidence |
| --- | --- |
| Neutral contracts | Define exchange/request/attempt/segment/completion/reference versions and shared fixtures before SDK wrappers; specify provisional capture, confirmed terminal evidence, incomplete capture and closed unknown distinctly |
| Atomic layout | Budget descriptors, heads, reservations, correlation and outputs under one writable resource/four mutations. Prove how already-sealed capture becomes an effect observation without a dangling reference if closure, retirement or a crash wins |
| Body and group capacity | Measure finite request/response/header/segment/active-exchange limits, both decoded and wire bytes, namespace creation and resource quotas. Design a bounded paged coverage manifest; do not allocate an array per retained member |
| Authority | Identify caller, exchange writer, executor and independent reconciler roles, fixed destinations, policy revisions and exact dispatch bytes. Prove the mapping to one-attempt kernel effects and identify any genuinely required generic extension before I/O |
| Transport and secrets | Qualify pinned Zig HTTP/TLS support with redirects, ambient proxies and automatic HTTP retries disabled; freeze interpolation/provenance, credential versions and allowlisted capture rules before dispatch |
| Lifetime | Specify current group availability versus historical body versions, caller/replay lifetime compatibility, explicit release and dependency-safe member cleanup. Preserve unlimited default retention and finite live-work/reconciliation budgets |

## Implementation sequence

1. Publish contracts, ownership/capacity worksheets and fixtures. Exercise the
   intent -> authorized attempt -> capture -> completion/unknown state machine
   with deterministic faults before wiring sockets.
2. Build the smallest shared Zig exchange library above Station: segment/manifest
   handling, budgets, lifecycle, current-policy read adapters and replay. Add a
   real package/manifest only when HTTP consumes it; do not build a generic plugin
   host, provider framework or a second authority database.
3. Add HTTP request construction and bounded transport. Record literal request
   text/bytes, variables, secret references, actual serialization and omissions.
   Resolve credentials only inside the authorized worker. Body segments may be
   buffered up to a declared bound before their digest is known; worker loss in
   that interval means incomplete capture, never invented completeness.
4. Implement explicit redirect/retry/reconciliation decisions using new linked
   attempt identities and recorded destinations. A status query or cancellation
   is itself authorized external work. Recover unknown attempts before deciding
   whether endpoint-specific policy permits another send.
5. Expose shared Zig behavior through all M11 SDK targets, with typed request,
   durable call/attempt identity, bounded body reads and explicit outcome states.
   No language adapter implements independent retry or capture semantics.
6. Ship synthetic non-trading examples, local/Compose/reference deployment,
   bounded telemetry and read-only Board metadata. Run the fault/security/replay
   corpus and measure the complete CI task before handing the common layer to M16.

## Exit criteria

- [ ] Versioned request/response text and byte framing, ordered duplicate headers,
  trailer handling, interpolation and exchange membership/completion fixtures are
  implemented and validated across boundaries. Unsupported protocol/framing and
  encoding combinations fail explicitly.
- [ ] Requests retain literal/template provenance and immutable ordinary bindings;
  credentials remain references. Header injection, invalid framing, secret-bearing
  response fields and redaction/truncation semantics have adversarial fixtures.
- [ ] Bounded capture handles known and unknown response lengths, empty and binary
  bodies, segmented requests/responses and partial capture. Final coverage names
  exactly the durable segments; no status line or body prefix implies completion.
- [ ] Every dispatch, redirect, explicit retry, reconciliation poll and remote
  cancellation has committed identity and current scope. Exercise safe retry under
  an explicit endpoint idempotency contract and closure of a non-idempotent unknown
  outcome. Recovery and replay never create hidden network attempts.
- [ ] Prove scheme/authority/SNI/certificate, resolved-address and proxy/redirect
  scope against independent peers, including DNS changes, metadata/admin targets,
  credential forwarding and forged attempt results. Do not confuse an authorized
  possibly-in-flight send with a promise of cancellation after revocation.
- [ ] Preserve caller PID/effect lineage across worker replacement, caller
  termination and name rebinding. Reconciliation has an explicit surviving owner
  and original finite budget; no late outcome activates a replacement caller.
- [ ] Qualify group/body dependency admission, current transcript permissions,
  replay availability, retained-version reads and cleanup. Expired/retired groups
  cannot disclose bodies through stale cursors or cached manifests; quota pressure
  cannot delete accepted history or release unresolved obligations.
- [ ] Inject worker/node/store loss before send, after remote application, during
  capture, between segment and final outcome publication, and after outcome commit
  before delivery. Exact Transit retries deduplicate; remote uncertainty survives.
- [ ] Replay complete captures with network, DNS and credential resolution disabled;
  missing/redacted required data produces an explicit gap, never a refetch.
- [ ] Every M11 SDK runs shared request/outcome/body fixtures and the relevant
  ownership/recovery checks. A Zig reference example and local/Compose/reference
  proofs exercise the real binaries with constrained execution and egress roles.
- [ ] Board exposes authorized exchange/attempt identity, policy/timing provenance,
  coverage and gaps through public reads. Protocol-field previews are allowlisted;
  arbitrary application bodies and credentials are not interpreted by Board.
  Diagnostics have bounded cardinality and exclude payloads/secrets/raw URLs.
- [ ] Record compatibility, operating/recovery instructions, concrete storage and
  control-reserve budgets, proof commands and measured local/hosted CI costs.
  Review the common API with M16's streaming requirements before marking complete.

## Boundaries

HTTP/2 application requests, HTTP/3, WebSocket/SSE and indefinite subscriptions,
provider-specific integrations, browser/offline clients and exactly-once remote
execution are separate scope. HTTP/1.1 wire fidelity is qualified at the declared
application boundary, not as a TLS packet capture. HTTP status is not business
success; endpoint-specific idempotency is not inferred from a worker retry.
The [HTTP idempotency rules](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)
inform endpoint policy; they do not replace recorded dispatch authorization or
resolve an unknown outcome for an arbitrary non-idempotent request.

After implementation, update M16's entry decisions from measured HTTP evidence.
Until then its shared components and capacity choices remain proposed.
