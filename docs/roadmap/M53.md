# M53 — Local SQL startup and authentication

Follow-up to M52's configured listeners: local development must not require TLS
or manual internal credential binding. Status: implemented with scoped local
qualification. Current interfaces belong to the [local SQL guide](../../apps/transit-cli/docs/sql.md)
and [wire contract](../../contracts/SQL_GATEWAY_V1.md).

## Scope and acceptance

- Keep both listeners independently opt-in; reject an enabled listener with no
  enabled accounts before child startup.
- Separate disabled/optional/required TLS from password/trust authentication.
  Trust is explicit and restricted to IPv4 loopback. PostgreSQL SCRAM supports
  plaintext; MySQL full-password exchange still requires TLS.
- Let an explicitly selected new SQL account bootstrap to the installation's
  original local owner through journaled native authorization. Never repeat a
  completed binding, reconstruct a retired role or restore revoked access.
- Retain account fingerprints, independent sequence owners, exact requests,
  ledger initialization, fencing and disabled-listener recovery.
- Report configured versus accepting ports, failures and connection commands.
- Qualify first initialization, compatible-installation enablement, all TLS
  modes, real psql/mysql CRUD, bad logins, owner-bootstrap reply loss and native
  revocation across restart. Preserve existing password/TLS and recovery proofs.
- Replace the shared definition for changed persisted enrollment/credentials;
  regenerate consumers and fixtures. Reject older state without altering it.
- Run root checks and committed-source clean verification before submitting a PR;
  record executed evidence separately from these acceptance intentions.

## Executed qualification

The [proof ledger](../../tests/README.md#local-sql-authentication--2026-10-18)
records passing root checks, protocol tests, source and installed real-client
workflows, setup faults and all nine clean experience recipes. The installed
workflow runs outside the checkout with adjacent executable discovery. The
record distinguishes runtime, source-proof and installed-harness revisions;
other ordinary lanes and the separate browser lane were not rerun for this change.

The shared current-v1 definition replaces the preceding persisted enrollment and
credential definition. Older installations reject without modification; the
guide explains separate initialization and preserving the matching old bundle
for accepted work. No user installation was reset during qualification.
