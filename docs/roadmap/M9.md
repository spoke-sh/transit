# M9 — Station behaviors, language bindings, and Arrow Tables

[Roadmap](README.md)

Status: bounded profile implemented and qualified on Linux x86_64.
Builds on [M7 state resources](M7.md), [M8 runtime readiness](M8.md),
Board, and the development/operator tooling delivered through [M6](M6.md).

Scope: the Station Zig implementation and behavior workers, usable through Zig
and bindings for **C/C++, Rust, Python, Node.js, Java, .NET, and Elixir/Erlang**.
Build on Transit's proven kernel and [state primitives](../STATE.md); include
GenServer, supervision, scoped registries and bounded [Arrow Tables](../TABLES.md).
The Table path uses [Fuze](../FUZE.md), the shared Zig query engine inspired by
DataFusion and Acero, with source interfaces designed for KV and future Documents.
Handlers use associated resources rather than replacing one state blob per
message. Bindings reuse the shared implementation and contracts; this milestone
does not require separate framework implementations in every language.

## Entry gates

The [Arrow integration evidence](../../packages/zig/transit-fuze/docs/integration.md)
records the compiler alignment, dependency compatibility fixes and initial IPC
capacity fixture. The [client ABI proof](../../packages/zig/transit-client/docs/bindings.md)
adds generated C signatures and host-loss recovery of frozen requests. These
prove the binding and dependency foundations. The
[qualification guide](../../tests/README.md#m9-station-bindings-and-tables)
maps the gates and exit criteria below to executable checks and limits.

The first [GenServer/Table implementation](../../packages/zig/transit-station/README.md)
now proves private turns, durable calls, two-table atomic writes, bounded Fuze
execution and captured Arrow replies with writer/consumer recovery. Scoped
registry/supervision and versioned Board lenses build on that boundary. The
[shared Station ABI](../../packages/zig/transit-station/docs/bindings.md) supports
all target languages, each qualified in both roles across language pairs.
The [three-process Zig example](../../examples/station-ledger/docs/running.md)
passes local, Compose and Substrate recovery and compatible same-PID upgrades.

[Runtime readiness](M8.md) supplies authenticated input origins, deployed outbox
delivery, opt-in catalog reclamation and explicit lifecycle controls. Station
must build on those public contracts, including their failure and retention
limits. The [pre-Station review](../reviews/PRE_STATION.md) remains the baseline.

Before fixing the behavior API, specify the one-resource layout for behavior
state and waiting/correlation records, exact proposal recovery, trusted scoped
provisioning, timer/lifecycle subscriptions, and versioned framework descriptors.
Those framework policies and services belong here; M8 supplies generic process
controls and origin evidence, not GenServer policy. The reference adapter requires
fresh worker-pod placement after logical suspension/retry; Substrate cold boot
can reuse a pod. Station's supervisor must expose placement unavailability and
cannot assume a resume command itself guarantees an activation. Station worker
templates must explicitly carry forward or replace the bounded provider-verified
bootstrap contract currently exercised by the counter; changing a template name
alone does not qualify a new worker runtime.

Resolve these additional design gates before promising a public API:

| Gate | Required decision / evidence |
| --- | --- |
| Binding architecture | Versioned Transit C ABI and separate Station exports, generation ownership, buffer/handle lifecycle, async/thread/cancellation rules and exact pending-proposal recovery; [client design](../CLIENT.md#language-neutral-boundary) |
| Language qualification | Pin runtime/tool baselines and packaging for every target; prove the common surface on Linux x86_64 and distinguish client support from reference worker isolation |
| Arrow dependencies | Start with the [Zig 0.17 zarrow candidate](../TABLES.md#arrow-and-compute-integration); align exact compiler revisions, pin a compatible zarrow-compute using the same module, and qualify IPC/C ownership with independent Arrow consumers |
| Fuze | Specify shared source/expression/logical/physical plan contracts, qualified rewrites and bounded execution; prove the [Table profile](../FUZE.md#bounded-execution-and-recovery) without embedding DataFusion or Acero |
| Table domain | Fix descriptor/key/row encoding, schema and operator/type subsets, one-resource transaction layout, service access policy and unsupported-operation errors |
| Result delivery | Prove a finite snapshot can be durably captured and framed through the existing byte/turn limits; specify completeness, crash resumption, cancellation and disclosure/lifetime policy |
| Capacity | Budget resource slots, schema/row/framework/result keys, mutation count, active views, outboxes, CPU and bytes for the complete example; helpers do not multiply M7/M8 limits |

Compatibility and result-framing gaps are milestone work, not assumptions that
the existing node or Arrow libraries already satisfy them. If the selected
profile cannot fit, revise its scope or explicitly plan a prerequisite using the
[linear sequencing rule](README.md#maintaining-the-sequence); do not silently
raise core limits or advertise a partially working language target.

## Implementation sequence

1. Prove the C ABI, binding generation and Arrow/compiler interoperability with
   a small Zig caller and shared foreign-language fixtures.
2. Implement the GenServer turn/recovery boundary, durable waiting, scoped
   registry and supervisor; exercise their one-resource state layout.
3. Implement typed tables, stream-input materialization, finite snapshot compute
   through Fuze and durable Arrow replies under measured bounds, with reusable
   source/plan/batch interfaces for further entities and SQL/Flight adapters.
4. Complete usable adapters/examples for every target and qualify the common
   behavior/Table surface, Board evidence and Zig reference workers together.

These are work stages within this milestone, not separate follow-up
milestones or permission to declare M9 complete after the Zig-only stage.

## Exit criteria

The implemented profile has one synchronous, bounded query batch, no enabled
rewrites, and durable result framing across mailbox turns. It retains the core's
four-resource/32-entry/four-mutation limits and caps captured IPC at 672 bytes.
Foreign clients are qualified on Linux x86_64; only Zig workers are qualified in
Substrate. Each criterion below is interpreted within that published profile,
with exact evidence and remaining limits in the [test guide](../../tests/README.md#m9-station-bindings-and-tables).

Qualification includes clean-checkout CI at implementation commit `1462041`, all
language targets, embedded Board browser checks, and local/Compose/Substrate
recovery and compatible same-PID upgrades. The documentation-only completion
record does not extend the profile to untested platforms or production scale.

- [x] Provide a GenServer behavior with initialization, sequential handlers,
  named state associations, transactional mutation proposals within M7's boundary,
  sends, and correlated request/reply on a Transit process/PID.
  Demonstrate that the process primitive also works without a GenServer behavior.
- [x] Publish a versioned shared binding surface, generated declarations/codecs
  and drift checks for Transit and Station. Preserve full-width identities,
  exact signed retry material, explicit ownership and error distinctions.
  Expose generation and each target's conformance checks through `just`, with
  the same pinned commands required in CI.
- [x] Ship runnable C and C++, Rust, Python, Node.js, Java, .NET, and Elixir and
  Erlang examples against the real authority. Each target exercises a handler
  proposal, correlated reply, resource access and Arrow result consumption;
  cross-language pairs interoperate without language-specific server paths.
- [x] Test foreign-runtime/port loss, exception/cancellation and buffer cleanup,
  event-loop/scheduler responsiveness, lost receipts, stale ownership,
  revocation/expiry and malformed data. Use shared golden wire/signature/Arrow
  fixtures, including integer values unsafe for JavaScript numbers.
- [x] Build typed Tables over KV with fixed schema/primary-key rules,
  insert/update/upsert/delete and bounded get/scan/query. Registry, supervision
  and waiting/correlation records use the same explicit resource layout.
- [x] Prove an atomic batch across two logical tables sharing one resource,
  with input progress and reply intent. Reject separate-resource atomic writes
  and oversize batches before publication. Exercise revision conflicts, loss of
  acknowledgement, restart, deletion/reinsertion and default retention.
- [x] Materialize stream-derived inputs with mutations and source progress in
  one commit; prove redelivery handling and recovery from checkpoint/tail.
  Rebuild the same visible rows after updates/deletes without double-counting
  historical versions in a finite aggregate query.
- [x] Qualify the selected zarrow/zarrow-compute operator/type matrix and expose
  finite snapshot results as Arrow record batches/IPC. Test nulls, empty results,
  integer overflow, schema mismatch and independent Arrow interoperability.
- [x] Prove bounded source/operator/sink execution, cancellation and completion
  under slow consumption and in-flight batches. Recover the accepted result
  without serializing execution pointers or extending an expired read view.
- [x] Expose bounded, permissioned Fuze plan explanations and explicit source
  capabilities. Test each enabled rewrite against execution without rewrites;
  preserve schema, null/error behavior, ordering and the authorized read basis.
- [x] Implement bounded durable Arrow reply framing with exact snapshot/result
  identity, authenticated fragments and verified completion. Inject loss,
  duplicates, malformed/truncated frames, slow consumers, producer/consumer
  restart, denied access and result closure; no partial success or fresh-view
  substitution. Prove the maximum accepted result fits the declared budgets.
- [x] Implement a minimal scoped registry with explicit scope lifetime and
  durable register/unregister/conditional-rebind operations. Prove recovery,
  conflicting registration rejection, and support for unnamed processes.
- [x] Record resolved PID/revision before delivery; test name rebinding and
  termination races with retries and late replies, without redirecting them.
- [x] Persist waiting state; route replies, timeout observations, and lifecycle
  notifications through mailboxes without holding a turn open for external I/O.
- [x] Expose retention contracts and bounded suspension. Reject a resumption
  request beyond required mailbox/resource lifetime; report permanent expiry
  separately from retryable activation failure. Prove that supervision stops
  retrying expired PIDs and that replacement requires an explicit new spawn.
- [x] Demonstrate workload-scoped temporary streams surviving worker recovery
  and retiring after logical owner termination/expiry with dependencies resolved.
- [x] Implement supervision with durable child identities, restart policy, and
  restart limits. Distinguish same-PID recovery from termination/new-PID spawn;
  prove supervisor and child recovery without duplicate children. Lifecycle
  observations distinguish process termination from activation loss.
- [x] Provide bounded poison-message handling, authenticated replies and
  explicit cancellation/timeout outcomes; demonstrate a blocked process remains
  inspectable and lifecycle control does not depend on its handler returning.
- [x] Demonstrate multiple processes exchanging messages across workers, preserving
  each mailbox's order and recovering pending deliveries.
- [x] Provide a small runnable non-trading Zig reference example and trace
  inspection commands alongside the binding examples. Qualify its worker
  recovery and bootstrap on the reference deployment.
- [x] Add versioned Board lenses for GenServers, supervision, registries and
  Table/query metadata, with explicit identity/schema provenance and links to underlying PIDs and
  state resources/records. Interpret framework structure without application
  value decoders. Prove unknown versions fall back to kernel views without
  guessing behavior from names or code tags. See [Board](../BOARD.md#higher-level-interpretation).

## Outside this milestone

Full SQL/dialect planning, arbitrary query code, continuous query maintenance,
joins/windows, multi-resource or distributed transactions, disk-scale indexes,
general large-result/blob transport, schema migrations, per-row TTL and writer
transfer are not implied by the bounded Table profile. Public SDK registry
releases, browser execution clients and qualification of every foreign runtime
as a Substrate worker are also separate scope. [M12](M12.md) implements gRPC and
[M13](M13.md) owns Flight/Flight SQL/ADBC, including the first small SQL frontend;
M9 establishes compatible seams without implementing those network services.
KV/Document query adapters, collaborative text and CRDT merge/recovery belong to
[M10](M10.md), with their own capacity/retention proofs. M9 establishes the shared
Fuze interfaces and bounded Table path that milestone builds on.
Select further work through new
numbered milestones; [TABLES.md](../TABLES.md#m9-scope-and-later-work) records the
transaction and streaming questions those milestones must resolve.
