# M24 — Transit CLI

[Roadmap](README.md)

Status: **Planned**; follows [Board grammar M23](M23.md) and precedes
[publication M25](M25.md). Formalize the user-facing `transit` interface around
two commands: `transit server` and `transit console`. Neither command is
implemented by this plan; the existing `query` and `query-v2` shells retain
their qualified behavior until an explicit compatibility transition lands.

Scope: a Zig supervisor/gateway that runs the neighborhood of services and
workers needed for a functioning locally placed Transit cluster, plus a
psql-like terminal console for slash meta commands and Transit's SQL grammar.
The console shares language assistance and public-operation semantics with
Board Explore. Local placement does not establish distributed authority,
high availability or the [M26](M26.md) portability and disaster-recovery proofs.

## Baseline and owners

- [transit-cli](../../apps/transit-cli/README.md) owns the existing signed query
  shells and will compose the public commands. [M13](M13.md) and [M18](M18.md)
  supply finite query submission, exact uncertain retries and verified results.
- [Launchers](../../launchers/README.md) supply persistent development topology,
  bootstrap and recovery evidence. Today native local placement uses Process
  Compose and recorded ownership; it is not a local runtime adapter or Station
  supervisor. Reuse its contracts without presenting that tooling as the new CLI.
- [Deployment](../DEPLOYMENT.md) owns physical lifecycle and gateway boundaries;
  [Transit](../TRANSIT.md), [Security](../SECURITY.md) and the
  [runtime contract](../../contracts/RUNTIME_SUBSTRATE_V1.md) retain authority,
  fencing, trust and provider distinctions. OS child processes and durable
  Transit PIDs are different identities.
- [Query language](../QUERY_LANGUAGE.md), the
  [grammar contract](../../contracts/sql/README.md) and [Fuze](../FUZE.md) own
  parsing, validation and execution. [Board Explore D4](../design/board-console/D4.md)
  and its [console notes](../design/board-console/CONSOLE.md) supply the language
  assistance direction; M23 supplies the selected shared editor/catalog contracts.

## Public command contract

| Command | Required behavior |
| --- | --- |
| `transit server` | Run in the foreground as a supervisor/gateway for an explicitly configured local installation; start, observe and stop its required service neighborhood, expose qualified public endpoints, and recover accepted work from durable history |
| `transit console` | Connect to a selected local or remote Transit endpoint with scoped credentials; edit and explicitly submit SQL, use `/` meta commands, and inspect operation progress and bounded results |

Define help/version output, options, configuration schema and precedence,
installation selection, endpoint/credential discovery, exit codes and signal
behavior before implementation. Keep credentials out of command arguments,
history and diagnostics. Separate human terminal output, machine-readable output
and stderr diagnostics. Unknown options and unsupported configurations fail
clearly before startup or submission. Specify the migration/deprecation policy
for `transit query`, `transit query-v2`, `rey-cli` and launcher entry points;
preserve their existing contracts while the two-command interface is introduced.
`kubectl-transit` keeps its Kubernetes inspection role.

## Server: local service neighborhood

Inventory required and optional roles, their dependencies and readiness. Include
disk-backed Ursula, authority, maintenance, delivery, the serving gateway and
the query/Station workers needed by the declared profile. Board and connector
workers have explicit enablement and credentials; example applications are not
required cluster infrastructure. Record how bundled and externally supplied
dependencies are located and version-checked so M25 can package a complete
installation without a source checkout or ambient development tools.

The supervisor owns bounded OS process lifecycle: dependency-ordered startup,
readiness deadlines, failure propagation, restart limits/backoff, child reaping,
joined shutdown and bounded logs. It must distinguish an OS restart from a
Station child restart or a fresh Transit activation. Where growing runtime
reconciliation is missing, specify and qualify the needed public local-placement
contract before claiming automatic recovery. A running child never grants
ownership, renews a lifetime or authorizes connector dispatch.

Separate deliberate first initialization from ordinary recovery. Persist the
installation identity, artifact/configuration versions and credential references;
refuse concurrent managers, conflicting ports and missing/rolled-back storage.
An interrupted bootstrap must recover the same accepted identities. Ctrl-C and
normal stop preserve data and accepted work. Destructive reset is a separate,
explicit operation, never a restart fallback. Use private bindings by default,
current scoped grants and declared TLS/origin policy for remote ingress; the
gateway cannot replace caller identity with a privileged shared identity.

Publish the native trust boundary: services running as one OS user are not a
sandbox. The local profile must not inherit Substrate's isolation claims. Keep
provider credentials and raw storage access confined to their owning roles;
kernel and query execution stay in their existing packages.

## Console: SQL and slash commands

Provide multiline editing, grammar-aware statement termination, paste handling,
keyboard navigation, highlighting and actionable diagnostics. Semicolons and
slashes inside strings/comments must remain SQL content. Define TTY and piped
input behavior, EOF, Ctrl-C, terminal resize and broken output pipes. Submission
is explicit; editing or accepting completion does not dispatch a query or apply
an administrative change. Live execution needs its own explicitly selected
contract and is outside this milestone's initial terminal profile.

Formalize slash-command syntax, arguments and help, retaining the existing
semantics of `/help`, `/info`, `/tables`, `/schema`, `/status`, `/next`,
`/resume`, `/cancel`, `/retry`, `/format` and `/quit` where supported. Extend
discovery to the selected authorized KV/Table/Document catalog. Meta commands
use owning public APIs; they are not another administration or storage backdoor.
Define bounded session history and any explicit persistence policy without
implicitly saving credentials, private literals or result rows.

Typeahead must be first-class at incomplete cursor positions: derive valid
constructions from the grammar, names and types from authorized catalog metadata,
and available actions from the endpoint's executable capability profile. Share
versioned language-assistance types, logic or generated tables and fixtures with
Board Explore rather than maintaining a separate terminal keyword list. Cover
qualified/quoted names, source and column context, meta-command arguments,
replacement ranges, ranking, accept/dismiss/undo and stale catalog generations.
Bound editor input, metadata pages/caches, pending requests and rendering; measure
cold and warm completion latency on declared fixtures before claiming parity.

Compilation at submission remains authoritative. Queries lower to qualified
Fuze plans; M23 declarations and controls lower to their owning public operations
only when supported and currently authorized. Clearly distinguish executable,
reference-only and missing syntax. Preserve full-width values, safe terminal
escaping, bounded result pages, observation basis and complete-result verification.
Admission, completion and uncertainty stay distinct. Reconnect/resume/retry keep
the exact accepted operation identity; quitting or interrupting local waiting
does not imply durable cancellation. Denial or realm/principal changes clear
protected completion/history/result state without inventing a new retry.

## Implementation sequence

1. Freeze the command/configuration and compatibility contracts, local topology,
   trust model, public operation matrix and language-assistance boundary. Close
   any missing growing lifecycle/catalog contracts before relying on them.
2. Implement the Zig server composition and local supervisor/gateway, reusing
   existing services, public bootstrap/recovery and launcher fault fixtures.
3. Implement the console on the shared compiler/client/editor contracts and
   add terminal-specific presentation and slash-command dispatch.
4. Exercise the actual commands on disk-backed installations and through a
   pseudo-terminal and noninteractive pipes. Record supported profiles, costs
   and usage beside the components; hand M25 a versioned artifact/dependency list.

## Exit criteria

- [ ] Document and exercise both public commands, configuration precedence,
  help, errors, signals, output formats and migration from existing entry points.
- [ ] One `transit server` runs the declared functioning local neighborhood;
  an independent `transit console` can discover authorized schema, submit SQL
  and read the verified result through its gateway.
- [ ] Prove partial-bootstrap recovery, duplicate-manager refusal, port conflict,
  child/supervisor/node/store loss, restart exhaustion and clean shutdown without
  orphaned children, silent reinitialization or loss of accepted work.
  Recovery preserves PIDs and exact operation identities and rejects stale owners.
- [ ] Publish role-specific credentials, readiness, storage and resident budgets;
  stalled logs/clients, denied reads and full storage preserve control progress.
  Report native isolation limits separately from reference deployment evidence.
- [ ] Shared Board/terminal fixtures establish grammar, capability and catalog
  agreement for valid, incomplete and unsupported SQL; completion leaks no hidden
  metadata and discards revoked or stale generations. Measure latency and memory.
- [ ] Real terminal tests cover multiline/pasted text, comments/quoting,
  completion edits, slash commands, EOF/signals, non-TTY use and safe rendering.
  Exact retries, cancellation races and lost replies retain current query proofs.
- [ ] Public-operation fixtures demonstrate SQL/CLI/Board semantic agreement for
  every advertised query or administrative form. Unsupported forms never partly
  execute; neither typing nor metadata completion applies changes.
- [ ] Run focused and clean committed-HEAD qualification through real `just`
  tasks. Record evidence and platform limits in [tests](../../tests/README.md)
  under [M10](M10.md)'s cost policy; proposed checks remain outstanding until run.

## Outside the selected profile

Distributed authority transfer, multi-host scheduling, HA/disaster restore and
general provider portability remain [M26](M26.md). Release distribution belongs
to [M25](M25.md). PostgreSQL wire compatibility, execution of all reference
grammar forms, continuous SQL and automatic effects on edit are not implied by
a psql-like shell or by sharing Board's completion experience.

## M23 implementation findings carried into the CLI

Reuse the shared finite query workspace, native draft budget records, neutral
TypeScript transport/result reader and application compiler as their actual
qualified profiles permit. The SQL candidate catalog currently returns at most
eight complete, compilable statements for one authorized source. It is not the
incomplete-cursor editor contract required above: add that shared contract and
its Board/terminal fixtures explicitly, rather than relabeling whole-statement
suggestions as typeahead.

The work-item application composition keeps publication inspection, query signing
and operator signatures separate. Its current binding must match the active data
contract, while recovery of an already prepared query does not depend on loading
that binding. Carry this distinction into console configuration changes, server
restart and terminal reconnect. A local UI's private deployment and shared query
identity do not provide remote per-caller authentication for the CLI gateway.

Bounded reads need independent observation cuts and must not monopolize signing
or recovery. The generated application's browser proof exposed contention when
background page validation and explicit pagination shared one request lock.
Serialize signature preparation where needed, join redundant presentation reads,
and preserve control capacity; do not solve contention by extending accepted
operation lifetimes or silently issuing a replacement query.
