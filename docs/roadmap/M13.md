# M13 — Board relief atlas and public query access

[Roadmap](README.md)

Status: In progress following the M12 implementation review. Builds on
[M10](M10.md)'s growing capture/credit protocol, [M11](M11.md)'s growing hosts
and [M12](M12.md)'s qualified Table SQL compiler. These are implemented
prerequisites, not work to repeat here. Completion still requires the evidence
below; existing framework tests do not qualify the new public frontends.

Scope: a separately configured public **query** capability, consumed by
Board and a new `transit-cli` executable installed as `transit`. Both reuse
one Zig client/contract, Station query delivery, and the existing Fuze compiler.
M13 includes M12's compiled `SELECT` now; it does not add another SQL dialect,
optimizer, query engine, or language binding. Table-only execution retains the
source and schema basis, complete manifest, and bounded segment identities.

## M12 review and decisions

- SQL parsing and compilation are pure and reusable. Compile against an
  authorized descriptor before freezing a request; never derive authorization
  from successful parsing. Preserve omitted versus explicit LIMIT and aggregate
  restrictions. Reject unsupported syntax before submitting work.
- M11 already hosts growing Station behaviors and query contexts. Build a real
  query service using those APIs, not a second host ABI or language interpreter.
- A durable submission receipt is not query admission or completion. The
  requester behavior admits at most one active query per configured principal,
  with no accepted query queue; additional submissions get explicit busy outcomes.
  Transport inboxes remain subject to the deployment's admission quota. Query
  limits must not become a fixed total-history catalog.
- Reuse signed Transit commands and current authorized reads. A separate query
  identity has scoped send/read rights; the existing Board inspection identity
  remains read-only. Board requests execution from an external Station host;
  it does not run handlers or access storage. Frozen signed submissions retain
  exact retry identity after uncertain transport outcomes.
- Results are read one verified segment at a time. Revalidate source policy and
  resource access at every read, including reads after completion. Revocation
  clears protected browser/session state; already disclosed terminal output
  cannot be recalled. A local disconnect does not cancel a durable query.
- Public metadata has no live decoded byte-size metric. The atlas must label
  unavailable metrics and bounded-page coverage, rather than invent heights,
  ages, global counts or application meaning from opaque values.

## Entry gates and implementation sequence

1. Specify the shared versioned request, frozen submission, status, source basis
   and typed result-page contract. Keep signed transport submission, behavior
   admission, capture, partial delivery and verified completion distinct. Define
   explicit cancellation and per-principal active-work limits.
2. Add a reusable Zig query client and Station handlers, a runnable growing query
   host, and the additive `transit query` shell. Reuse the existing growing ABI,
   Table descriptors, Fuze SQL/PlanCodec and segment/credit implementation.
   Shell commands include `/help`, `/tables`, `/schema`, `/info`, `/cancel`,
   `/next`, `/format` and `/quit`; rendering does not implement query semantics.
3. Qualify real disk Ursula/node operation, lost receipts, host recovery with
   current ownership, quota rejection, cancellation, and revocation before and
   after partial delivery. Read-time denial must not expose stale typed rows.
4. Implement D5/D6's accepted architecture with explicit process/resource
   emphasis and overhead detail, coordinated with Browse. Record the focused
   D7 interaction decision separately from earlier review outcomes: explicit
   entry and one draft/result across Canvas/Browse. Auto emphasis, animated
   entry, D8 venues and growth horizons remain open unless specifically selected.
5. Connect the Board workspace through a separately configured query identity.
   Generate runtime-validated browser wire types from the Zig public contract;
   keep query execution explicit and view changes free of submissions. Test the
   real CLI and browser, then update owning docs and milestone evidence.

## Exit criteria

- [ ] The runnable query service hosts growing Station processes outside a test harness with `.query`
  configured, processing `result_chunk`/`result_complete`/`result_ack` frames
  under real disk Ursula/node conditions, reachable by at least one of Board
  or `transit-cli`.
- [ ] The query capability is specified and qualified as its own bounded
  public contract: authorized Table queries only, qualified Fuze operations,
  explicit source/schema revision, bounded concurrent queries per principal,
  and delivery through M10's segment/credit protocol rather than an unbounded
  response. It is provably distinct from Board's existing inspection grant,
  not an implicit widening of it.
- [ ] Board implements the accepted D5/D6 foundation (resource architecture,
  subtle process fabric, Figures 1 and 4's overhead detail) coordinated with
  the existing Browse mode per D1, using real authorized data rather than the
  design reviews' synthetic fixtures.
- [ ] Board's data workspace (design reviewed and selected from D7) lets a
  human enter one authorized resource, compose a bounded query, run it
  explicitly, and see the same draft/result in both a Canvas and a Browse
  representation without silently re-running or losing part of the query
  when switching views.
- [ ] `transit-cli` ships as `transit`, with `query` launching an interactive
  shell: `/`-prefixed meta-commands (at minimum help, schema/table listing,
  session/connection info, quit), typed result rendering, and the same
  authenticated query capability Board uses — not a second implementation of
  query semantics.
- [ ] Neither frontend can execute unqualified operations, decode opaque
  values, access a KV or Document source, or export/write results back into
  a source resource. Denial and revocation clear protected data in both
  frontends and in any remembered workspace state.
- [ ] Partial, expired, cancelled and denied query results are distinguishable
  from complete ones in both frontends; a result never silently completes
  from a partial batch, and current authorization is re-checked at read time,
  not only at query start.
- [ ] Test crash/restart of the growing host mid-query, revocation during an
  open Board workspace or CLI session, and denial before/after partial
  delivery. A remembered Board workspace or CLI history creates no retention
  pin and no offline copy of query results.
- [ ] Document the query capability's contract, `transit-cli`'s command
  reference and meta-commands, and Board's implemented workspace behavior
  beside their code; record which D7/D8 proposals remain open follow-ups
  versus implemented in this milestone.

## Outside this milestone

KV and Document adapters and cross-source querying remain [M14](M14.md)
work. SQL is exactly M12's qualified read-only Table subset, with no new syntax
or rewrite enabled here. Export, result write-back, joins/transactions across
resources and continuous/subscribed queries are excluded.

D3/D4's process-fabric-at-scale visuals (100 to 1 billion processes) and D8's
shared-venue/growth-readiness treatment are not required deliverables here.
They are large enough, and distant enough from "run a query," to warrant their
own milestone if design review does not resolve them within this one's
timeline; insert one under the [sequencing rule](README.md#maintaining-the-sequence)
rather than silently deferring them or cramming an unreviewed interaction in
to close this milestone's exit criteria.

`transit-cli` does not replace or absorb `rey-cli`'s protocol-administration
commands in this milestone; that remains a separate, later decision. Browser
or offline query execution, a saved/scheduled query capability and any export
format beyond typed rows in each frontend's native rendering are excluded.
