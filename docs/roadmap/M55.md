# M55: Automatic local server startup

## Scope

Use one `transit server` invocation for creation, recorded bootstrap recovery and
ordinary restart. Preserve installation identity, exact provisioning receipts,
current grants, artifact compatibility, storage markers and rollback detection.
This follows the local usability work in [M53](M53.md) and the storage foundation
in [M54](M54.md). It changes the local supervisor, not raw node bootstrap or
provider initialization contracts.

## Implementation

1. Remove the public server initialization switch. Under the existing sibling
   lock, classify the destination as missing, empty or populated. Create only
   the first two; populated directories must pass existing recovery validation.
2. Add `startup.require_existing`, default false, to typed YAML/environment
   settings. It rejects missing/empty destinations before creation and applies on
   restart. SQL inspection and reload use the same registry.
3. Preserve private staging, fsync and nonreplacing publication. An empty
   destination may be removed only with nonrecursive directory removal. Refuse
   symbolic links and files. Never infer a new installation from missing records
   in a populated directory or adopt unpublished sibling staging files.
4. Report creating/resuming/opening on stderr and preserve ready stdout. Update
   public contracts, guides, examples and all local-server proof callers.
5. Replace the shared definition for the changed settings checkpoint registry;
   regenerate schemas, SDK resources and independent signing/storage fixtures.
   Reject older definitions without rewriting or deleting existing installations.

## Validation

Unit coverage checks absent/empty admission, existing-only policy, identity
preservation, link/file refusal and contents appearing before publication.
Real server proofs cover YAML/environment policy, no effects on rejected paths,
first start, empty-directory creation, normal restart, SQL settings/reload and
interrupted bootstrap with exact receipt recovery. Existing missing storage,
checkpoint loss, artifact mismatch, rollback and lock proofs remain required.

Run `just check`, `just test::server-faults`, the configured SQL access and Board
proofs, then committed-source `just ci-clean` lanes relevant to the changed
contracts and local startup. Record executed results and failures in the proof
ledger; planned checks are not passing evidence.

## Status

Implementation and qualification in progress. Deployment data remains untouched;
all new startup and recovery checks use disposable installations.
