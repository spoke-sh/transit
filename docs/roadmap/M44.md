# M44 — Semantic declarative diagnostics

Tracking: [#69](https://github.com/rupurt/rey/issues/69).

Errors must explain the failing construct or object, the authoritative outcome
and a valid next action. Detailed caller-owned input is useful diagnostic context;
credentials, unrelated stored values and inaccessible objects remain outside it.
The tracking issue records the source review, open questions and adversarial
acceptance matrix. Parser acceptance does not establish execution support.

## Delivery

- Record the conflicting INSERT key and one-based input row in the atomic
  terminal mutation status; preserve it across replay, restart and later data
  changes. Carry signed keys through all ten SDKs without JSON precision loss.
- Separate terminal rejection, rejected input, preparation failure and unknown
  send in console presentation and recovery guidance.
- Retain compiler subject, type and source location; classify unavailable
  statements before unrelated local-interface I/O.
- Preserve original query failure evidence and file/application attribution.
- Qualify disclosure, partial results, compatibility and cross-interface parity
  against the issue's full matrix before closing it.

## Implemented increments

- A checked source inventory covers declarative owners, literal error-reference
  counts, named outcome/operation tags, imports and checked grammar productions.
  CI requires explicit review when that surface changes; semantic mapping and
  executable-case completeness remain separate closure gates.
- A generated neutral diagnostic contract validates owned context, precise
  integers, explicit missing-detail reasons, outcome evidence and identity-bound
  recovery actions. Adapter adoption and domain mappings remain in progress.
- Atomic mutation conflict witnesses and all-ten-SDK transport; console
  rejection, input disposition and uncertainty guidance are separate.
- Owned SELECT/mutation binding context, file/record/field attribution, and
  offline application member/option/nested-SELECT diagnostics.
- Prepared parameter indices, all SQL use sites, types/counts, scalar correction
  context and changed-schema fingerprints; both console modes retain shared
  compiler context without creating work on failure.
- Absolute script/statement byte coordinates and completed-command counts survive
  framing, comments, CRLF and Unicode without retaining input buffers.
- Interactive first-failure row/column/instruction and exact adapter keys,
  frozen binding identity, measured budgets and KV decoding reasons; current
  permissions gate enrichment and incomplete output remains explicit.
- Original finite-query failure codes, measured page/segment/result-byte limits
  and compact runtime row/column/instruction/key/decoder witnesses are retained
  in source and requester records. The failed job fits 255 bytes. All ten SDK
  status models and Board carry the shared envelope alongside the original
  failure; retirement changes presentation without replacing the cause.
- Source admission and durable query closure retain expected/observed policy
  revisions, resources, declarations, Table schemas and allowed/requested budgets.
  Metadata repair and retirement preserve the original witness within existing
  record/turn bounds. Non-UTF-8 script paths have explicit byte encoding.
- Writer errors point to `.schema writer`, which inspects the current authorized
  write target independently of the read source and preserves saved recovery.
  Mutation scalar context and machine categories/truncation are explicit.
- Owned file conversion scalar/type/path/discovery evidence and first runtime
  predicate/aggregate row, column, instruction and binding/plan identity.
- All ten SDK exception/error models retain bounded owned diagnostics and flag
  invalid optional detail without replacing primary uncertainty. Native callers
  share the Zig validator; port callers validate the generated envelope shape.
  The C error layout and exported validators use a coordinated definition cutover.
- Board query failures retain compiler/attempt envelopes through HTTP and the
  browser client, with evidence/target validation and caller-facing worksheet
  and Live draft presentation. Original SQL spans also survive EXPLAIN.
- Mutation rejection records retain observed policy revisions, permission masks
  and declaration fingerprints in one 192-byte value. Pure owner projections
  cover all mutation phases/reasons/input dispositions and catalog receipts/
  input dispositions. Caller adoption remains a separate increment.
- Flight/ADBC compiler detail and saved failure-code/status projection, including
  exact budget counters and current-access gating after gateway replacement.

The issue remains open. Complete semantic mappings and executable inventory
coverage, broader adapter/exception adoption of the structured diagnostic
envelope, broader source/lifecycle mismatch coverage, a structured Flight/ADBC detail channel,
and remaining publication/migration/reactive/effect outcome mappings are not established by
these increments. The source query failure-code table is a bounded domain
inventory, not an assertion that every reachable public failure is covered.

## Verification

The proof ledger owns executed results. New unit cases exercise each conflict
position, signed extrema, atomic rollback, changed stored data and malformed or
truncated witness records. Installed SDK mutation consumers must assert the
same witness after lost replies and exact recovery. A new shared v1 definition
rejects previous persisted/ABI semantics; no fallback supplies absent witnesses.

The shared query bridge now carries original compiler context through native
and port failures, including EXPLAIN. Attempt diagnostics distinguish local
preflight, unknown dispatch, authority command rejection and failed status reads.
Unknown causes are internal failures. Query compiler and uncertain-dispatch
diagnostics now survive installed native/port/SDK callers. Other error-producing
adapter families and full semantic validation at every foreign boundary remain
separate coverage; this increment does not establish them.
