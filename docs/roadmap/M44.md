# M44 — Semantic declarative diagnostics

Tracking: [#69](https://github.com/rupurt/rey/issues/69).

Errors must explain the failing construct or object, the authoritative outcome
and a valid next action. Detailed caller-owned input is useful diagnostic context;
credentials, unrelated stored values and inaccessible objects remain outside it.
The tracking issue records the source review, open questions and adversarial
acceptance matrix. Parser acceptance does not establish execution support.

## Delivery

- Record the conflicting INSERT key and one-based input row in the atomic
  terminal mutation status; preserve it across replay, restart and later data
  changes. Carry signed keys through all ten SDKs without JSON precision loss.
- Separate terminal rejection, rejected input, preparation failure and unknown
  send in console presentation and recovery guidance.
- Retain compiler subject, type and source location; classify unavailable
  statements before unrelated local-interface I/O.
- Preserve original query failure evidence and file/application attribution.
- Qualify disclosure, partial results, compatibility and cross-interface parity
  against the issue's full matrix before closing it.

  executable-case completeness remain separate closure gates.

  integers, explicit missing-detail reasons, outcome evidence and identity-bound
  recovery actions. Adapter adoption and domain mappings remain in progress.
- Atomic mutation conflict witnesses and all-ten-SDK transport; console
  rejection, input disposition and uncertainty guidance are separate.

## Verification

The proof ledger owns executed results. New unit cases exercise each conflict
position, signed extrema, atomic rollback, changed stored data and malformed or
truncated witness records. Installed SDK mutation consumers must assert the
same witness after lost replies and exact recovery. A new shared v1 definition
rejects previous persisted/ABI semantics; no fallback supplies absent witnesses.

The shared query bridge now carries original compiler context through native
and port failures, including EXPLAIN. Attempt diagnostics distinguish local
preflight, unknown dispatch, authority command rejection and failed status reads.
Unknown causes are internal failures. Query compiler and uncertain-dispatch
diagnostics now survive installed native/port/SDK callers. Other error-producing
adapter families and full semantic validation at every foreign boundary remain
separate coverage; this increment does not establish them.


## Serving control witness increment

Serving and reactive input dispositions replace bare reason bytes with one
bounded record containing the original input commitment, reason/cause and values
used at the failing check. Expected/observed revisions, policy, codecs, identity
commitments, quotas, generations and lease/session phases survive later metadata
changes. Explicit session closure differs from reached or recorded expiry.
Current native/service read authority gates all retained detail.

The private browser client preserves committed rejection reasons, verifies the
observed input identity, validates optional evidence independently and records a
later scope failure separately. Current denial suppresses protected diagnostic
facts. Query, application and reactive clients share a neutral diagnostic library.
The coordinated current-v1 cutover covers stored serving dispositions, reflected
responses and the distinct closed terminal. The proof ledger records executed
checks; this increment does not complete Follow terminal, adapter read/transport,
effect or full semantic-inventory coverage.


## Follow stop and query outcome increment

Follow preserves original scheduling stop evidence in the existing bounded view,
including closure in the session transition that removes the active slot.
Cancellation/retirement no longer leaves a stale copying/admitted phase. Status
reads copy the head/view/query together and project the independent original query
failure under current disclosure rights. The browser owns both details, preserves
non-denied exact results and does not automatically retry or reset on a failed
refresh. Watch validation records original schema/type/progress-marker mismatches.
This coordinated current-v1 cutover replaces the view and private status layout.
Adapter read/transport diagnostics, broader field-level witnesses, effects and
complete semantic inventory coverage remain required.

## Serving adapter evidence increment

HTTP failures and SSE/WebSocket terminals carry the neutral diagnostic with a
finite primary reason. Request-local evidence distinguishes local decoding,
failed reads, unknown exact sends, native rejection and known native receipt.
Concurrent socket input/event tasks own separate evidence; interrupted output
cannot append a second HTTP response. Truncated commands retain their decoding
cause without becoming transport outages. Bootstrap timeout, closed session,
expired lease, unavailable resource, changed read cut and unsupported read
capability have distinct meanings. Browser errors preserve known HTTP status,
validate optional detail and exact submission identity, and avoid implicit
snapshot reset or fresh command retry. Generated OpenAPI/AsyncAPI reuse the
shared diagnostic schema within their existing description budget.

This completes the adapter increment's executed scope in the proof ledger.
Serving operation outcomes, effect outcomes, broader field witnesses and the
complete semantic inventory remain required.

## Serving operation outcome increment

Serving records retain authenticated reply byte counts and validate phase/result
consistency within a 170-byte maximum. Every phase has an owner projection with
original route, codec, policy, deadline, commitment and resolution identity.
Result-read refusal is distinct from pending admission and exposes the original
outcome only after the final current-authority check. HTTP and reactive events
share the projection; browser validation keeps optional detail independent and
binds it to operation, resource, realm, caller/service and terminal input. Live
views retain operation detail separately from snapshot/refresh progress. The
current-v1 cutover adds serving identities and owner-completed/failed outcomes.
Effect evidence, broader field-level witnesses and semantic inventory completion
remain required.
