# M16 — gRPC connector and bounded streaming calls

[Roadmap](README.md)

Status: In progress; second connector, after [HTTP/shared exchanges M15](M15.md).
[GRPC.md](../GRPC.md) owns protocol semantics. This plan is based on implemented
M14 storage and inspected kernel limits. M15's local, Compose and reference
recovery schedules now pass with the hardened pinned TLS adapter. Expanded
hosted cost evidence remains open and is not inferred from local timings.

## M15 handoff and initial authority decision

Reuse Exchange's immutable segment/coverage, frozen intent, exact terminal
settlement, EXB2 descendant holds, current-availability replay and bounded cleanup.
Reuse Publication for request bodies and descriptors, public growing ownership
and scoped bindings for workers/callers, and the pinned TLS certificate verifier.
HTTP framing, template syntax and response status remain in the HTTP adapter.

The first RPC profile fixes a finite outgoing batch and its half-close before
committing the effect intent. One dispatch covers exactly that batch, method,
destination, credential references and finite budget. This supports all four
method shapes, including concurrent bounded response capture, without granting
permission for arbitrary later writes. Responses cannot generate more messages
on the same connection. A worker restart closes unknown rather than replaying
any sent prefix; a new call requires a new explicit effect. No kernel widening
is needed for this profile. Interactive response-dependent sends require a
separately specified authority extension and are not claimed here.

Required ALPN negotiation now has independent TLS 1.2/1.3 evidence for `h2`,
missing selection and incompatible offers. The finite transport now passes all
four call shapes against independent grpcio, with binary/Unicode/full-width
protobuf, duplicate/binary metadata, trailers, non-OK status and finite budgets.
An independent h2 peer proves simultaneous directional credit progress and
refusal of malformed terminal envelopes. The pinned client engine adds bounded
polling and strict terminal validation; it imports no high-level retry client.
The [durable RPC contract](../../contracts/STATION_GRPC_V1.md) and request codec
now have independent binary fixtures. Publication shares HTTP's resumable upload
helper; the unchanged HTTP failure corpus passes in 483.14 seconds. Exchange
response publication and effect settlement now share authenticated Exchange
service/worker helpers; placement qualification remains open.
Pure RPC capture/replay now validates indexed body digests, actual sent counts,
ordered filtered metadata, frozen endpoint/schema/credential policy and explicit
retry equality against all live peers. The separate disk-backed worker proof now
passes all four complete and partial-crash shapes, current-policy replay, exact
receipt recovery, explicit idempotent retry and bounded cleanup in 344.45 seconds.
All ten M11 language targets now pass installed caller/replay/disposal schedules
through the shared native binding. Deployment, Board and remaining authority/
publication races remain open.

Scope: Zig-native unary, server-streaming, client-streaming and bidirectional RPCs
with finite live-call/message/byte budgets. Reuse M15's exchange lifecycle,
immutable body references, capture/replay, current-policy reads, secret references,
reconciliation and cleanup. Extend the shared components for demonstrated needs;
keep protobuf, RPC status and stream direction semantics in the gRPC adapter.

## Entry gates

| Gate | Required decision and evidence |
| --- | --- |
| M15 handoff | Run the common contract/failure corpus with a binary-message adapter; enumerate reused APIs and small required extensions. Do not copy HTTP's lifecycle or encode protobuf as HTTP text |
| Transport | Select immutable Zig-compatible HTTP/2, protobuf and TLS dependencies and generated descriptors; qualify trailers, metadata, framing, compression bounds, flow control and cancellation against independent peers |
| Streaming authority | Map exact committed outgoing message/batch, stream-open and half-close units to current dispatch authority. Existing one-shot effect authorization is not a blanket permit for future sends; define/prove any generic extension before interactive I/O |
| Executor ownership | Record call/connection incarnation and ordered handoff, distinguishing PID fencing from a previously authorized executor's possibly-in-flight send. Recovery cannot move a live connection or infer remote accepted offsets |
| Capacity | Measure directional credit units, wire/expanded message and metadata sizes, active calls, captured segments, retained evidence, queued work and reserved control capacity; reuse M14 chunks without treating 64 KiB qualification as a whole-call bound |
| Retry | Prove the selected transport cannot transparently redial, retry, hedge or apply service-config retries. Every fresh RPC is an explicit recorded attempt; method-specific idempotency remains a separate policy |

## Implementation sequence

1. Review M15 outcomes and settle versioned binary call/message/terminal contracts,
   descriptor digests and shared fixtures. Define per-direction order and coverage;
   there is no invented total causal order across the two directions.
2. Qualify the reusable transport without effect semantics, then implement the
   gRPC adapter over common exchanges. Keep the eventual inbound Flight server
   adapter separate from outbound dispatch authority.
3. Implement unary and each streaming shape behind the same explicit authority,
   bounded admission and publication rules. This sequence does not permit calling
   a unary-only implementation a completed streaming milestone.
4. Exercise peer stalls, crash/revocation/closure races and partial transcripts.
   Reuse HTTP's common failure corpus and add streaming-specific negative cases.
5. Complete generated shared bindings and all M11 SDK adapters, actual Zig
   example workers, launcher/reference proofs and Board metadata. Record the
   measured reusable transport/capture surface for M17 onward.

## Exit criteria

- [ ] Publish language-neutral call, pinned descriptor/schema, message, half-close,
  transcript and result contracts. Generated helpers construct durable requests
  without sockets, credentials, reflection or hidden network schema discovery.
- [ ] Exercise all four call shapes against independent peers. Qualify ordered
  binary/duplicate metadata, message bytes, trailers, terminal status, compression
  limits and explicit finite budgets. Preserve original protobuf bytes before
  decoding; redaction cannot claim byte-exact secret-bearing capture.
- [ ] Commit each outgoing message or bounded batch before authorizing those exact
  bytes, method, destination and credentials. Prove current-policy/work-cutoff
  races, half-close ordering, executor fencing and control progress with a blocked
  peer. The initial call permit grants no arbitrary subsequent sends.
- [ ] Persist directional observations and coverage before disclosure. Explicitly
  provisional messages remain distinct from a complete captured terminal result;
  `OK` alone cannot hide missing capture or undo prior application progress.
- [ ] Enforce bounded queues and admission credit independently in both directions;
  HTTP/2 credit and local transport writes do not prove remote durable handling.
  Oversized/decompressed input and exhausted capture capacity fail visibly without
  dropping already accepted messages or starving closure/cancellation.
- [ ] Inject worker/authority/store failure before send, after remote execution,
  during each partial stream shape and before final publication. Resume recorded
  local progress without replaying a sent prefix or implicitly reconnecting.
- [ ] Prove no hidden retry/hedging, an explicit idempotent retry, a non-idempotent
  unknown outcome and permanent bounded reconciliation closure. Generic remote
  stream resume is unsupported without a separately qualified acknowledgement and
  deduplication protocol; local cancellation cannot promise remote rollback.
- [ ] Prove TLS/authority/method/credential scope, alternate-endpoint and forged
  result rejection, current transcript/body reads, caller retirement and safe
  group cleanup. Historical body references cannot bypass current group policy.
- [ ] Replay with dialing, sending, reflection and secret resolution disabled.
  Every M11 SDK runs shared binary/Unicode/metadata/outcome and ownership fixtures;
  shared Zig owns ordering, capture and reconciliation semantics.
- [ ] Ship a Zig reference caller, connector worker and local/Compose/reference
  tasks. Qualify real worker loss and effect isolation; independent foreign
  implementations are test peers, not the runtime gRPC implementation.
- [ ] Add bounded service signals and authorized Board call/attempt, direction,
  coverage, half-close and terminal metadata, with no application protobuf decoder.
- [ ] Run M15's unchanged common corpus plus streaming additions; document measured
  limits, client/dependency versions, recovery and CI cost. Review the shared
  abstractions and the M17–M20 plans against actual connector evidence.

## Boundaries and later handoff

No generic application RPC server hosting, gRPC-Web, unlimited live sessions,
transparent partial-stream restart or exactly-once remote effect guarantee.
[Flight M19](M19.md) later qualifies its own ingress identity, server RPC adapter,
metadata and ADBC clients over this transport. [Documents M17](M17.md) and
[unified queries M18](M18.md) reuse publication/read/reference patterns, not RPC
semantics or a dependency on live connections. Later plans are reviewed now for
coherent composition and reviewed again when both connectors have executable
qualification; this document does not invent that future evidence.
