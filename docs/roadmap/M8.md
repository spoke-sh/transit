# M8 — Station GenServer, supervision, and registries

[Roadmap](README.md)

Status: Planned; builds on [M7 state resources and associations](M7.md), the
kernel, Board, and the development/operator tooling delivered through [M6](M6.md).

Scope: the Station Zig library and behavior workers expressing Transit's proven
kernel and [state primitives](../STATE.md). Handlers use associated resources;
the framework does not require replacing one application-state blob per message.

## Entry gates

The [pre-Station review](../reviews/PRE_STATION.md) compared M7's implemented
profile with this milestone. These are prerequisites within M8's existing scope,
not claims that M7 already implements a framework. Specify and prove them before
settling the public behavior API:

- [ ] **Authenticated inputs and least privilege.** Deliver trusted origin/kind,
  source PID/turn or external principal, and effect/attempt evidence where
  applicable. A forged correlation/reply/lifecycle payload cannot impersonate
  those sources. Define registry/supervision rights without distributing the
  realm root key to behavior workers; serialize each principal's mutations.
- [ ] **Delivery and notifications.** Supply a recoverable outbox delivery loop,
  timer observations and process/activation lifecycle notifications. Declare
  service ownership, current grants, retries, readiness and shutdown behavior.
  Prove progress without the test harness issuing `deliver` commands.
- [ ] **Initialization and failure.** Record child creation/initialization intent,
  resource allocation and completion so crashes neither run ordinary handlers
  early nor duplicate children/resources. Distinguish activation loss, a
  durably blocked handler, termination and replacement; define recovery without
  bypassing the existing block or minting a new PID on an uncertain spawn.
- [ ] **Atomic layout and recovery.** Fit behavior data and waiting/correlation
  records that must commit together into one writable resource with versioned
  key ownership. Specify recovery of an uncertain proposal, view expiry,
  grant loss and cancellation before recomputation or cleanup.
- [ ] **Capacity and retention budget.** Size a concrete GenServer/registry/
  supervisor example against lifetime catalogs, four concurrent views and the
  shared journal. Include repeated calls and child replacement, not just initial
  startup. Define backpressure when a fresh view or output slot is unavailable;
  do not promise indefinite service with unreclaimed lifetime catalogs.
- [ ] **Suspension and inspection evidence.** Define the requested resumption
  bound over required resources, and versioned framework descriptors exposed
  through authorized reads. Prove scoped observation without requiring access
  to every related PID or decoding application values in Board.

If these require an independently deliverable kernel expansion beyond M8's
scope, insert and number it before Station under the [sequencing rule](README.md#maintaining-the-sequence).
Do not silently weaken these gates or add a follow-on to a completed milestone.

## Exit criteria

- [ ] Provide a GenServer behavior with initialization, sequential handlers,
  named state associations, transactional mutation proposals within M7's boundary,
  sends, and correlated request/reply on a Transit process/PID.
  Demonstrate that the process primitive also works without a GenServer behavior.
- [ ] Build a minimal typed Table interface over the proven KV contract for
  registry and supervision records. Define schema/version checks and bounded
  access without adding arbitrary queries, automatic migrations, or new commit
  guarantees. Persist waiting/correlation state through the same resource model.
- [ ] Implement a minimal scoped registry with explicit scope lifetime and
  durable register/unregister/conditional-rebind operations. Prove recovery,
  conflicting registration rejection, and support for unnamed processes.
- [ ] Record resolved PID/revision before delivery; test name rebinding and
  termination races with retries and late replies, without redirecting them.
- [ ] Persist waiting state; route replies, timeout observations, and lifecycle
  notifications through mailboxes without holding a turn open for external I/O.
- [ ] Expose retention contracts and bounded suspension. Reject a resumption
  request beyond required mailbox/resource lifetime; report permanent expiry
  separately from retryable activation failure. Prove that supervision stops
  retrying expired PIDs and that replacement requires an explicit new spawn.
- [ ] Demonstrate workload-scoped temporary streams surviving worker recovery
  and retiring after logical owner termination/expiry with dependencies resolved.
- [ ] Implement supervision with durable child identities, restart policy, and
  restart limits. Distinguish same-PID recovery from termination/new-PID spawn;
  prove supervisor and child recovery without duplicate children. Lifecycle
  observations distinguish process termination from activation loss.
- [ ] Provide bounded poison-message handling, authenticated replies and
  explicit cancellation/timeout outcomes; demonstrate a blocked process remains
  inspectable and lifecycle control does not depend on its handler returning.
- [ ] Demonstrate multiple processes exchanging messages across workers, preserving
  each mailbox's order and recovering pending deliveries.
- [ ] Provide a small runnable non-trading example and trace inspection commands.
- [ ] Add versioned Board lenses for GenServers, supervision, and registries,
  with explicit identity/schema provenance and links to underlying PIDs and
  state resources/records. Interpret framework structure without application
  value decoders. Prove unknown versions fall back to kernel views without
  guessing behavior from names or code tags. See [Board](../BOARD.md#higher-level-interpretation).
