# M40: Extended SQL operations and relational composition

Status: explicit source/output aliases and bounded Boolean composition are
implemented through native finite queries and local file queries. Their
source-qualified checks and remaining performance/recovery gates are recorded
below. COUNT(column) is implemented with current-source qualification pending.
Other operation families remain planned. This work
follows [type semantics and schema discovery M39](M39.md) in the roadmap, extends
[SQL M36](M36.md) and completes the remaining operations already indexed by
the [SQL reference](../reference/sql.md). The ongoing SQL implementation effort
includes both milestones; an initial finite-query increment does not complete it.

Renumbered from the SQL branch’s former M36 and M38 after main inserted M34,
M37 and the standards/branching M38, then from M39 when the type-system
prerequisite was inserted. Its original scope remains intact.
The original full-reference implementation scope remains selected. M34 owns its
selected finite Table joins/grouping and maintained operator guarantees; this
milestone extends that profile without redefining its snapshot-vector, bag/null,
ordered arithmetic or complete-publication semantics. Distribution remains M35.

M38's standards ledger and semantic effect/trait model inform new lowering here;
its historical catalog contracts own snapshot/branch selectors and interpretation.
Reserve system-time syntax for temporal semantics, distinguish resource revisions
from catalog snapshots, and bind historical names/decoders before compilation.
These contracts are prerequisites where applicable, not implemented capabilities.
M40 retains the original remaining SQL scope without absorbing M38's graph,
foreign-relation or branch-storage implementation and without introducing a
second historical catalog or execution authority.

## Scope and owners

| Operation family                | Required semantics and owners                                                                                                                                                                                                                                                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Richer SELECT                   | Native source/output aliases and native/file Boolean composition lower through shared semantics; file output aliases, typed expressions, aggregation, grouping, ordering, joins beyond M34’s selected profile and reusable query composition remain. Zig Fuze keeps bounded active state and explicit durable spill where needed |
| EXPLAIN and query description   | Shared logical/physical explanation and output schema; compilation without execution, source disclosure or effect dispatch                                                                                                                                                                       |
| Historical reads                | Exact retained revision selection through existing authorized version handles; explicit unavailable-history and current-denial behavior                                                                                                                                                          |
| COPY                            | Typed import/export framing, source/destination identity, explicit batches and completeness; no hidden file/network authority                                                                                                                                                                    |
| MERGE and upsert                | One-resource selection/conflict rules, key immutability, atomic accepted changes and exact original-command recovery                                                                                                                                                                             |
| BEGIN, COMMIT, ROLLBACK         | Explicit transaction scope and resident/work budgets above Station; no invented cross-resource atomicity; rejected or uncertain commit cannot be called rolled back                                                                                                                              |
| PREPARE, EXECUTE and parameters | Owned typed parameter definitions, exact binding, source/schema compatibility, plan lifetime and bounded prepared state                                                                                                                                                                          |
| ALTER, DROP, TRUNCATE           | Conditional definition lifecycle and dependency checks; retained data, logical retirement and physical cleanup remain separate                                                                                                                                                                   |

M36 owns the first executable inspection, bounded Table mutation, declaration,
maintained-query, subscription, event-time and recorded-effect profiles. Extend
those neutral contracts here rather than introducing another execution authority.
All operations need actual client, CLI and SDK reachability, shared validation,
current-source authorization and explicit unsupported transport profiles.

## COUNT(column) continuation

The next finite aggregate increment starts in `feat/sql-count-column` from
`a3e15a9f`, independently of the fixed qualification heads in #52 and #63.
The shared value-count transition, SQL compiler, native/file execution,
checkpoint codecs, manifest and all ten typed SDKs now expose the aggregate.
The coordinated native/plan definition cutover rejects prior definitions and
progress layouts. The implemented contract is:

- Count top-level value cells of any admitted source-column type. Missing/null
  contribute zero; type error/conflict fail in source order. Empty input returns
  uint64 zero, and overflow rejects. `COUNT(*)` continues to count selected rows
  without inspecting their cells. Neither spelling adds DISTINCT or expressions.
- Apply the existing predicate and derived-input LIMIT before aggregation.
  Retain separate selected-row and contributing-value counters, so null/missing
  inputs still consume the LIMIT. Preserve source/alias scopes and output aliases;
  the default output name remains `count`.
- Use a typed `count_values` aggregate with one projected source column and an
  explicit u64 `value_count` in resumable progress. Validate it against selected
  rows and require zero for other aggregate kinds. Preserve input-page, output,
  source-basis and current-authorization checks across recovery and cancellation.
- Treat the changed progress encoding and manifest/ABI fields as one current-v1
  hard cutover. Replace plan/native definition identifiers, regenerate schemas,
  binding resources and signing fixtures, migrate all ten SDKs and preserve
  missing/foreign-definition rejection. Old accepted work stays with its matching
  build; no fallback decoder, implicit migration or progress reset is permitted.

lowering and execution, then public surfaces and generated resources. Apply the
current v1 hard-cutover policy to incompatible stored, wire and ABI changes;
preserve missing/foreign-definition rejection and existing recovery gates.

SDK/CLI consumers, disk-backed recovery and failure injection. Test data larger
than resident caches for stateful relational operators and catalogs. Keep
semantics for null, missing, conflict and type error explicit in each operator.

separately. Compare frozen ReleaseSafe probes with alternating controls, retaining
