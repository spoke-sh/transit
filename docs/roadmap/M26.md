# M26 — User documentation and interface reference

Status: in progress. M25 makes a separately compiled application installable;
this milestone makes the implemented interfaces discoverable before
[M28 publication](M28.md). Documentation does not extend a runtime profile.

## Scope and owners

Add a Docusaurus site as `apps/transit-docs`, using strict TypeScript and the
locked workspace dependencies through Vite+. Present getting started, building
applications, querying, public interfaces and operation as user journeys.
Review every foundational document in `docs/` for status, navigation and the
boundary between implemented contracts and future design.

Keep one authoritative source for each topic. The site renders repository
Markdown and package guides directly; generated OpenAPI/AsyncAPI descriptions
remain derived from owning Zig types. Wire contracts remain in `contracts/`,
component configuration beside its implementation, and proof details in tests.
Provide readable operation/message/schema references and original downloadable
specifications. Preserve repository links and engineering history.

The reference must cover CLI commands and recovery, both SQL capability profiles,
Board OpenAPI, serving OpenAPI, reactive AsyncAPI, native signed protocol,
Flight/Flight SQL/ADBC, language SDKs and installation/bootstrap. Do not advertise
SQL DDL, unqualified Arrow types, public release channels or generic protocol
compatibility as implemented. Explain receipt, completion, uncertainty and
current authorization at the entry point where a user needs them.

## Exit criteria

- [ ] A locked Docusaurus package supports local development and static builds,
  portable hosting paths, accessible desktop/mobile navigation and diagrams.
- [ ] Task-oriented entry pages and interface references link all foundational
  topics, preserve source ownership and correct stale implementation status.
- [ ] OpenAPI/AsyncAPI operation and schema pages and downloads are generated
  from checked authoritative descriptions, without hand-maintained copies.
- [ ] Strict types, lint/format, production broken-link checks and browser checks
  cover the actual site; document their evidence and commands.
- [ ] Documentation-only CI changes build the site. Existing ordinary checks
  remain intact; new hosted timing is unmeasured until observed.

## Handoff

M28 must publish documentation and downloadable specifications for the exact
release, with tested installation commands and explicit compatibility labels.
A preview built from a checkout does not imply any public release is available.
M29 must update deployment and recovery guidance with the topology it actually
qualifies; a documentation diagram alone cannot establish distributed authority.
