# M26 — Clustered execution and portability

[Roadmap](README.md)

Status: Planned; follows [publication M25](M25.md), building on
[Transit CLI M24](M24.md), [declarative reactive applications M23](M23.md) and
[Flight interoperability M22](M22.md), and extends the
kernel, framework, connector, serving/reactive, Document/query and reference-runtime
proofs. Renumbered from the former M24 with its cluster obligations preserved.
M23 application-definition migrations do not establish authority movement or
disaster recovery; neither do M24's local supervisor nor M25's published packages.
Those remain this milestone's obligations.

Scope: extend the reference slice to distributed supervision and lifecycle
management, while preserving a portable protocol. Build on
[M10](M10.md)'s growing-state profile, workload matrix and verification harness;
single-authority growth and multi-node execution are separate qualifications.

## Baseline after M18

M15–M18 supply reusable finite publication/capture, current-policy readers,
exact signed recovery and bounded cleanup over one growing authority. M18's
[physical query example](../../examples/state-query/docs/placement.md) qualifies
Table with source/requester hosts in separate Substrate actors, fresh keys and
exact ownership generations after physical worker and node/store loss. Its
courier and finite caller run at the operator; it is not an automatic growing
runtime binding, distributed registry or clustered authority proof. Native
KV/Document query recovery and their ten-SDK matrix do not fill those gaps.

Reconcile the [M8 runtime profile](M8.md) with
[growing Station's supported surface](../../packages/zig/transit-station/docs/growing.md)
before selecting a topology. The existing controller cannot be assumed to
reconcile growing query/service hosts merely because operator bootstrap works.
Version and qualify any missing growing runtime binding, registry or supervision
contract before using it for automatic movement. If that foundation requires a
separate implementation milestone, insert it under the roadmap sequencing rule
before proceeding with cluster claims.

Keep three recovery questions separate: can a fresh worker obtain current rights,
can the same authority recover retained history, and can authority safely move
under partition? The first two passed within declared profiles; the third needs
the routing/revocation/fencing protocol below. A new URL, pod, key or region must
not change a call's logical identity or revive retired source/request evidence.
An unavailable revocation authority cannot be replaced by a previously valid
source pin, ticket, route declaration or provider snapshot.

## Entry gates and reuse

M20 adds two concrete movement constraints. Its challenge is local to one gateway,
so challenge/attachment affinity must survive routing until consumed; shared
durable cursor verification alone is insufficient. Reference restart can also
exceed the logical session lease. Recover accepted operations independently from
explicit session reopening, and never grant extra lifetime because an observer
or revocation authority was unavailable. M21 render generations and M22 access
tickets must preserve this separation when placement changes.

M21 adds a narrow native read-access observation so metadata permission cannot
stand in for value-read authority. Partitioned adapters must preserve its current
grant/scope/lifetime and final-tail checks. Browser Web Locks cover only one
origin; route movement, multiple origins and non-browser callers need an explicit
shared-principal sequence strategy. Durable requester admission remains the
owner of accepted work. Count retained clock/lease/attachment inputs in movement
and recovery load, and never use retention to compensate for an unavailable owner.

M21's physical consumer proof also requires stable public/private endpoints
across pod replacement and reissued foreign-resource grants after fresh-key
registration. Native grant replacement starts a new incarnation; renewing worker
ownership alone cannot restore its prior resource permissions. A temporary DNS
or connection failure must preserve exact pending proposals and allow observation
recovery. It is not evidence that a process or its accepted inputs were retired.

| Gate | Required decision / existing component |
| --- | --- |
| Authority domains | Specify partition keys, owner/grant authority, revocation propagation, routing and rebalance protocol. M10 growing storage is not distributed write authority |
| Recovery roots | Reuse M14 publication, M15/M16 exchange evidence, M17 causal checkpoints and M18/M22 exact query references; define which authority protects every root and retirement decision across movement |
| Serving and watches | Reuse M19's fixed admission targets, M20's session/watch generations and M21's view recovery; specify route and subscription recovery across partition/placement changes without treating reconnect as new authority |
| Runtime | Inventory bounded-v2 versus growing runtime/controller/registry/supervision support; qualify missing public contracts before automatic movement. Separate sandbox movement, code migration and logical ownership; no provider snapshot grants execution rights |
| CLI and releases | Reuse M24's qualified local lifecycle and M25's immutable artifact/compatibility manifest. Extend their evidence for each clustered topology; a working local server or published image supplies no authority-transfer or HA proof |
| Failure model | Declare tolerated partitions/failures and availability tradeoffs before selecting coordination mechanisms; prove stale authorities cannot authorize new work |
| Capacity | Derive workload and control-reserve budgets from the completed single-authority components. Measure skew/hot actors, replica lag, retained pins and recovery, without choosing trading latency targets |
| Qualification matrix | Record source kind, query/serving protocol, authority profile, provider, SDK/client and failure topology separately; extend M18's Table physical baseline explicitly before claiming KV/Document clustered coverage |

## Implementation sequence

1. Revisit the completed M15–M25 evidence and define a concrete cluster topology,
   authority/placement protocol and generic adapter conformance suite. Close the
   growing runtime/controller entry gate before relying on automated scheduling.
   Keep higher-level component APIs unchanged unless a versioned contract is necessary.
2. Implement routing/ownership transfer and provider recovery over durable
   authority; qualify process/grant/mailbox safety before moving connector work.
3. Exercise common publication, cleanup, connector reconciliation, Document merge
   windows, serving admission, watch resumption and query-ticket suites across
   failure/partition schedules. Extend generic seams instead of adding a separate
   clustering path to each protocol.
   Run the existing one-authority suites unchanged as a baseline, then introduce
   movement/partition faults at prepare, admission, staging, manifest publication,
   pin release, read disclosure, retirement and bounded collection boundaries.
4. Qualify backup/restore/migration, Board partial observations and the portable
   local adapter. Publish measured topology/workload limits and operational steps.

## Exit criteria

Include control prerequisites in overload/recovery schedules. M21 needed a
small authorized clock read in reserved capacity instead of repeated discovery
before renewal. Test with concurrent views and multi-page result verification,
and require observers to reclaim expired live slots without deleting retained
session or query evidence. Empty-mailbox waits are not progress checks while
clock observers and live callers continue submitting identified work.

- [ ] Specify authority partitioning, routing and rebalancing before claiming
  horizontal write scaling. Preserve PID/mailbox order, fencing, grant/revocation
  authority and cross-partition delivery; independent appends do not create a
  cross-partition transaction. Measure hot-PID/partition behavior as well as
  aggregate throughput against the M10 workload matrix.
- [ ] Exercise Substrate suspend/resume, worker migration, and stale snapshots
  against kernel ownership and history validation.
- [ ] Recover `transit-runtime-controller` state and wakeups from backlog after controller
  failure; test ownership transfer during partitions and worker-pool changes.
  Prove the declared growing runtime profile end to end, including stale or
  duplicated bootstrap registrations, fresh-key grants and exact generations.
  A manual operator action or successful sandbox start cannot close this gate.
- [ ] Prove cluster-scoped registry uniqueness, conditional rebinding, and
  lookup consistency during partitions; unavailable mutation authority fails
  closed. Rebuild lookup projections from recorded registry history.
- [ ] Extend M1/M15/M16 sandbox, credential, and egress proofs, and M22 gateway
  access/result-recovery proofs, across supported cluster topologies and provider revisions.
- [ ] Extend M19 request/route/provenance recovery, M20 session/watch/resume and
  cross-protocol retry, and M21 live-view proofs across movement and partitions.
  Old route revisions retain accepted destinations; stale watch owners cannot disclose after their policy boundary.
  Missing cross-partition coverage produces explicit resynchronization, not an
  invented global cursor, snapshot or automatic command retry.
- [ ] Define and test runtime-adapter conformance independently of Kubernetes
  resource types; prove a lightweight local adapter can preserve PID, mailbox,
  fencing, and recovery semantics without provider snapshot support.
- [ ] Evaluate whether multiplexing processes within a sandbox is useful;
  document shared failure, suspension, snapshot, and isolation consequences
  before extending the initial one-process-per-Substrate-Actor mapping.
- [ ] Extend M7's proven KV compaction, tombstone cleanup, bounded reader
  dependencies, and resynchronization to distributed consumers and supported
  cluster topologies. Exercise consumer watermarks/pins and retry horizons under
  partitions; preserve no-resurrection guarantees and bounded GC resources.
- [ ] Extend M17 Document checkpoint/causal retention and replica resynchronization
  proofs across supported topologies; partitions cannot renew merge windows,
  revive retired documents or allow stale replicas to bypass current grants.
- [ ] Extend M14 publication and M18 unified source/read/result proofs across
  movement and partitions: no mixed revision, lost staging reservation, early
  root reclamation or permanent-identity reuse. Cross-resource/partition snapshots
  and transactions remain unsupported unless separately specified and proved.
  Include released source pins, result-prefix revocation, finite request-resource
  expiry and permanent retirement through restart/restore on both sides of a
  transfer. Preserve namespace/correlation and frozen mutation identity while
  endpoints change; never restore an unavailable old result by issuing a new query.
- [ ] Document backup/restore, post-termination retention, and code/schema
  migration with tested procedures, preserving policy, expiry, and deletion
  generations. Fence old deployments and reconcile external effects before
  allowing any restored history to authorize new live work.
- [ ] Extend Board qualification to distributed observations and provider
  changes; show independent read positions, uncertainty, and partial visibility
  without inventing a globally consistent snapshot or exposing hidden resources.
- [ ] Measure representative mailbox, turn, effect, and recovery workloads;
  establish latency/throughput targets from those measurements.
  Separate provisioning, compile/image work, fault recovery, query execution,
  cleanup, retained disk bytes and peak RSS. Publish per-topology measurements
  and hosted task costs; single-machine finite proof durations and cold-store
  sizes establish neither distributed throughput nor working-memory ceilings.

Cross-layer deadlines need a separate failure schedule: allow a legitimate slow
page to complete within the server budget, then cancel it at the caller boundary
and prove joined cleanup. Repeated caller timeouts must neither substitute a
query nor create a false complete-result claim. Reconcile a fixed accepted prefix
at observer restart and prove clock/expiry progress under continuously admitted
control traffic; global mailbox quiescence is not a recovery precondition.

Flight adds a replica-shared ticket verification key, not distributed authority.
Test credential/principal scope on each pooled RPC and revalidate source/service
rights after endpoint movement. Old ticket verification, durable request retry
and result retention are independent contracts; topology or key recovery cannot
make missing current rights valid. Measure complete native reads and metadata
workspaces as well as transport buffers under concurrent fetches.

Preserve the scoped-status boundary discovered by the Flight gateway: a caller
with a foreign resource grant need not be permitted to inspect the foreign PID.
Diagnose from durable query evidence unless process inspection is separately
authorized. Test both source and requester retirement after real returned
prefixes, including when metadata remains readable and capture pins are released.
Gateway failover must reconstruct canonical signed requests at their original
sequence, not infer deduplication from SQL text or a live connection.
