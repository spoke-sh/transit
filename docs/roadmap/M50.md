# M50 — Consumer SDK source and handbook boundary

Separate consumer APIs from the runtime before [M51](M51.md) configures local
database access. Status: implemented; committed-source qualification gates apply.

## Scope and decisions

- Move language APIs and native distribution packages to `sdks/<language>/`.
- Keep runtime entry points in `apps/` and shared Zig/TypeScript libraries in
  `packages/`. Board remains part of Transit.
- Add a Zig consumer package that exports shared modules with identical types;
  retain client, Station, query and native ABI ownership under `packages/zig/`.
- Update packaging, generation, workspace resolution, example consumers and
  documentation links together. Preserve package names and current contracts.
- Give the handbook a dedicated SDK sidebar with shared semantics, installation
  pages for every supported language and links to the detailed API owners.

SDKs may depend on shared runtime packages; runtime code must not depend on SDKs.
The repository root composes both runtime and example builds. Its lazy SDK
dependency is enabled for examples and disabled for runtime packages. Runtime
source closure excludes SDKs; requesting examples in that closure fails explicitly.
The docs app may read SDK Markdown without importing SDK implementation.

## Acceptance and evidence

- Generated declarations still match the unchanged shared definition.
- Runtime manifests/imports reject dependency inversion, with negative controls.
- The actual Nix runtime and SQL gateway build from a source tree without SDKs.
- An isolated Zig application compiles through the SDK and runs its declaration
  command; installed language consumers retain their existing conformance gates.
- Handbook links, search and navigation pass under root and prefixed hosting.
- Root checks and all ordinary clean lanes run against committed source before
  the PR is submitted. Incomplete checks are not counted as passed.

Current usage belongs in the [SDK handbook](../reference/sdks.md) and
[SDK source directory](../../sdks/README.md). Executed results belong in the
[proof ledger](../../tests/README.md).
