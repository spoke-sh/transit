# M20 — Reactive interfaces over HTTP serving

[Roadmap](README.md)

Status: Planned; follows [M19](M19.md). The selected scope is **live views with
resumable change notifications and snapshot refresh**, shared by Board and an
application interface. No subscription, continuous-query or predictive scheduling
implementation is claimed.

Scope: version and qualify a source/watch contract, HTTP notification delivery
and frontend refresh lifecycle over the serving foundation. [Reactive interfaces](../REACTIVE.md)
owns snapshot/change handoff, resume/gap semantics and the relationship to D4.
Finite snapshots keep M13/M18 query identity, source evidence, admission and
retention. [Flight interoperability](M21.md) follows as the second serving protocol;
it does not depend on continuous-query computation.

## Entry gates

| Gate | Required decision / evidence |
| --- | --- |
| Serving | M19's actual concurrency, identity, cancellation, quotas and deployment profile; one long-lived response must not occupy the only serving slot |
| Source/watch contract | A bounded public owner can acquire compatible snapshot and change boundaries without missing commits; do not assume existing inspection cursors or every M18 adapter has this capability |
| Initial matrix | Select a Board inspection projection, a Table query view and the application example; enumerate unsupported KV/Document projections rather than inheriting them implicitly |
| Notification meaning | Define invalidation/progress coverage, monotonic positions, duplicates, coalescing, reset-required outcomes and service/schema generations; notifications are not a complete event history |
| Transport | Pin SSE framing and the browser auth/reconnect reader; qualify real proxy buffering/timeouts and bounded event decoding, without credentials in URLs |
| Lifecycle and cost | Define watch admission, finite lease/renewal/close, current read checks, refresh quotas, retained-result accounting and explicit opt-in retention policies |
| UX | Distinguish displayed snapshot basis, changed/pending refresh, disconnected/gap and denied states; Follow changes must not claim D4's continuous Stream semantics |

## Implementation sequence

1. Specify versioned watch, source position, snapshot acquisition and reset
   contracts with independent fixtures and a deterministic handoff/resume model.
   Reuse public read owners; any missing generic read primitive gets a versioned
   public contract and qualification, never a Board-to-storage shortcut.
2. Implement one source/watch adapter and HTTP notification path over M19, with
   bounded leases, current-policy checks and recovery after serving-process loss.
3. Add the application live view and Board inspection/query refresh using one
   shared subscription client/lifecycle. A query refresh is a new finite query;
   an uncertain submission always recovers its original identity.
4. Prove duplicate/reconnect/gap, revocation, generation changes and slow-client
   schedules. Add each further source only with its decoder/schema/lifetime matrix.
5. Qualify browser and server recovery, overload, resource use and all three
   deployments; publish measured freshness/cost evidence and unsupported modes.

## Exit criteria

- [ ] Define and implement a public snapshot/watch handshake that loses no
  invalidation at a concurrent commit boundary. Prove overlap/deduplication or
  atomic acquisition; source policy/retention changes cannot produce a false
  complete snapshot or silently skipped change.
- [ ] Board inspection, a declared Table query view and an application view use
  the shared watch model. Each exposes the actual snapshot/source basis; panels
  from different sources do not imply one consistent cut.
- [ ] A watch binds principal/realm, published service, source/projection/filter,
  schema/decoder versions and generation. Current authority is checked on every
  bounded batch and within a declared maximum interval while idle.
- [ ] Resume after transport/gateway loss yields duplicate-safe ordered progress
  within retained coverage or an explicit reset/resnapshot. Reject forged,
  foreign, future, incompatible and retired cursors; possession grants no read.
- [ ] Coalesced invalidations carry their covered-through position. A commit
  during refresh remains dirty until a qualified snapshot covers it. Under
  quiescence and available capacity, the view converges without an unbounded
  queue or pretending every intermediate state was rendered.
- [ ] Refreshes preserve fixed query/source/schema identity and record their own
  admitted query/result IDs. Rows/profiles switch only to a complete verified
  snapshot. Late replies cannot replace a newer generation; changing the query
  or scope starts a new explicit generation.
- [ ] Known denial clears protected state and stops further disclosure; hidden
  names/counts do not leak through events or errors. A disconnected or stale view
  keeps its original permitted basis and never appears current by default.
- [ ] Pause, hide, lease expiry, renew, close and reconnect have explicit behavior.
  Bound abandoned watches and scheduled work without treating socket closure as
  durable query cancellation or expired lease as permission to erase results.
- [ ] One active refresh and one newest unsubmitted invalidation per initial scope
  cooperate with current query admission. Multiple tabs/viewers sharing a
  principal cannot multiply grants, starve peers or flood durable busy outcomes.
- [ ] Slow readers, reconnect storms, large results, notification floods and
  stalled authority/storage preserve bounded memory, scan work and control
  progress. Budget connections, buffers, delivery, refresh starts and retained
  results independently; quota refusal does not authorize data expiry.
- [ ] Qualify SSE framing/reconnect and the actual browser reader/proxy with
  independent peers, including fragmented UTF-8, partial frames, idle links,
  duplicate IDs and malformed/oversized events. Heartbeats do not claim source
  progress or durable consumption.
- [ ] Prove snapshot/change and cursor recovery under server/node/store restart,
  source retirement and opted-in retention advance. No raw Ursula tail or
  independent event bus is needed to reconstruct the watch's meaning.
- [ ] Provide real browser/application examples in local, Compose and reference
  placements, shared protocol fixtures, usage/recovery docs and `just` proofs.
  Measure source-commit-to-visible-snapshot latency, refresh/retention cost,
  fairness and resident bounds at declared loads; distinguish plans from evidence.

## Outside this milestone

Incrementally maintained continuous SQL, joins, retractions/aggregate maintenance,
event-time windows, external connector polling, arbitrary bidirectional sessions,
exactly-once event consumption, cross-source snapshots and offline data caching.
D4's automatic execution while typing, speculative predictions and Live session
scheduling remain proposed and require separate numbered implementation scope.
No `SUBSCRIBE` grammar or general administrative SQL is introduced. Subsequent
Flight support does not inherit a claim of continuous `DoExchange` semantics.
