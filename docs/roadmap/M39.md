# M39: Comprehensive types and bounded schema on demand

Status: final qualification in progress. The shared logical model, exact codecs,
frozen CSV/JSONL discovery, local file-query host, logical Arrow export and installed
Python/TypeScript owners are implemented. Comparative baselines and regression
gates are being recorded before the optimization pass. Final committed-HEAD clean
qualification remains outstanding. Tracked by [issue #36](https://github.com/rupurt/rey/issues/36).

## Outcome and baseline

Add a comprehensive Zig-owned type system that supports efficient ad hoc queries
over CSV and JSONL/NDJSON with explicit, partial or discovered schemas. Preserve
exact interpretation, five-state values, bounded resident work and current
authorization while comparing discovery and execution with a pinned DuckDB build.
DuckDB supplies comparison evidence, not runtime code or kernel authority.

The starting implementation at `d5541301` had six `Unified.Type` scalars: int64, uint64, finite float64,
boolean, UTF-8 and binary. Its schemas contained one to eight named columns; Arrow
represents value/null/missing/type-error/conflict separately. Source adapters
require explicit KV decoders, Table schemas or accepted Document projections.
Offline declarations support four scalar tokens; current stored Tables have an
int64 key and one nullable scalar value. That starting revision had no file reader, inference or rich logical values.
The implemented local profile below extends those capabilities while native
query, Table and Flight admission retain their declared narrower boundaries.

Current implemented behavior and each interface's limits are explained in the
[handbook type reference](../reference/sql/types.md). The
[performance owner](../reference/performance.md#schema-on-demand-measurements)
defines workload dimensions and measurement limits. Keep those public owners
sufficient to understand support without reading this delivery record.

## Dependencies and scope boundaries

This milestone follows [M38](M38.md) and precedes the extended SQL continuation,
renumbered from M39 to [M40](M40.md), because richer expressions and COPY need
these type and reader contracts. Work packages depend on the specific contracts
below, not on assuming every earlier proposal is implemented.

| Existing owner | Relationship |
| --- | --- |
| [M34 relational guarantees](M34.md) | Reuse equality, ordered arithmetic, multiplicity and failure gates when extending operators to new types |
| [M36 declarations and callers](M36.md) | Extend shared typed definitions, inspection and public surfaces; do not fork SQL, catalog or SDK semantics |
| [M38 standards and historical schemas](M38.md) | Coordinate type traits, richer Tables and exact historical binding; M38 retains catalog snapshots, branches and merge ownership |
| [M40 extended SQL](M40.md) | Supply type/conversion and source-decoding prerequisites for expressions, parameters and COPY; M40 retains statement orchestration and transactions |
| [Benchmark issue #35](https://github.com/rupurt/rey/issues/35) | Reuse provenance, result checking and reporting where available; file discovery workloads are distinct from declarative TPC coverage |

Neither fixed-point application policy, general continuous/event-time queries,
cross-resource atomicity nor a new external access mechanism is selected here.
The kernel stays generic. Fuze stays Zig native and outside authority; file and
network acquisition belongs to explicitly authorized adapters/connectors.

## Work packages

The initial [type contract](../../contracts/FUZE_TYPES_V1.md) and
[source contract](../../contracts/FUZE_SOURCE_V1.md) specify the selected semantics.
Independent descriptor/value/inference fixtures precede the reader and foreign
consumer implementation. T1–T4 and the declared T6 surfaces are implemented; T5/T7
performance and final clean qualification remain in progress.

| Package | Owner and deliverable | Entry gate |
| --- | --- | --- |
| T1 Shared logical types | Fuze/public contract owners: recursive type descriptors, field identity/nullability, canonical fingerprints, explicit scalar/nested families and unsupported families | Audit current query, Table, Document, catalog, plan/progress and Arrow definitions |
| T2 Semantic operations | Fuze: literal binding, casts, inference unification, expression promotion, equality/hash/order and aggregate result/error tables | T1; M34/M38 traits where applicable |
| T3 Discovery contract | Query/source owners: neutral options, immutable source identity, evidence, resolved schema and exact failure/completion rules | T1–T2; authorized acquisition and explicit capture/replay boundary |
| T4 CSV and JSONL | Zig adapters: explicit-schema path, bounded sampling, full-input discovery and raw mode; deterministic multi-file resolution | T3; independently generated framing/inference fixtures |
| T5 Execution and memory | Fuze/adapters: typed batches, bounded arenas and nested children, delayed conversion, cache identity and cancellation | T2–T4 correctness; baseline measurements before optimization |
| T6 Public surfaces | SQL, catalog/Station, Arrow and SDK owners: declarations/literals/inspection, generated neutral codecs, CLI/Board and installed callers | Per-surface capability matrix; coordinated incompatible-definition cutover |
| T7 Qualification | Tests/benchmark owners: differential and independent oracles, adversarial growth/recovery schedules, DuckDB reports and regression gates | Exact supported subset and reviewed comparison budgets |

T1 includes signed/unsigned widths, float32/64, exact decimals, boolean, UTF-8,
binary, date/time/timestamp/interval and UUID; recursive struct/list/fixed-array/
map/tagged-union and JSON representations. Decide 128-bit integers, decimal width
and precision, enum/domain/extension scope explicitly. A type is complete only
for the declared operation/storage/transport capabilities, not every conceivable
SQL family. Publish the initial matrix before implementation.

T2 specifies lossless versus lossy conversion and overflow/rounding, finite and
non-finite behavior, timestamp precision and timezone-data identity, map keys,
field order, string collation and nested state propagation. Define aggregate
accumulators and source-order failure behavior. Sampled inference and expression
promotion must not accidentally share a permissive cast table. Preserve full
u64 values and exact decimals through every language boundary.

T3 freezes source bytes/version, format/options, sampling locations/coverage,
algorithm definition and resolved type identity before output. Bound sample
bytes and records independently, plus fields, depth, files and active work.
An unresolved empty/all-null sample needs an override or explicit raw result.
Specify late unknown fields, incompatible values, strict versus typed-error/raw
outcomes, and bounded diagnostics without silently dropping rows. Non-seekable
replay requires explicitly budgeted spooling/capture or rejection; retries must
not consume a different stream under the same identity.

T4 covers CSV dialect/header ambiguity, multiline/escaped fields, encoding/BOM,
null versus empty, duplicate names and ragged rows; JSONL duplicate keys, sparse
objects, missing versus null, nested heterogeneous arrays, large exact numbers
and malformed records. Test multi-file permutations, name alignment, late schema
drift, compressed input and records split at arbitrary buffer boundaries.

T5 keeps logical types separate from physical layouts and retains scalar fast
paths. Evaluate batch dispatch, columnar buffers, nested offsets, bounded scratch,
projection/conversion pruning and reusable metadata. These are hypotheses until
measured. Pushdown cannot hide conversion errors or change the discovery sample.
Cache keys include source identity, schema, options and definition; cached bytes
or schemas never retain authorization. Resident memory must be independent of
row/file cardinality through bounded discovery and paged metadata/spooling.
Do not raise fixed limits or require retention opt-in to simulate that property.

## Acceptance and evidence

- [ ] Publish one type/capability matrix and semantic tables, with canonical
  neutral fixtures covering all selected families and five-state combinations.
- [ ] Verify inference and conversion using independent oracles, including
  2^53 boundaries, signed/unsigned extrema, decimal rounding/overflow, negative
  zero, temporal ambiguity, Unicode, empty/null/missing and nested conflicts.
- [ ] Prove deterministic resolved schemas for a fixed basis/options/evidence;
  distinguish a sampled candidate from full-input conformance. Test late
  outliers, sparse new fields and stale inference caches without silent coercion.
- [ ] Exercise files and file collections larger than resident budgets, bounded
  nested shape growth, allocation failure, cancellation, record-size rejection,
  partial framing and slow output. Account for RSS and all auxiliary allocations.
- [ ] For captured/durable workloads, use disk-backed Ursula and actual callers
  to test source replacement, accepted-but-lost replies, node/worker/store loss,
  exact saved recovery, revocation before/during/after discovery and failed-prefix
  completion. Ephemeral file scans do not claim durable recovery implicitly.
- [ ] Verify Arrow and installed language values/ownership per advertised type;
  generate boundary schemas from public Zig types. Preserve narrower Flight and
  other transport profiles until their independent tests pass.
- [ ] For incompatible changes, replace current v1 definition identifiers and
  migrate formats, consumers, fixtures, generated resources and docs together.
  Missing/foreign definitions and incompatible saved/stored work reject before
  execution; no old-format fallback or implicit data reset.
- [ ] Pin DuckDB version/build and corpus hashes, run the handbook comparison
  matrix, retain every raw sample and semantic mismatch, and establish reviewed
  numeric throughput/latency/memory regression budgets before optimization.
  Existing six-type explicit queries are mandatory regression controls.
- [ ] Update the handbook and component contracts as each slice is implemented;
  record actual commands, environments, failures and limits in
  [the proof ledger](../../tests/README.md). Run required focused proofs,
  `just check` and committed-HEAD `just ci-clean` before claiming completion.

## Implemented checkpoints

- T1/T2: bounded recursive types, canonical binary/JSON codecs, exact numeric and
  temporal binding/casts, domain promotion, structural equality/hash/order and
  shared specialized six-scalar definitions. Independent scalar fixtures cover
  all widths and exact semantic hashes.
- T3/T4: neutral frozen bindings, explicit/partial/sampled/full/raw discovery,
  bounded framing and recursive values, deterministic name alignment, current
  host checks and length/hash verification. Saved bindings require existing
  matching captures; they never refetch or grant access.
- T5: full-row validation through EOF, bounded row ownership and Arrow batching,
  private quota-limited gzip/stdin/file captures, cancellation and slow-output
  cleanup. A 600058901-byte input completes with swap disabled under a 256 MiB
  RAM/cache cgroup limit in explicit/sampled/full/raw modes. Final numeric
  regression gates and any measured optimization are recorded separately.
- T6: logical IPC export, reflected recursive JSON schemas, C ABI/native-port
  codecs and installed Python/TypeScript logical owners. The public
  [surface matrix](../reference/sql/types.md#surface-capability-matrix) explicitly
  retains native query, Table, catalog, Board, other language SDK and Flight
  admission limits. Additive local actions preserve existing operation meanings;
  new neutral documents reject missing/foreign definitions. No incompatible
  stored/native format cutover or durable file-job admission is selected.
- T7: independent source/scalar/SQL/Arrow/installed-owner oracles, exhaustive
  allocation failures, changed content, current denial, cancellation and failed
  prefix completion. DuckDB 1.5.2/PyArrow 23.0.0 comparison probes retain exact
  provenance and raw data. Baseline and final acceptance records follow below.

The [proof ledger](../../tests/README.md#fuze-logical-type-foundation) owns executed
commands and checkpoint scope. Core clean CI passed at `2b729f7a` and `13c00e1b`;
those results do not qualify later commits or unexecuted lanes. Native accepted
work retains its disk-Ursula recovery contracts and tests. Local file captures
are ephemeral, so their process-loss tests establish cleanup rather than durable
accepted-work recovery.
