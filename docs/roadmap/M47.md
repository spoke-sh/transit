# M47: General Table storage and query efficiency

Status: planned. Tracked by [issue #76](https://github.com/rupurt/rey/issues/76).
Implementation is selected with the complete shared foundation in [M54](M54.md).
Its baseline, integration and qualification gates supersede treating this work
as isolated Table tuning; the original accepted measurements below remain intact.
Follows M46 in the linear roadmap. It preserves M43/M45's completed profiles and
consumes the general typed-Table foundation without reopening their claims.

## Scope and sequencing

M46 measures higher mutation latency and read amplification than the former
two-column representation. On 2026-10-07 the user explicitly accepts those
documented costs for M46 and selects this separate optimization effort. The
[matched campaign](../../tests/mutation_latency/results/2026-10-07/README.md)
preserves original samples, failures, controls and source/binary hashes. Acceptance
does not turn historical budget failures into passes or establish a latency SLO.

1. Reproduce the integrated baseline and set per-workload improvement targets.
   Attribute preparation, computation, native requests, provider work, publication
   and completion; separate ordinary timing from instrumented counts.
2. Reduce redundant schema/definition reads and batch known immutable records.
   Bind caches to verified identity and exact source basis; preserve current
   authority, cancellation, stale-cut rejection and poisoned-read behavior.
3. Evaluate bounded batch disclosure for catalog queries. The current pull
   interface validates each returned row, while the console buffers rows. Any
   replacement needs an explicit authorization boundary, revocation-after-buffering
   tests and byte/memory bounds. Storage pages, execution vectors and output
   batches remain separate choices.
4. Reduce wide/nested and staged-statement reconstruction/publication costs.
   Compare immutable decode reuse, record packing and generic bulk publication
   with measured alternatives. Preserve native four-write/256-byte limits unless
   a separate generic authority contract is explicitly specified and qualified.
5. Evaluate scan/key layout and scalar range access for composite/no-key schemas,
   growing indexes and retained history. Coordinate incompatible changes through
   one current-v1 cutover, never a legacy fallback or silent reset.

The qualified M46 foundation can feed M34 / issue #70 independently of these
optimizations. Coordinate batch ownership/provenance with issue #71, schema and
historical identity with issue #31, and transport consumption with issue #48.
Neither SIMD nor joins alone removes provider or durable-publication cost.

## Qualification and exit criteria

Keep matched ReleaseSafe controls and independent value/count verification.
Separate row count, retained history, cache size, readers, skew and value width;
measure CREATE/ALTER/DROP and recovery alongside point/multi-row DML. Record
requests/bytes, allocation/resident memory, retained storage and control latency.
Use enough samples for every reported percentile and preserve failed outcomes.

Require exact lost-receipt recovery, original identities through ALTER/DROP/name
reuse, fenced replacement, current denial, atomic old-or-successor visibility,
allocation/quota/storage pressure and incomplete-result rejection. Requalify
affected CLI/SDK/Board/Flight consumers, root checks and committed-source clean CI.
Tighten accepted regression ceilings only with executed evidence. Completion
requires end-to-end improvements with preserved authority/recovery, not one cache
microbenchmark, a relaxed ceiling or faster polling.

Current behavior and measured limits belong in the
[performance reference](../reference/performance.md); executed checks belong in
the [proof ledger](../../tests/README.md). New measured mechanisms belong in their
public implementation owners and consolidated Internals account.
