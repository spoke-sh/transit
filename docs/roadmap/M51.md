# M51 — Typed configuration and SQL settings

Delivery of [#86](https://github.com/rupurt/rey/issues/86), before
[configured local database access](M52.md). Status: implementation complete,
qualification in progress. The [configuration reference](../reference/configuration.md)
and [SQL reference](../reference/sql/settings.md) own implemented behavior;
the [proof ledger](../../tests/README.md#typed-configuration-and-sql-settings)
records executed evidence and limits.

## Accepted scope

One shared typed registry supplies YAML/environment resolution, validation,
effective values, source attribution, change policy and generated reference
data. SQL exposes settings, catalog discovery, reload outcomes and session
overrides. Existing server/console invocations remain the user workflow.

There are no new CLI commands, flags or dot commands. Loading/reloading validates
the whole candidate; there is no separate config-check function or operation.
Configuration never grants access or restores revoked permissions.

## Implementation sequence

1. Define domain-owned descriptors and a bounded shared resolver. Select one YAML
   source, add TRANSIT_CONFIG/XDG discovery, retain typed nested environment
   precedence, and record effective/default/configured sources.
2. Separate immutable installation identity and artifact compatibility from
   mutable desired generations and per-component applied observations. Preserve
   explicit initialization, current-v1 rejection, native fencing and recovery.
3. Add action-bound, currently authorized settings inspection/reload/status
   operations. Protect secrets and source details. Persist exact accepted
   operations and preserve uncertainty across lost responses.
4. Validate and prepare whole candidates; publish one immutable generation per
   owner. Mark restart-required fields pending and report cross-owner partial
   outcomes explicitly. No reload automatically restarts or provisions services.
5. Extend shared SQL compilation and adapters for SHOW ALL, exact dotted keys,
   settings/reload-history relations and standalone transit_reload_conf().
   Catalog listings use current database/schema/Table authority and bounded pages.
6. Add session-owned SET/RESET within administrator ceilings. Preserve the wire
   adapters' fixed encoding/autocommit requirements and prepared-execution rules.
7. Qualify actual installed server/console and database clients; publish current
   usage, exact contracts, scientific mechanisms and executed proof evidence.

## Source and lifecycle decisions

Select existing --config, TRANSIT_CONFIG, project transit.yaml, XDG transit.yaml,
system /etc/transit/transit.yaml, then defaults. First match wins; invalid or
missing explicit sources fail. Remove home-root transit.yaml discovery. Pin the
selected filename, allowing atomic file replacement. A default-only startup
remembers its project filename for later creation. Losing an accepted source
never silently restores defaults.

Defaults precede YAML, startup environment and existing invocation overrides.
Session overrides are separately eligible. Reload cannot read a changed parent
shell's environment. Keys are canonical dotted names; environment nesting uses
double underscores. Unknown keys, duplicate keys and invalid effective
combinations fail with bounded source diagnostics.

Every key declares initialization-only, restart-required, reloadable,
new-session, session-settable or read-only behavior. Scope and change timing are
separate. A valid startup can apply restart-required configuration through the
existing server command. Immutable configuration and incompatible artifacts
remain rejected without data deletion or reset.

Reload returns an operation identity. History distinguishes acceptance,
application, pending restart and failure by owner. Preparation/EXPLAIN/status do
not dispatch; administrative execution is a standalone SQL operation. Native
current permissions remain independent of captured configuration generations.

## Acceptance and evidence

- Discovery, YAML bounds, typed overrides, source coordinates and redaction.
- Observable live, restart-required, new-session and session changes.
- Invalid candidate rejection without changing active settings.
- Exact retry, concurrent generation conflicts, interrupted application,
  local application/pending restart and retained accepted work after replacement.
- Current authorization for inspection, reload and paged disclosure, including
  revocation; startup never restores a revoked grant.
- Existing console access during malformed/pending topology edits.
- Real installed console and TLS PostgreSQL/MySQL workflows with no new CLI
  administration commands.
- Focused proofs, just check and committed-HEAD just ci-clean. Record executed
  evidence in tests/README.md; failed/incomplete proofs do not qualify delivery.

## Boundaries

M52 owns independently opt-in local PostgreSQL/MySQL listener activation and
provisioning. Persistent SQL configuration writes, role/database defaults,
transaction-local settings, includes, watchers and cluster-wide orchestration
are deferred. Board's inspection identity gains no administration rights.

## Ownership inventory

| Input owner | Configuration classification |
| --- | --- |
| Local server | Registered operator YAML: identity/native quotas are initialization-only; ports, artifacts, Board and application placement require restart; Host policy reloads; query defaults apply to new sessions |
| Native node and storage children | Generated private projections of installation identity, storage paths, quotas and artifact placement; no second mutable grant store |
| Query host | Generated placement and connection bindings; query-specific execution budgets remain their explicit query contracts |
| Board | Generated listener/private upstream binding; presentation and application definitions remain outside host settings |
| Standalone SQL gateway | Private deployment artifact with explicit account/ledger/TLS/budget bindings; optional settings service delegates to the local owner and does not infer a YAML source |
| Flight and serving | Explicit service bindings retain their owning machine contracts; query/serving administration does not acquire configuration rights |
| Console | Client connection/presentation preferences remain `.show`; host metadata/reload uses SQL and an explicit management binding |
| Launchers | Generate owning deployment artifacts; provider lifecycle and current native authority remain separate |

The first live application group is deliberately local: gateway Host policy and
session defaults share its atomic checkpoint. Every other registered service
field requires restart. No unimplemented remote applier is reported as applied.
RESET returns to a session's captured default; reload changes new-session defaults
and ceilings. This resolves the initial plan's ambiguity about an inherited
default changing underneath an existing session.
