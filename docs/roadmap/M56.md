The user selected a native SQL session API over HTTP/TLS during review. Retain
that direction alongside the PostgreSQL/MySQL adapters. The
[Quack comparison](../internals/service-interfaces.md#http-api-design-and-the-quack-comparison)
records primary sources and lessons for request cost, typed batches and logical
session lifetime. This selects the architecture, not a Quack dependency or
compatibility target.

Make multiple local or remote `transit console`, PostgreSQL and MySQL connections
ordinary sessions of one service-owned SQL runtime. Opening a console requires no access
to private installation files and holds no account-wide recovery lock. Accepted
operations remain recoverable after any connection disappears. A remote native
console needs an endpoint, account, database and authentication/trust settings;
it does not need server files, a filesystem mount or a tunnel. Local and remote
native access do not require either optional database-wire listener. Remote
native support is part of this delivery, not deferred follow-up work.

Deliver the complete selected foundation as one implementation PR with logical,
reviewable commits. The stages below are dependencies and review boundaries,
not separately enabled legacy/new session paths.

The first implementation preserves the existing console's supported catalog
reads, DDL/DML, inspection, settings, typed parameters and diagnostics. Explicit
KV/Document/source query configurations move to authorized service-owned source
bindings; clients select a binding instead of supplying private worker identities.
Explicit captured query execution continues through the existing durable job
owner, distinct from ordinary interactive SELECT. Inventory these modes before
removing their direct console implementations. Raw SDK and explicit low-level
client APIs remain independent interfaces, not console fallback paths.

The shared runtime must not narrow native logical types to the wire gateways'
scalar subset. Each adapter advertises and enforces its own representable profile
before opening a result stream or admitting a mutation. Existing PostgreSQL/MySQL
syntax restrictions can remain explicit while their supported operations move
to the common owner. This work adds no transactions, savepoints, COPY, continuous
queries, distributed SQL scheduler or new top-level CLI commands. Board and
Flight integration are later consumers, not prerequisites.

## Reviewed decisions

1. Host one SQL runtime registry in the supervised SQL service. One enrolled
   account has one active coordinator regardless of the adapter used to connect.
2. Define a network-accessible native SQL session protocol and shared Zig client,
   separate from the kernel native protocol. Use bounded HTTP over verified TLS
   for remote connections, with account SCRAM authentication. Both this transport
   and a local socket call the same session API and preserve the same semantics.
3. Provide automatic local connection through a private Unix-domain socket.
   Verify OS peer credentials and map the owning UID to a once-provisioned local
   login binding. No TLS or SQL password is needed for that local profile.
4. Discover that socket from conventional settings or a nonsecret per-instance
   rendezvous file in the user's runtime directory. Neither discovery nor login
   reads the installation record or a server signing key. Explicit selection
   always wins and fails visibly if its instance is unavailable.
5. Configure remote exposure explicitly, with independent native listener and
   TLS settings. Support endpoint/account/database selection using existing
   console connection files and additive connection options, not a new command.
   Reuse the SCRAM credential owner; explicit loopback trust is separately scoped.
   PostgreSQL/MySQL remain opt-in and are not dependencies of the native protocol.
6. Keep one active Table mutation per account initially, with durable bounded
   pending admission. Multiple sessions and concurrent reads do not imply
   parallel Table writes within an account.
7. Use an account-scoped admission token for native mutations and paged operation
   discovery after client-state loss. Do not require a client recovery file or
   automatically replay SQL after reconnect.

Socket directory selection must define an owner-checked fallback when
`XDG_RUNTIME_DIR` is absent, pathname bounds, instance disambiguation, stale
socket cleanup and explicit endpoint overrides. Remote/native transport details
are frozen in the first contract commit, before listener implementation.

## Implementation sequence

### 1. Freeze the neutral session and admission contracts

- Create the current-v1 SQL session contract and reflected Zig types before
  wiring adapters. Define version/definition negotiation, server instance,
  capability profile and structured errors.
- Specify authenticated session open/close, prepare/describe, parameter binding,
  execute, bounded fetch, cancel, operation status/discovery and exact resume.
  Freeze the bounded HTTP API, local-socket carriage and authentication transcript
  bindings. Bound messages, cells, handles and idle leases explicitly. Define
  TLS verification, private-CA references, session-token handling, credential
  rotation/revocation and rejection of credential-forwarding redirects.
- Distinguish logical sessions from HTTP connections. Define an execute request
  carrying SQL and parameters that can return schema plus an initial bounded
  batch or an accepted operation handle; do not require separate prepare/bind
  requests for every simple query. Keep durable admission before acknowledgement.
- Generate the HTTP endpoint description and typed schemas from the public
  contract. Reuse logical codecs without exposing private storage formats or
  requiring lossy JSON number/string conversion. Record which result encodings
  are supported, how they are negotiated and their byte/allocation bounds.
- Define endpoint, authenticated account and database/source selection separately
  from server-internal realm/resource/worker identities. Server capability
  discovery returns authorized metadata, never private keys. Retained operation
  identity includes the target instance so recovery cannot switch servers silently.
- Distinguish temporary session/statement IDs, admission tokens, durable
  operation IDs, native signed steps and captured-query IDs. Define reconnect,
  reset, service restart, stale handles and cross-session access rules.
- Give fetched batches an ordered cursor and bounded acknowledgement/retry
  policy. A lost response cannot silently skip rows or reopen a fresh snapshot;
  expired temporary state reports an incomplete result. Cancellation uses an
  independently admitted request so a stalled result stream cannot block it.
- Define native request-token equality over authenticated account/role, request
  content and binding context. Repeated identical admission returns the original
  operation; different content conflicts. Persist frozen compilation so retries
  cannot reinterpret schema changes. Define reservation, intent-ready and
  accepted-execution receipts separately.
- Record an executable capability matrix for the current console and both wire
  adapters, including types, settings, inspection, source profiles and errors.
  Specify the native logical result codec without round-tripping through a
  PostgreSQL/MySQL representation.

Gate: independent codec fixtures and state-transition tests cover invalid or
foreign definitions, conflicting token reuse and illegal lifecycle transitions.
Contract syntax under discussion is labeled proposed until it has an executor.

### 2. Extract the shared SQL runtime

- Introduce `packages/zig/transit-sql` as a real package with a manifest, public
  module and direct checks. Move neutral account/session/statement execution
  there from the gateway package and application; leave adapter-specific codecs,
  probes and protocol cycles with their adapters. Remove superseded ownership.
- Give Session, Statement and Result explicit allocator and I/O lifetimes.
  Domain transitions remain deterministic; socket tasks do not own durable state.
  The runtime composes Fuze, Query, Catalog and Station through package interfaces.
- Move source selection, logical result descriptions, settings capture and
  current authorization checks behind the shared API. Remove PostgreSQL-specific
  imports from neutral execution. Metadata preparation opens no data snapshot;
  execution acquires its own source basis.
- Register one AccountRuntime per enrolled account. Preserve fenced activations,
  exact ControlLane ownership and independently joined transports. Reject
  duplicate local registration and stale native ownership.
- Preserve console features absent from current gateway Statement, especially
  ALTER/DROP, catalog inspection, complete native types and explicit sources.
  Protocol restrictions stay in admission/capability checks rather than changing
  the common operation's meaning.

Gate: shared runtime tests exercise the same typed operations through native and
wire adapter harnesses; package dependency checks keep SQL outside the kernel.

### 3. Make admission and recovery independent of sessions

- Extend the paged account ledger with the durable token-to-operation mapping.
  Reserve count/content quota before acceptance; concurrent identical requests
  race to one binding. Complete intent publication precedes an accepted receipt.
- Keep the existing saved-step-before-dispatch, receipt-before-sequence-advance
  and processed-input-before-terminal-observation rules. Retain original signing
  identity, selected role and expected catalog/schema revisions.
- Return distinguishable rejected-before-admission, reserved/incomplete,
  accepted/pending, completed and unknown observations. A read failure does not
  establish absence. Status inspection does not dispatch; explicit resume and
  the recovery worker use only the original operation.
- Index settings reload and other existing administrative owners through typed
  operation references. Preserve their journals, generation checks and separate
  authorities; no synthetic cross-domain transaction or replay of SQL text.
- Provide account-scoped paged discovery and authorized detail. Recovery after
  losing a token may require selecting an operation; identical-looking SQL is
  never an automatic match. Do not expose another account's SQL, values or results.
- Keep wire executions' internally allocated identities. Sending SQL a second
  time through PostgreSQL/MySQL remains a new operation, including after timeout.

Gate: fault injection around reservation, publication, native dispatch, receipt
and terminal reply yields one original outcome. Restart and credential rotation
preserve exact recovery; quota pressure does not delete accepted history.

### 4. Implement session scheduling and bounded read execution

- Run independent session reads through service-owned Fuze tasks and authorized
  snapshots. Each HTTP/socket/native client object has one borrower. Join tasks
  before freeing their transport, result buffers, snapshots or spill.
  Bound compute batches and yield/check cancellation so CPU-heavy reads cannot
  monopolize the service executor despite separate socket admission slots.
- Bound total/per-account sessions, active queries, preparations, in-flight
  requests, session memory, output buffers, spill and wait deadlines. Preserve
  existing numeric bounds initially; document additional aggregate budgets.
- Retain short account ingress locks and one active Table operation per account;
  never hold them during terminal input, read execution or blocked output.
  Schedule accounts fairly within explicit active-work limits.
- Reserve separate capacity for cancellation, status, recovery and shutdown.
  Backpressure remains bounded and cannot retain an unbounded result or queue.
- Recheck current account, credential, selected role and object rights before
  preparation disclosure and each protected result batch, including LIMIT 0,
  cached metadata and terminal counts. Revocation clears protected buffered state.
- Close/reset/idle-expiry releases session state and cancels interactive reads.
  Accepted operations outlive the session. Cancellation invokes the relevant
  domain's rules and does not promise rollback of published work.
  Closing one HTTP connection does not close its logical session. Bound retained
  unacknowledged result data, require current authorization on fetch retries and
  release reads when their statement/session lease ends. A new logical session
  does not reopen an interrupted query's snapshot.

Gate: slow readers, query saturation and a stalled mutation leave another session
able to read and control its work within the configured admission bounds.

### 5. Implement the native network client and host all adapters

- Build a shared Zig native-session client with neutral wire codecs, explicit
  owned result buffers, deadlines, TLS/CA verification, SCRAM exchange and exact
  operation handles. Keep server runtime dependencies out of its public boundary.
  The console uses this client for both remote TCP/TLS and local socket transport.
- Reuse a bounded pool of HTTP connections with explicit ownership; preserve
  logical sessions across transport replacement. Prevent credential-bearing
  redirects, HTTP caching of protected results and blind replay of mutations.
  Bind requests to the owning server instance so routing cannot silently move
  a live session or operation to an independent service.
- Add the native TCP/TLS adapter and local socket transport to the existing
  supervised SQL service. All adapters obtain sessions from the same registry;
  no extra SQL service hop is required. Preserve the existing executable name
  unless the package split requires a separately reviewed artifact change.
- Implement the native authentication and request/result contracts from step 1,
  including exact logical cells, typed parameters and structured diagnostics.
  Bind credentials and handles to the intended server instance and account.
  Remote clients discover authorized capabilities and bindings from the service;
  they never receive worker credentials or need direct access to the node.
  This SQL endpoint is separate from the existing signed-native forwarding routes;
  do not weaken that gateway's identity-header rejection or native request budgets.
  Accept local peer identity from the socket itself, never a forwarded UID header.
- Adapt PostgreSQL/MySQL engines to the shared Session API. Preserve Parse/Bind/
  Execute/Sync write admission, prepared metadata, read-portal cuts, MySQL reset,
  cancellation authentication, scalar codecs and explicit unsupported operations.
- Keep native protocol health and SQL readiness distinct. Report readiness only
  after required account activation and the configured native listener are usable.
  Optional wire listeners report their own configured/ready/failed state.
- Drain admission, join sessions and retain uncertain work before service exit.
  After restart, stale session handles fail; durable operation handles still
  identify the original work under current access.

Gate: a native console in a separate network/filesystem environment connects over
TLS using only endpoint/account/database and client trust credentials, with both
wire listeners disabled. Native, psql and mysql also share one account concurrently,
including when a wire listener is disabled/re-enabled. Disabling admission does
not stop retained work.

### 6. Integrate automatic local startup and configuration

- Extend typed settings, environment overlays, schema generation, SHOW and reload
  classification for native socket/listener policy and session/work limits.
  Keep native service enablement separate from optional PostgreSQL/MySQL ports.
- Provision the default local peer account and binding once through the existing
  exact enrollment journal. Restart never recreates a revoked credential/grant.
  Disabled or removed accounts may retain recovery capacity without new admission.
  Native and wire logins selecting the same enrolled account reuse that account;
  adapters must not provision separate coordinators for it.
- Resolve local paths and rendezvous ownership independently of private data
  storage. Test multiple installations, stale discovery, same-name instances,
  absent runtime directory, occupied sockets and different OS users.
- Preserve automatic missing/empty installation initialization, require-existing
  policy, artifact hashes, storage markers, rollback detection and restart budgets.
  Configuration errors identify the actual socket/account/setting rather than a
  stale installation-record location.
- Update `transit.yaml.example` and default onboarding so two bare consoles work
  with both optional database ports disabled. An explicit remote connection needs
  only connection/authentication settings, never private server data files.

Gate: fresh initialization and ordinary restart expose the same intended local
connection, with permission revocation surviving restart and no silent fallback.

### 7. Switch the console to service-owned sessions

- Replace direct catalog/query/settings execution in ordinary `transit console`
  with the native session client. Remove its installation-record dependency,
  caller credential lock and mandatory mutation/reload recovery files.
- Make explicit remote endpoint/account/database settings override local
  discovery. Keep credentials in a prompt or private referenced file, outside
  URLs, shell history and diagnostic output. Network/identity failures never
  silently attach to a local instance. Verify a fresh client home directory.
- Keep terminal editing, history, formatting, timing, scripts, `-c`, parameter
  files, offline help and rc preference precedence. Remote metadata powers
  completion, inspection and schema assistance under current access.
- Preserve configured Table/KV/Document source semantics by selecting registered
  service bindings; reject obsolete console connection schemas clearly. Retain
  explicit durable jobs through their owning contract, with no legacy execution
  fallback in the interactive console.
- Make `.status`, `.resume` and `.cancel` operate on service operation identities.
  Preserve convenient use for the last known operation; offer paged discovery
  and explicit selection when no unique operation is known. Do not automatically
  replay a mutation during reconnect or execute anything from startup preferences.
- Distinguish local presentation timing from server execution/wait time, connection
  loss from query rejection, and incomplete rows from successful completion.

Gate: two unconfigured consoles can remain connected, alternate reads/writes and
keep independent SET values. Killing either leaves the other usable and exposes
the interrupted operation through authorized server-side discovery.

### 8. Cut over contracts, documentation and qualification together

- Replace the shared definition for incompatible stored/session/account semantics.
  Regenerate schemas, signing/storage fixtures, SDK binding resources and generated
  documentation. Missing/foreign definitions reject before execution; do not
  reinterpret old recovery files, maintain parallel console implementations or
  automatically delete an existing installation.
- Update public CLI, SQL, configuration, query and security references; component
  guides, contracts, component directory, quickstart, example configuration and
  actual client examples. Update Internals from proposed reasoning to the measured
  implemented mechanism and record its remaining limits.
- Add session/admission/recovery cases to the invariant inventory. Record exact

- Run the real integration/fault matrix below and compare one/multiple connections

  Include cold versus reused TLS connections, client/server request counts,

- Complete committed-HEAD clean qualification, inspect the final diff and submit
  one PR explaining the hard cutover, session behavior, evidence and limitations.

## Acceptance and fault matrix

| Scenario | Required observation |
| --- | --- |
| Two bare native consoles, wire ports disabled | Both connect; independent settings and reads; no credential/recovery lock |
| Remote native client with fresh home and no server filesystem | TLS login, capability discovery, reads/writes and recovery work with PostgreSQL/MySQL disabled |
| Untrusted CA, wrong hostname, wrong password, redirected endpoint | Reject before SQL admission; no forwarded credential or local fallback |
| Reused/replaced HTTP connection with a live session | Session settings remain; identity and current permissions are checked; expired handles fail |
| Lost fetch response and retried cursor | Original bounded batch or explicit interruption; no skipped rows or new source snapshot |
| HTTP intermediary retry/cache/routing behavior | No duplicate mutation, protected cached response or attachment to the wrong service instance |
| Native + PostgreSQL + MySQL, same enrolled account | One coordinator; operations retain identity; supported equivalent SQL agrees |
| Metadata/types/parameters | Native keeps its complete existing profile; adapter restrictions reject before admission/disclosure |
| Disconnect before/after admission reply | Token retry finds the original or establishes current absence; no duplicate dispatch |
| Conflicting token or changed schema on retry | Reject conflicting reuse; retain the original bound intent |
| SIGKILL console; SQL service restart after send | Other clients remain usable or reconnect; accepted work resumes exactly |
| Lost token and several similar commands | Paged authorized discovery; no automatic match by SQL text |
| Concurrent writes and reload | Coordinated domain ownership; no overwritten journal or shared sequence collision |
| Revocation/rotation during buffered output/recovery | Current access gates metadata/results; original signed step remains verifiable |
| Slow readers; session/read capacity full | Bounded memory/spill; explicit admission failure; control/recovery remains schedulable |
| Idle timeout, cancel, reset and shutdown | Read resources release; no cross-session cancellation; published writes are not undone |
| Many retained operations, small resident cache | Paged growth within deployment quota; no fixed total-cardinality array |
| Different local UID; spoofed account; stale socket | Deny or fail visibly without attaching to another installation |
| Disabled listener or account; current grants revoked | Stop new admission; preserve retained work and never restore grants on restart |
| Incompatible definition or old console recovery schema | Explicit rejection before mutation; no reset or fallback |

Use disk-backed Ursula and actual CLI/protocol clients for process and socket
failures. Deterministic state tests cover transition invariants separately from
physical recovery. Preserve existing raw caller/SDK recovery coverage.
