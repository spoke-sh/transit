# M52 — Configured local database access

Delivery of [#82](https://github.com/rupurt/rey/issues/82), after M49's authorization
and trusted access boundary and M51's configuration lifecycle. Status: implemented
and locally qualified. The [local SQL guide](../../apps/transit-cli/docs/sql.md)
owns the user workflow; the [executed proof record](../../tests/README.md#configured-local-sql-access--2026-10-17)
records the installed workflow, failure schedules and clean-checkout coverage.

PostgreSQL and MySQL are independently opt-in. With neither configured, the
server starts no SQL gateway and provisions no SQL-only credentials, accounts or
ledgers. Configuration selects exposure and private credential references;
ordinary startup never reapplies or restores grants.

## Delivery and acceptance

- Package the matching services and supervise configured dependencies.
- Expose actual connection details, TLS trust paths and readiness without secrets.
- Compose public role/catalog administration and explicit recoverable setup.
- Qualify neither, PostgreSQL-only, MySQL-only and both listener configurations.
- Exercise the installed owner/writer/reader workflow with both real CLIs.
- Preserve accepted operations and data when disabling a listener or replacing
  its worker; provide an explicit retained-operation recovery path.
- Test compatible-installation enablement, startup failure, occupied ports,
  credential rotation and stop/resume with current permissions.

This delivery replaces the current-v1 definition and rejects incompatible old
installations without deleting them.
No migration or legacy compatibility path is included. Existing-installation
enablement refers only to an installation already using the current compatible
definition. Local users explicitly initialize new state after their own reset.

Current user semantics live in the local server and gateway guides. Executed
installed proofs and qualification limits live in `tests/README.md`.

## Implementation sequence

1. Register independently nullable PostgreSQL and MySQL listeners, private account
   references, trust configuration and bounded gateway settings in the shared
   configuration registry. Listener changes require restart; reload validates and
   reports pending changes without opening a socket. Reject collisions with every
   other local listener before starting children.
2. Include the matching SQL gateway and its pinned TLS dependencies in the local
   bundle. Discover and fingerprint artifacts without starting a disabled service.
3. Extend the installation owner with recoverable account enrollment. Save exact
   signed requests before submission and receipts before advancement. Separate
   worker, ingress, control, coordinator, table and private-reader sequence owners.
   Publish reviewable inputs and profiles for the existing authorization and
   catalog commands; startup must not restore credentials or data grants.
4. Manage local TLS trust through the pinned TLS library or accept explicit PEM
   references. Derive a salted verifier from an explicit password file, never a
   shared default. Report public trust paths and connection coordinates without
   emitting credentials. Preserve the existing verifier rotation controls.
5. Supervise initialization separately from fresh activation and admission.
   Expose configured, awaiting-authorization, initialized and accepting states
   truthfully while retaining access to the core administration surfaces.
6. Keep ledger recovery independent of listener and TLS availability. Retain
   enrolled identities, original catalog bindings and accepted operations when
   an account or protocol is disabled. Drain and join connection tasks before
   stopping recovery workers; never reinterpret an uncertain operation as a
   fresh SQL submission.
7. Publish an installed-bundle walkthrough using ordinary role/catalog grants,
   verified TLS with `psql` and `mysql`, shared CRUD, rotation and recovery.
8. Qualify the installed workflow outside the checkout on disk-backed Ursula,
   then execute the repository checks against committed HEAD before opening the
   implementation PR. Record executed evidence separately from these intentions.

## Lifecycle acceptance matrix

| Retained enrollment | Configured listeners | Required behavior |
| --- | --- | --- |
| None | Neither | No SQL processes, ports, credentials or ledgers |
| None | PostgreSQL, MySQL or both | Recoverable setup; admission waits for current authority |
| Present | One or both | Fresh fenced runtime; only selected protocols accept connections |
| Present | Neither | No SQL listener; retained operations remain recoverable |
| Present, account removed or disabled | Any | Reject new login; preserve identity, bindings and recovery history |

Setup interruption, revoked grants, occupied ports, expired certificates and lost
responses must not erase accepted work or silently restore authority. Account
limits bound active work; they must not impose a fixed total lifetime account or
operation count. The installed tests must include current owner/writer/reader
permissions, Unicode and NULL values, compatible-installation enablement,
replacement fencing, disable/restart and exact uncertain-operation recovery.
