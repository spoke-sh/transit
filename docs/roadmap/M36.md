# M36 — Simulation and external fault verification

[Roadmap](README.md) · [Tracking issue #26](https://github.com/rupurt/rey/issues/26)

Status: In progress. The first slice adds generated multi-process authority and
delivery schedules to the existing verification foundation. The resource profile also adds numbered page I/O faults, captured-root checking
and checkpoint/trim recovery. Shared Session/courier schedules also exercise uncertain transport, activation
fencing and finite settlement/maintenance. Focused Document, Exchange, refresh
and runtime package schedules are implemented. The external supervisor and
installed Python/Node profiles are implemented; selected application/query/browser
qualification and the final clean/hosted gates are in progress. Executed results belong in the
[proof ledger](../../tests/README.md#authority-and-delivery-simulation).

## Scope and rationale

Explore interacting failures across publication, ownership, current policy,
delivery and recovery using real implementation code. Retain reproducible seeds
and concrete counterexamples, with an independent oracle and explicit progress
assumptions. This extends M10's verification foundation without reopening its
completed scope or changing execution/storage contracts.

Two complementary methods address different gaps:

- Deterministic simulation substitutes controlled scheduling, time and I/O around
  production logic. Same-build replay makes failures inspectable and reducible.
- Vortex-style external testing drives real compiled binaries and public clients
  against disk Ursula, observing process and network faults outside those binaries.
  A seeded workload does not make operating-system scheduling deterministic.

The [public verification account](../internals/verification-method.md) owns the
mechanism and evidence boundaries. Issue #26 records the component matrix,
motivation and primary TigerBeetle references.

## Delivery sequence

1. Add a named authority/delivery simulator with two producer PIDs, replaceable
   workers, one destination and bounded delayed decisions. Preserve live caches,
   compare independently recovered state, and distinguish append refusal from
   acceptance with a lost reply. Check route order, original provenance, exact
   retries, permission changes and retirement. End generated traces with an
   explicit bounded schedule for eligible work.
2. Extend page-store faults, immutable publication, resource views, checkpoints,
   trusted time and maintenance. Preserve atomic conditional append as a modeled
   storage premise until a separately qualified lower-level model exists.
3. Schedule real shared client/framework state machines through controlled
   transports. Add focused Document convergence, connector uncertainty and
   query/reactive lifetime oracles.
4. Add an external supervisor over actual node, workers, courier and disk Ursula.
   Reuse owned fixtures and inject request/response loss/delay, connection failure,
   process kill/pause and restart against current history. Preserve exact signed
   identities and distinguish requested fault times from observed execution.
5. Add installed SDK drivers for host scheduling, disposal and cancellation;
   qualify selected service/browser/provider combinations independently.

The first slice has no automatic worker scheduler, HTTP transport, application
handler, finite clock/lifetime, resource mutation, page fault or physical provider
model. Its progress result is conditional on its finite explicit schedule and
available storage/permissions; it is not a general liveness theorem. External
testing retains reference placement, actual disk and host ownership proofs.

## Acceptance and evidence

- [x] Saved and generated multi-process traces match an independent logical
  projection and cold recovery; replay produces identical results.
- [x] Evidence binds source revision/dirty status, compiler/binary/oracle identity,
  generator configuration and concrete traces. Incomplete runs never pass.
- [x] Bounded minimization and compiling production-code mutations demonstrate
  route/provenance detection; errors/timeouts do not count as detections.
- [x] Eligible work drains under the explicit finite schedule after faults stop;
  retirement remains terminal. Automatic scheduling needs separate evidence.
- [x] Add page staging/read/publication faults, captured resource roots and
  interrupted prefix trimming with independent state/input/output checks.
- [x] Add shared Session/courier scheduling, finite settlement, clock refusal and
  maintenance-driven expiry with independent input/output conservation checks.
- [ ] Add focused Document, effect, query/reactive and runtime/application oracles.
- [x] External real-binary tests retain operation histories, binary/topology/fault
  evidence and reliable cleanup, and exercise installed SDK drivers.
- [ ] Ordinary regression and scheduled discovery tasks have explicit ownership;
  local timings and hosted cost evidence are recorded separately.

No protocol cutover, storage migration, authority partitioning, trading policy,
universal exactly-once remote effect or hardware performance target is introduced.
