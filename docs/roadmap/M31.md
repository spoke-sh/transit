# M31 — Protocol consolidation and v1 hard cutover

[Roadmap](README.md)

Status: **In progress**. Follows [interactive queries M30](M30.md) and precedes
[publication M33](M33.md). The accepted
[public versioning policy](../reference/versioning.md) requires one current v1
definition per Transit-owned protocol before 1.0. This milestone removes the
existing parallel implementations and qualifies the replacement.

## Baseline and owners

At the start of this work, the native bounded v2 authority/client and growing
v3 authority/client coexisted.
The growing implementation supplies the latest durable collection foundation.
Table query v1 and unified query v2 also coexisted; Flight/reactive consumers
used the earlier Table interface. Installation declarations, local configuration,
page storage and SDK operations have additional format generations. Renumbering
wire constants alone does not consolidate any of these implementations.

| Boundary | Required cutover |
| --- | --- |
| Native protocol, core and Ursula backend | Keep the growing authority foundation as v1; remove bounded authority/storage implementations, old envelopes, signatures, routes and schema generators |
| Public client and Station | One session/turn/behavior implementation; migrate required consumers and remove legacy exports and host operations |
| Board, runtime controllers and launchers | Replace remaining bounded-profile dependencies through public client operations; preserve inspection scope, lifecycle and recovery gates |
| Fuze, query and consumers | One current plan/source/result definition named v1; migrate Table-only consumers, Flight/reactive paths, CLI and Board without dropping required result/authority checks |
| Installation, configuration and saved operations | One current definition per format; reject incompatible artifacts and preserve their original recovery material |
| Bindings and SDKs | Regenerate neutral declarations and fixtures; update all installed language consumers together |
| Documentation and qualification | Remove superseded current contracts/examples/navigation; re-execute proof against the replacement and retain historical evidence as history |

## Implementation checkpoint — 2026-09-30

The workspace has one native v1 authority/client path, ported runtime and Station
supervision, current-only native routes and schemas, definition-bound signatures,
persisted requests/installation fencing, and coordinated Board/Flight/SDK changes.
The [current proof ledger](../../tests/README.md#native-v1-cutover-checkpoint--2026-09-30)
records executed schedules and remaining gaps. This is a branchable implementation
checkpoint, not completion of the exit criteria. Final query recovery/browser,
installed-language, placement, documentation inventory and clean-HEAD qualification
remain outstanding; do not infer a release-ready cutover from the commit alone.

## Compatibility and data boundary

Match the latest implemented semantics for each interface. Preserve required
authority/readiness/recovery behavior when moving a consumer; missing growing
runtime operations are implementation work, not permission to silently remove
fencing or use provider state as authority. Separate upstream formats and
application-owned revisions from Transit protocol generations.

Define an enforceable compatibility discriminator for incompatible definitions
that share v1. Changing only version labels cannot reject all old requests or
stored artifacts. No fallback routes, negotiation to an older implementation or
automatic migration remain. Incompatible retained histories and pending requests
must fail before execution, with original bytes preserved and an explicit operator
procedure. A hard cutover does not authorize deleting an existing installation.

## Exit criteria

- [x] Record the policy in AGENTS.md and the public handbook, including upstream
  exclusions, matched-build requirements and accepted-work preservation.
- [x] Inventory every owned version discriminator and its implementation/consumer
  dependencies, including formats already called v1 with incompatible old shapes.
- [x] Replace native bounded/growing branches with the latest v1 authority,
  storage, client, Station, inspection and runtime paths; remove legacy code.
- [x] Consolidate query and dependent Flight/reactive/Board/CLI consumers on the
  latest v1 contracts; remove earlier codecs, plans, routes and profiles.
- [x] Consolidate installation/configuration, saved requests and all host/SDK
  surfaces; regenerate schemas, declarations, fixtures and independent consumers.
- [ ] Prove rejection of incompatible peers, signatures, histories, checkpoints,
  saved requests and installation artifacts without mutation, disclosure or reset.
- [ ] Run current authority, recovery, scope, finite-memory and exact-retry proofs
  against v1; retain useful forbidden-outcome cases from the removed profiles.
- [x] Public documentation, exact contracts, examples and generated descriptions
  show only the current supported implementation. Historical records remain dated.
- [ ] Run `just check`, relevant focused/integration and installed-SDK proofs,
  then `just ci-clean` against committed HEAD before pushing. Record actual
  execution and limitations in the proof ledger; skipped checks do not pass.

Publication depends on completing this cutover. The milestone does not establish
post-1.0 compatibility commitments, automatic data conversion or clustered
authority movement; [M34](M34.md) retains the latter qualification.
