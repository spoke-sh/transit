# M49 — Declarative authorization

Implementation of [#83](https://github.com/rupurt/rey/issues/83), following the
reviewed native-authority and trusted Table-mediation plan. Status: implementation
in progress; no new authorization capability is qualified by this plan.

## Scope and decisions

- One paged durable role, membership, object and grant model in native authority.
  SQL and framework services use public typed operations; the kernel remains
  independent of SQL syntax, Table layouts and application handlers.
- Named LOGIN/NOLOGIN roles, credential bindings, inherited/selected roles,
  object ownership, delegated grants, RESTRICT/CASCADE and default privileges.
- Database/catalog and schema/Table identities remain distinct from the backing
  resource and its fenced writer. Grants bind stable IDs, never reusable names.
- Restricted Table users use a trusted server-side access boundary and receive
  no backing-resource read capability. Native raw-resource access is a separate
  explicitly privileged capability, not Table-level authorization.
- Current authority gates metadata, preparation, execution, result disclosure,
  mutation publication and recovery. Revocation never means rollback of a
  committed operation; independent grant paths remain independently effective.
- Mandatory current-v1 hard cutover. The user will explicitly remove their old
  local installation before fresh initialization. No automatic reset, converter,
  legacy policy profile or fallback decoder is part of this work.
