# M49 — Declarative authorization

Implementation of [#83](https://github.com/rupurt/rey/issues/83), following the
reviewed native-authority and trusted Table-mediation plan. Status: implementation
delivered. Qualification is scoped to the [proof ledger](../../tests/README.md)
and the committed-source results reported with the pull request. Complete SQL
wire and clean-checkout gates must pass before issue closure.

## Scope and decisions

- One paged durable role, membership, object and grant model in native authority.
  SQL and framework services use public typed operations; the kernel remains
  independent of SQL syntax, Table layouts and application handlers.
- Named LOGIN/NOLOGIN roles, credential bindings, ADMIN/INHERIT/SET membership,
  logical ownership, delegated grants, RESTRICT/CASCADE and future-only defaults.
  Stable database/schema/Table identities remain distinct from backing resources
  and fenced writer PIDs. Names never supply durable authority.
- Restricted Table users use a trusted server-side access boundary and receive
  no backing-resource read capability. Direct raw-resource access remains an
  explicitly privileged infrastructure profile with its own native grants.
- Current authority gates metadata, preparation, execution, result disclosure,
  mutation publication and recovery. Revocation preserves committed outcomes and
  independently supported grants; it does not mean rollback or external recall.
- Original signed subjects bind caller, selected role, credential epoch, query
  and recipient. Saved work retains its exact identity through worker, service,
  credential and physical-store replacement. Recovery never silently re-signs
  accepted work under new authority.
- Mandatory current-v1 hard cutover. The user explicitly removes the old local
  installation before fresh initialization. There is no automatic reset,
  converter, parallel policy profile or fallback decoder.

## Qualification and submission gates

The [proof ledger](../../tests/README.md) retains actual commands, definitions,
executable hashes where captured, failures and scope limits. It includes both
successful focused runs and the SQL wire attempt whose large accepted write
outlived the operator-observation budget. A larger observation budget alone is
not qualification. The complete replacement preflight passes at its recorded
revision, including the original accepted write and both real CLI workflows; the
final clean growth lane must independently pass the entire task.
The SQL command deadline, original operation identity and one-attempt schedule
remain unchanged.

The ordinary inventory includes native administration, CLI/ABI/host changesets,
restricted Table isolation and all installed restricted SDKs. Before submission,
run `just check` and `just ci-clean` against committed source. All ordinary
lanes at the same revision are required when using lane-scoped clean runs. Report
unfinished or failed tasks explicitly; local evidence does not claim execution
of Compose/Substrate placement or every external fault/capacity profile.

Current user semantics live in [security](../reference/security.md),
[SQL](../reference/sql.md), the [Table service guide](../../apps/transit-table-service/README.md),
[administration CLI guide](../../apps/transit-cli/docs/authorization.md),
[native contract](../../contracts/AUTHORIZATION_V1.md) and their component owners.
The [execution model](../internals/execution-model.md) explains authority,
publication ordering, recovery and trust assumptions. Historical progress and
qualification accounts are not required to discover the current interfaces.

## Exclusions and next delivery

Row/column policies, general ABAC, identity federation, security-definer routines,
new SQL transaction semantics and per-viewer Board login are excluded. Flight's
explicit infrastructure-reader profile is separate from restricted Table-service
isolation. This work does not claim general PostgreSQL/MySQL system-catalog or
administrative-syntax compatibility.

[M52](M52.md) / [#82](https://github.com/rupurt/rey/issues/82) composes these
contracts into optional configured local PostgreSQL/MySQL listeners. Neither
listener starts or provisions SQL-only dependencies when unconfigured. Startup
observes retained authorization rather than recreating grants. This delivery
remains separate from the wire implementation already provided by M42.
