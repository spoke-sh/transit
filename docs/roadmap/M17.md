# M17 — Documents and collaborative text

[Roadmap](README.md)

Status: Complete for the declared growing profile on Linux x86_64; selected after [gRPC M16](M16.md),
building directly on
[bounded publication M14](M14.md), [Station M9](M9.md), [state resources](../history/STATE.md),
[idiomatic SDKs M11](M11.md) and the first [Fuze](../history/FUZE.md) Table execution profile.

Scope: a Zig-native Station Document abstraction for **both structured state and
collaborative text**, backed by accepted durable changes and recoverable
checkpoints. [Unified queries M18](M18.md) separately adds KV/Document adapters
and the wider query/schema/request contract; no query obligation is dropped.
Station owns mutation and CRDT semantics; Transit remains the authority for
acceptance, ownership, permissions and lifetimes.

## Connector handoff

M15/M16 now provide executed finite publication, authenticated reply routing,
current-policy replay, same-PID recovery and local/Compose/reference placement.
M17 reuses Publication and the operator topology, without depending on transport
adapters, RPC status or Exchange attempt semantics. SDK ownership and Board's
source-bound metadata patterns remain useful; their connector proofs do not prove
Document convergence or atomic index publication.

The selected model and paged materialization direction are in
[Documents](../history/DOCUMENTS.md#selected-m17-model-and-merge-rules). The first code step
is an immutable ordered index over Publication so accepted data and causal history
can grow independently of resident buffers. It adds no kernel storage primitive.
The [Document package](../../packages/zig/transit-station-document/README.md) now
implements canonical changes, structured/text merge, bounded reads and recoverable
private-turn publication jobs and incremental checkpoints. Component tests preserve
old snapshots, reconstruct accepted tails and qualify three-mutation final acceptance.
The disk proof now qualifies worker/node/store loss, exact retries, current-policy
reads and bounded cleanup with one resident authority page. All ten M11 SDKs pass
the installed change/read recovery schedule. The real two-client local proof
qualifies remote admission, original replies and worker/node/store recovery.
Board API/browser and isolated Compose/reference placement also pass. See [executed evidence](../../tests/README.md#m17-qualification).
At this handoff, serving and clustering remained for the later system review;
the [roadmap](README.md) now scopes that work in M19–M35 without expanding M17's proof.

## Entry gates

Complete the foundational design in [Documents](../history/DOCUMENTS.md) before fixing the public API.
Record the choices and their proof obligations there; this milestone selects the
work, not a CRDT algorithm, storage encoding or compatibility promise.

| Gate | Required decision / evidence |
| --- | --- |
| Document model | Fix document/resource identity, schema/type and change-format versions, nested map/list/scalar operations, replaceable strings versus editable text, Unicode indexing and conflict visibility |
| Merge semantics | Select and qualify Zig-native CRDT algorithms for the supported operations; define replica/operation identities, causal dependencies, concurrent set/delete/edit behavior, atomic change boundaries and explicit resolution |
| Acceptance and security | Separate tentative replica edits from accepted history; specify current authorization, a fenced writer, duplicate/conflicting operation handling, rejected dependencies and bounded pending work |
| Storage and capacity | Specify a useful bounded document/text profile, operation/checkpoint/result budgets and atomic publication; prove the chosen layout fits or define a versioned storage extension with recovery and reclamation tests |
| Retention and resynchronization | Preserve causal/deletion evidence needed by supported merges; define opted-in replica merge windows, stale-replica resynchronization, permanent retirement and separate physical cleanup |
| Query handoff | Publish bounded accepted-state reads with exact Document/type/change revisions and explicit missing/null/type-error/conflict states; M18 owns Fuze/Arrow projections and query syntax |
| Bindings | Extend M9's shared contracts and M11's public SDKs across all language targets, preserving operation identities, Unicode semantics and asynchronous ownership |

M14 provides immutable publication, not a CRDT, a materialized index or a
checkpoint/causal-retention policy. Reuse its segment/descriptor/cleanup and
source-bound read interfaces, plus connector-qualified reference/availability
patterns where applicable. Document operations have no dependency on live
HTTP/gRPC or on the connectors' protocol adapters.

The current 256-byte KV values and bounded per-turn mutation count do not imply
that a complete Document change and all index/causal metadata fit. Qualify the
complete example, including framework and causal metadata. If a larger
prerequisite is necessary, insert and renumber a
milestone under the [sequencing rule](README.md#maintaining-the-sequence) before
claiming support. Do not silently raise limits or put authoritative state in a
worker-local file or a second database.

## Implementation sequence

1. Specify the model, acceptance boundary, storage profile and retention contract;
   establish shared operation/merge/read fixtures and capacity measurements. Review
   the M15/M16 handoff using their executed evidence before fixing the API.
2. Implement durable Document changes, materialization and checkpoints, keeping
   accepted mutation, input progress and outputs under one visibility decision.
3. Implement concurrent structured edits and plain-text collaboration, including
   duplicate/dependency handling, explicit conflicts and replica resynchronization.
4. Qualify bounded accepted-state reads and versioned change/checkpoint references
   for M18. Keep Document mutation/merge semantics in Station, outside Fuze.
5. Complete language adapters, runnable examples, Board metadata, instrumentation
   and local/Compose/reference recovery proofs.

## Exit criteria

- [x] Publish versioned Document descriptors and change/read contracts, including
  stable document and replica identities distinct from Transit PID/activation.
  Create, associate, read, change and retire Documents through supported public
  interfaces and current resource/service policy.
- [x] Support nested maps, lists and scalar fields plus collaborative plain text.
  Distinguish replacement from sequence editing; define Unicode positions, stable
  element identities, nested deletion and concurrent field-conflict behavior.
- [x] Keep tentative local edits distinguishable from durable acceptance. Route
  changes through the fenced writer; CRDT mergeability cannot grant permission,
  authorize an effect or revive an expired resource/process.
- [x] Prove convergence for the same accepted change set under supported causal
  delivery permutations and duplicates. Exercise concurrent edits, delete/edit
  races, explicit conflict resolution, missing/rejected dependencies and reuse
  of an operation identity with different content.
- [x] Commit each accepted change's state, input progress and outputs atomically
  within the declared resource boundary. Reject oversize work before publication;
  recover uncertain acknowledgements without duplicate changes or partial state.
- [x] Recover documents, text and merge/conflict metadata from checkpoint plus
  retained tail. Inject worker/node failure during publication and compaction;
  prove unpublished chunks remain invisible and reclaimable if staging is used.
- [x] Demonstrate unlimited retention by default and explicit finite policies.
  Bound live/pending work without treating capacity pressure as expiry. Preserve
  the checkpoint, tombstone and causal evidence needed by accepted dependencies.
- [x] Reject stale replicas beyond an opted-in merge window and provide an
  authorized resynchronization path without blindly replaying old edits. Test
  delayed operations after trim, document retirement and PID replacement; no
  resurrection or implicit lifetime extension through a replica/checkpoint.
- [x] Publish the accepted-state read contract consumed by M18: exact source/type/
  change-format identity, bounded path/list/text reads and explicit missing, null,
  type-error and conflict outcomes. No speculative state leaks into reads; source
  loss, revocation and resource retirement remain explicit.
- [x] Extend every M11 public SDK with Document changes/reads. Run shared
  change/Unicode/read fixtures and cross-language round trips;
  bindings reuse the Zig semantics rather than implementing independent CRDTs.
- [x] Ship a non-trading example with two independently editing clients making
  structured and text changes. Exercise temporary disconnection, duplicate and
  reordered submissions, restart and resynchronization using Zig reference callers.
  Provide runnable local/Compose/reference tasks and retained proof evidence.
- [x] Add Board views for Document identity, source revision, merge/profile
  versions, conflict metadata and retained-history gaps, with current permissions
  and provenance. Keep application document/text values out of Board interpretation.
  Add bounded service signals and document configuration/recovery beside the code.

## Outside this milestone

Rich-text formatting/editor integration, a browser/offline SDK, compatibility with
a particular external CRDT format, indefinite offline merge after opted-in expiry,
full-text indexing, automatic schema migration, continuous materialized queries,
cross-resource joins/transactions and distributed query execution are separate
scope. The collaborative proof does not require a browser editor or a new external
connector. The SQL compiler and public Table query path were qualified in M12/M13.
KV/Document Fuze adapters, nested Arrow query types, wider request framing,
query SDK extensions and source/optimizer equivalence belong to [M18](M18.md).
Flight/ADBC remain [M22](M22.md); their first profile stays Table-only
until additional source/protocol combinations are explicitly qualified.

## Component handoff

Use M14 publication for immutable change/checkpoint material, keeping domain
validation and one visible Document head under a final accepted turn. An index
built over many turns needs its own validated publication root; writing a body
record does not automatically make all materialized state atomic. Budget each
operation and persist continuations instead of materializing the entire document.

Use same-PID fresh ownership for worker recovery. A new PID/resource requires
an explicit bootstrap/migration or new-Document decision; a replica, name or old
checkpoint cannot reopen retired authority. Causal deletion evidence and opted-in
merge-window floors are Document obligations, not consequences of byte cleanup.

M18 receives a versioned bounded reader and conformance fixtures. It must not
reimplement CRDT merging or decode speculative changes during query execution.
