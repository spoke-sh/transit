# D10 — Atlas D1–D8 in monochrome

Previous: [D9 — Implemented atlas and workspace](D9.md) · [Review index](README.md)

Status: **In review**. Implementation: **Design redraws, not implemented UI**.
The user selected vector wireframes for every D1–D8 figure as the material for
finalizing implementation. D9 remains the bounded implemented baseline. No earlier
open interaction, metric or scale question is accepted by this translation.

## Question

Do the Atlas's process fabric, resource architecture, semantic zoom and
workspaces remain clear when labels, geometry and line styles carry the meaning
without the original material rendering or color?

## Proposal

Use the monochrome vocabulary of [Console D5](../board-console/STRUCTURE.md)
and [Board grammar D1](../board-grammar/D1.md). Preserve separate inbox/outbox
geometry, stable backing-resource identity and explicit evidence. Draw selection
with a strong perimeter, associations with labeled dashed edges, and dependency
steps with solid arrows. Age uses wall marks and exact text; a missing time basis
still means **Age unavailable** in a real implementation.

Redraw all **34 figures** one-to-one. The old PNGs and recorded outcomes stay
unchanged. These are semantic translations into vector review plates, not traced
raster geometry. Simplified contour/building detail gives labels room; shapes
remain schematic rather than calibrated measurements. The common Transit header
adopts the later Console direction. D1–D3 retain a contextual navigation rail;
D4–D8 retain the spacious atlas canvas under the header. Final shell integration
belongs to Board grammar.

## Review outcome

The user chose **redraw all figures as monochrome vector wireframes**. That
choice establishes the comparison format and intended aesthetic. The 34 redraws
are now available to finalize the implementation direction; their detailed
geometry and unresolved alternatives have not yet been accepted. The selected
D2 Figure 7, D5 architecture and D6 Figures 1/4 remain the prior visual baseline.

## Open questions

- Are well-wall marks plus exact age sufficient without material shading?
- Which density and contour detail should survive at each projected size?
- Should Auto emphasis and one venue layout be selected, or should the first
  implementation retain explicit emphasis and an ordinary participation list?
- Which original framing details should carry into the shared Console shell?

## Evidence and limits

Every original figure is mapped exactly once in the inventory. D1–D8's existing
synthetic fixtures supply counts, sample rows and intended invariants; geometry
is schematic and not a calibrated chart. Old source limitations describe the
original review context. [D9](D9.md) and current component documentation own the
implemented baseline; this redraw does not reassert an old implementation limit
as today's status.

The [M23 inventory](../../roadmap/M23.md#design-to-implementation-inventory)
scopes the new UI and its missing public metric, aggregate, reactive and
administrative contracts. No generated screenshot proves those APIs, timestamps,
resource byte totals, scale, authorization, motion or keyboard behavior.

These SVGs use only black and white, with a hatch for explicitly unknown coverage.
The 1440 × 960 plates are desktop review compositions. A production responsive,
accessible renderer and reduced-motion interactions require real M23 browser
qualification; scaling down an SVG is not that proof.
