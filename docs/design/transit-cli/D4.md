# D4 — Responsive completion menus

[Review index](README.md) · [Previous: D3](D3.md) · [Next: D5](D5.md)

Status: **Accepted and implemented**. Implementation and executed checks are recorded in the
[proof ledger](../../../tests/README.md#responsive-console-completion-menus--2026-10-24). The public
[terminal guide](../../../apps/transit-cli/docs/console.md#terminal-editing-and-history)
owns current behavior.

## Question

How can completion stay responsive when typing narrows an open list, without
replacing it with a loading message or accepting stale metadata?

## Proposal

Refine [D3](D3.md)'s completion interaction. Open immediately on Tab and show
real suggestions as soon as available. Show no loading placeholder during
opening, refinement or acceptance validation. Keep an idle list stable.

While editing the same token, filter the disclosed candidates immediately and
fetch fresh suggestions in the background. Preserve the selected candidate by
spelling and kind when it still matches. Hide unrelated candidates when context
changes. An empty filtered shortlist cannot establish that no matches exist.

Keep one in-flight request and the latest draft, coalescing intervening edits.
Retained candidates are a presentation preview; insertion still requires the
current request and fresh metadata/authorization checks. Repeated Tab/Enter
during refresh does not queue acceptance.

## Review outcome

Accepted: no loading placeholders, immediate opening and filtering, quiet
background refresh, stable selection and current-evidence insertion. An opening
delay was considered and dropped in favor of displaying real results immediately.
This supersedes D3's loading message and unconditional selection invalidation
during same-token editing. There are no open interaction decisions for this fix.

## Evidence and limits

The [editing fixtures](../../../tests/console_editing.py) use a real PTY and a
controlled metadata peer. Shared assistance units cover lexical boundaries,
suffixes and identifier spelling. These checks establish editor behavior, not
new service authorization guarantees or a production latency target.
