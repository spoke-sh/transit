# D3 — Completion, history and draft editing

[Review index](README.md) · [Previous: D2](D2.md) · [Next: D4](D4.md)

Status: **Accepted and implemented**. The review began at source revision
`20df3ac4`; implementation and local qualification are recorded in the
[proof ledger](../../../tests/README.md#console-completion-and-editing--2026-10-24).
Manual terminal/SSH key delivery remains unverified. The observations below
describe the starting revision; the public terminal guide owns current behavior.
[D4](D4.md) supersedes the loading presentation and same-token selection reset.

## Question

How should a person compose SQL and dot commands with grammar/catalog completion,
search previous commands, correct edits and clear the prompt without confusing
text editing with statement execution?

## Proposal

Build on [D2](D2.md)'s explicit-submit console and the current multiline editor.
Use **Tab for completion in the draft and acceptance in history search**.
Use **Esc to return to an empty prompt** from any editing state. Provide
**Ctrl-G to dismiss a menu or leave history search while keeping the draft**.
Make undo cover ordinary edits, including clearing the draft.

The accepted default is to open completion with Tab. While that menu is open,
typing refines its candidates. Typing with the menu closed does not open it.
Completion offers continuations admitted by the current SQL profile and
authorized catalog metadata; history offers previously submitted text. Neither
action submits a statement.

### What the implementation established at review time

| Area | Observed behavior at the source revision | Design implication |
| --- | --- | --- |
| Tab | Calls `accept()`, which requests assistance if none is open | Completion is partly present, but its discovery and presentation need work |
| Ctrl-Space | The editor handles the NUL byte as a completion request | The key has an implementation; this review has not established why the user's terminal fails to deliver or expose it |
| Ctrl-Z | Restores one completion replacement; ordinary insertion/deletion clears that undo slot | The help's general-undo wording exceeds the implementation |
| Esc | Dismisses completion; exits history search by restoring the saved draft | It does not implement the requested clear-to-empty behavior |
| Up/Down | Always recalls history outside completion | A multiline draft needs vertical cursor movement as well |
| Assistance | Production parsers supply grammar expectations; Table assistance looks up authorized schemas, aliases and types | Extend the shared owners rather than add a console SQL parser or static keyword list |
| Candidate bounds | Builders retain at most eight candidates, with no explicit truncation/coverage indicator | One returned candidate does not establish uniqueness; eight returned candidates do not establish an exhaustive list |
| Metadata I/O | Request and acceptance refresh run synchronously; pending input can invalidate the response afterward | Keep that stale-response protection while making editing responsive during acquisition |

The settings assistance owner also exists, but the native SQL session's current
`assist` dispatch selects source or Table assistance. Settings-name support must
be wired and verified through this actual console route before advertising it.

## Visual studies

These monochrome wireframes use synthetic catalog and history entries. `|`
marks the cursor and `>` marks the selected candidate; neither is SQL input.
Prompt and continuation text keep the implemented multiline alignment.

### Figure 1 — Completion belongs below the draft

```text
transit> SELECT *
    ...> FROM it|

  > items          table
    item_events    table
  Tab/Enter accept   Up/Down select   Ctrl-G dismiss   Esc clear
```

The prompt remains stable. The menu does not replace the prompt or insert
candidate text while the selection moves. The selected item can show its full
name and a short type/source detail without exposing row values.

After Tab accepts the first candidate:

```text
transit> SELECT *
    ...> FROM "items"|
```

The menu closes, and the cursor follows the inserted identifier. The statement
has not executed. The quoted spelling illustrates the shared owner's current
identifier quoting; the terminal must not independently change those rules.

### Figure 2 — Completion understands the cursor and the suffix

```text
transit> SELECT i.va| FROM items AS i;

  > value          BIGINT · i
  Tab/Enter accept   Ctrl-G dismiss   Esc clear
```

The source declared after the cursor supplies scope. Acceptance replaces only
the selected token, preserving `i.`, the later `FROM`, the semicolon and all
other text. An ambiguous unqualified column appears with a valid qualifier.
Without a known source, the menu supplies supported grammar and functions;
it does not guess columns by inspecting unrelated tables.

### Figure 3 — History search has its own query and preview

```text
history> items|

  SELECT id, value
  FROM items
  WHERE id = 42;

  Tab/Enter edit   Up/Down older/newer   Ctrl-G return   Esc clear
```

The preview is the saved command, including its line breaks. Search text and
preview remain separate from the saved original draft. Tab loads the preview
into the editor and closes search. The next Tab then invokes SQL completion.
Enter also accepts a match for editing; a later Enter is needed to submit it.

### Figure 4 — Clear and undo are explicit

```text
transit> SELECT *
    ...> FROM items|

[Esc]

transit> |

[Ctrl-Z]

transit> SELECT *
    ...> FROM items|
```

One Esc clears the entire unsubmitted draft and all temporary assistance.
Undo restores that draft and cursor, without restoring a stale completion menu.
Esc in history search clears the saved original draft, search query and preview;
undo restores the original draft, never an unaccepted history preview.

## Interaction details

### States and key precedence

The editor has three visible modes: **draft**, **completion**, and **history
search**. Completion can be loading, showing candidates, or showing a short
unavailable/no-match status. History browsing with Up/Down is a draft preview,
not a fourth search mode. Executing a statement is outside these editing modes.

| Key | Draft | Completion | History search |
| --- | --- | --- | --- |
| Tab | Request suggestions; insert one only when uniqueness is established | Accept the selected candidate and close; while loading, do not queue acceptance | Load the selected match into the draft and close search |
| Enter | Submit eligible complete SQL/dot commands; otherwise insert a newline at the cursor | Accept the selected candidate without submission; if none is ready, dismiss without submission | Accept the selected match without submission; no match leaves search open |
| Up / Down | Move vertically; at the first/last display row, browse older/newer history | Move selection; scroll the visible candidate window as needed | Older/newer matching command |
| Shift-Tab | Open completion, without insertion | Select the previous candidate | No change |
| Ctrl-R | Save the draft and start reverse search | Dismiss completion and start reverse search | Select the next older match |
| Esc | Clear the entire draft | Clear the entire draft and menu; invalidate pending responses | Clear search, preview and saved draft; return to an empty prompt |
| Ctrl-G | No change | Dismiss the menu and keep the draft/cursor | Cancel search and restore the original draft/cursor |
| Ctrl-C | Clear the draft | Clear draft/menu and invalidate pending responses | Clear search and return to an empty prompt |
| Ctrl-Z / Ctrl-_ / Ctrl-X Ctrl-U | Undo one edit group | Dismiss the menu, then undo one draft edit group | Undo one search-query edit group and recompute the preview |
| Left / Right | Move the cursor | Dismiss and move the draft cursor; do not accept | Move within the search query; do not accept the preview |
| Typing / Backspace / Delete | Edit the draft | Edit the draft and refresh suggestions for the new context | Edit the search query and recompute the preview |

Acceptance consumes the key. **No key both accepts a candidate or history match
and submits SQL.** After acceptance the next key acts in draft mode. Enter on an
empty draft is a no-op. The normal SQL scanner still determines eligible
statement boundaries, including semicolons inside quotes/comments and pasted
multiple statements; completion does not introduce another submission parser.

Ctrl-P/Ctrl-N browse older/newer history directly from any draft row. In
completion they select the previous/next item, and in search the older/newer
match. This provides a predictable alternative to Up/Down's row-boundary rule.
Ctrl-A/Home and Ctrl-E/End retain their current whole-draft start/end meaning.
Ctrl-U retains deletion from the draft start to the cursor, and clears the
query in history search. Empty-draft Ctrl-D exits; this proposal does not change
the current nonempty-draft Ctrl-D behavior.

While SQL is executing, Ctrl-C retains the existing cancellation/settlement
behavior. Esc neither cancels accepted work nor queues a clear for a future
prompt. Editor undo cannot undo a submitted statement. The external editor owns
its own keys while it has terminal control.

### Opening, refining and accepting completion

1. Tab captures the active statement, cursor and editor generation. Local
   console vocabulary needs no catalog request. Catalog-dependent suggestions
   use the service's authorized assistance operation.
2. If exactly one candidate is returned **and the owner establishes that the
   matching set is complete**, the initial Tab may insert it. Otherwise show
   the list with the first candidate selected and leave text unchanged.
   Until coverage is represented in the shared result, always show the list.
   Automatic insertion uses the same acceptance checks as a selected candidate.
3. Up/Down and Shift-Tab change selection without changing the draft. They wrap
   within the returned list; scrolling the menu never acquires an unbounded
   catalog or invents additional candidates. Tab/Enter accepts, then closes it.
4. Typing while the menu is open refines the context. Immediately invalidate
   the old selection; do not let Enter accept an old item while refreshing.
   A delayed response cannot reopen a menu closed by Esc/Ctrl-G or another mode.
5. Acceptance refreshes catalog/authorization evidence as needed, validates
   the same request and candidate, and applies one atomic text edit. A changed
   source/policy discards the candidate; it must not select a different first
   item or replay the acceptance key against a new result.

Repeated Tab while loading has no deferred effect. Completion loading or
failure never traps ordinary typing, Esc, Ctrl-G, history search or interrupts.
Do not turn a transient empty response into an insertion or a SQL submission.

The replacement range covers the current token, including the part after the
cursor. It preserves suffix tokens, existing whitespace and indentation.
The shared owner supplies identifier quoting and any intentional insertion
padding. Insert a separating space only when the edit requires one; do not
double existing whitespace or add a space before `.` or `)`. No automatic
semicolon, query rewrite, inferred join condition or placeholder SQL is inserted.

### What smart completion knows

| Context | Candidates and constraints |
| --- | --- |
| Empty SQL / keyword prefix | Statement families executable in this session profile, filtered by the prefix |
| `FROM`, `JOIN`, mutation/DDL target | Currently discoverable Tables or configured sources, with operation-specific grammar; discovery does not grant execution permission |
| Projection / predicate / assignments | Columns from the bound source(s), qualifiers and aliases, including sources after the cursor when the production parser can resolve them |
| `alias.` | Only that alias's columns; preserve the qualifier already in the draft |
| Ambiguous column | Valid qualified alternatives; never silently choose a source |
| Aggregates / expressions | Functions, operators and argument continuations admitted by the compiler and relevant column types |
| `INSERT`, `UPDATE`, `DELETE` | The Table compiler's supported columns, assignments and literals; never suggest unsupported expression assignment or `RETURNING` |
| `CREATE` / `ALTER` / `DROP` | Supported Table grammar, schema types and actions; a new object/column name remains user input |
| `SHOW`, `SET`, `RESET` | Registered settings and supported catalog forms; mutable settings only where appropriate, through the actual session assistance route |
| Dot command name | The shared console command vocabulary, with the local command's help summary |
| `.help`, `.mode`, `.timer` arguments | Registered help topics, `table`/`json`, `on`/`off`, respectively |
| `.schema` argument | Currently authorized Table names |
| String / comment | No SQL candidates; leave the text alone |
| Quoted identifier | Exact identifier spelling and escaping, without treating it as a string literal |

Use the active statement around the cursor in a multiline or pasted batch.
Earlier statements and dot commands must not contaminate its scope. Qualified
names, aliases, nesting, literals and comments are parser responsibilities.
If incomplete binding cannot determine a scope, return an explicit unsupported
or unbound context rather than inventing a source.

Supported grammar means the connected interface's **executable profile**, not
every production in the reference grammar. Candidate inclusion is assistance,
not proof of statement validity or permission. Full validation and current
authorization remain at execution.

Do not query row values for suggestions. Typed literal templates such as
`TRUE`/`FALSE` are different from sampling data. History is not a source of
catalog identifiers or completion ranking. File-path completion for `.connect`
and `.execute`, fuzzy typo correction, snippets and generated SQL are outside
this review's first interaction contract.

### Ranking, limits and feedback

Filter by grammar role, binding scope, supported types and current metadata
authorization before prefix matching and ranking. Prefer an exact typed prefix
spelling, then other valid prefix matches; use the grammar role to prioritize
identifiers over general alternatives in name positions. Break remaining ties
deterministically by candidate kind and canonical spelling. Preserve catalog
case and the owner's quoted/unquoted matching rules. No frequency-based or
probabilistic ranking is needed.

Keep eight candidates per response initially. Show as many as fit beneath the
draft while keeping its cursor visible, with a minimum one-item presentation on
short terminals. Use a selection marker and text labels; meaning must not
depend on color. Details are bounded and terminal-escaped. A candidate clipped
in the list has its full spelling available in the selected-item detail.

| Condition | Presentation and next action |
| --- | --- |
| Loading | `Loading suggestions…` after a short delay; typing remains available |
| Complete matching set is empty | `No matching suggestions` |
| Inside a string/comment | `No completion inside this text` |
| Binding/context unsupported | `No suggestions for this SQL context` |
| Candidate or scan budget exhausted | `Showing a limited list; type more to narrow` |
| Service unavailable / request timed out | `Completion unavailable; Tab retries` |
| Metadata changed before acceptance | Keep the draft; discard selection and offer refreshed suggestions without accepting one |
| Permission/session lost | Apply the existing session failure/privacy behavior; erase protected assistance and incompatible in-memory editing state |

Do not display an exhaustive match count without evidence. At a scan budget,
an empty shortlist means incomplete search, not absence. Ranking applies within
the evidence returned by the owner; a bounded partial scan cannot establish a
global best match or a unique match. Large-catalog lookup needs a bounded public
prefix/range operation or continuation, not a resident copy of the catalog or a
larger fixed array. Do not silently remove the current catalog scan budget.

Suggested interaction parameters for qualification: debounce menu refinements
by 75 ms, show loading after 150 ms, and cap a completion acquisition at one
second or the smaller connection request budget. These are proposed UI budgets,
not measurements or server guarantees. A refresh failure never blocks manual
editing or changes SQL execution settings.

### History search and recall

[D5](D5.md) supersedes this review's initial empty filter and Esc clearing with
draft-seeded search and cancellation that restores the saved draft. The original
proposal below records the earlier decision.

Ctrl-R saves the current draft, cursor and edit history, then opens an empty
search query without selecting a command. Typing starts the search; another
Ctrl-R on the empty query selects the newest entry. Search is a literal substring
match with ASCII case folding and exact non-ASCII spelling. Normalize runs of
spaces, tabs and newlines for matching so a one-line search can find multiline SQL. Keep the
original command bytes for preview and insertion. Search never compiles or
executes the preview or fetches catalog metadata.

Start with the most recent matching command. Skip duplicate command text while
navigating a search, without rewriting or deleting the persisted history.
Show `No history matches` when appropriate; never leave an earlier candidate
looking selected. Search changes restart at the most recent match. Ctrl-R/Up
move older; Down moves newer and stops at the newest match. Tab/Enter on an empty
query with no selected match does nothing. Ctrl-G restores the original draft;
Esc abandons it and returns to an empty prompt.

Ordinary Up/Down history browsing preserves the original draft so moving past
the newest entry restores it. Browsing only previews entries. Editing a recalled
entry or accepting a search match installs it as one undoable draft replacement;
neither changes the saved entry. A history match always requires explicit Enter
from draft mode to execute. Saved history remains local text, not a retained SQL
operation or proof of current access.

All history browsing remains paged/bounded through the history owner. A durable
history file may outgrow resident memory. The new search match policy needs
separate fixtures for whitespace, UTF-8, duplicate skipping and bounded scans.

### Undo and terminal keys

Ctrl-Z becomes actual draft undo. Also support Ctrl-_ and the two-key sequence
Ctrl-X then Ctrl-U as alternative bindings, following
[Readline's undo convention](https://www.gnu.org/software/bash/manual/html_node/Miscellaneous-Commands.html).
Retain Ctrl-Space as an optional
alias for requesting completion when its NUL byte reaches the editor; Tab is
the advertised path. Do not claim to fix terminal/desktop interception without
testing that terminal. While the raw console owns editing, Ctrl-Z is consumed
as undo; it must not suspend the process. Cooked/external-editor behavior is
outside that mapping.

Use a bounded volatile edit journal, proposed at 128 groups and 256 KiB combined
storage. One group is a completion insertion, paste, accepted history replacement,
clear, or contiguous typing/deletion run. Cursor movement, mode changes and
whitespace/punctuation boundaries end a typing group. Evict the oldest groups
when either budget is reached; do not persist undo or bound durable history by
this limit. Undo restores text and cursor. Repeated undo walks older groups;
new editing after undo discards the abandoned branch. Redo is deferred.

Search has a separate query-edit journal within the same memory budget. Undo
there edits only the query and refreshes the preview. It cannot mutate the saved
original draft. Leaving search discards that journal. Esc/Ctrl-C clearing is
one undoable change to the original draft; an unaccepted preview is not a draft.
Submitting a statement starts a new draft journal. Session/authorization-loss
cleanup clears all protected snapshots, including undo and saved search drafts.

Decode terminal events before dispatching editor actions. A bare Esc is not
the prefix of an arrow, Home/End, Shift-Tab or bracketed-paste event. Wait for a
bounded escape-sequence interval before treating an isolated Esc as clear;
once a control-sequence prefix is recognized, an unknown/truncated sequence
must not become a clear action. Propose 50 ms for an isolated Esc and 250 ms for
an already-started sequence, to be tested locally and over SSH/multiplexers.
Legacy terminal bytes cannot distinguish all delayed Esc/Alt sequences perfectly;
this timing tradeoff needs explicit qualification.

Bracketed paste preserves line breaks, makes one undo group and never executes.
Do not treat pasted keys as completion/history/clear commands. Do not rely on
Ctrl-S or distinguishable Shift-Enter for the basic workflow. Incremental UTF-8,
CR/LF, input overflow and signal precedence keep their owning input contracts.

### Shared ownership and required contract work

| Owner | Responsibility / gap this review introduces |
| --- | --- |
| Fuze production parsers | Active-statement context, replacement spans, grammar/type expectations and suffix-aware binding; no second grammar in the terminal |
| Query assistance and catalog clients | Authorized candidates, stable ranking, bounded scans and honest completeness/status evidence |
| SQL session protocol/service | Route all advertised assistance, including settings; carry typed status/coverage and source/profile evidence |
| SQL client / terminal adapter | Own and release bounded responses; preserve one in-flight request and one latest desired request, invalidate obsolete generations and join cancelled I/O |
| Terminal editor | Modes, key decoding, bounded undo, viewport/menu presentation, request scheduling and atomic acceptance |
| Console help and public guides | One key map matching implemented behavior; generated/shared command names and arguments |

The current response supplies range, items, profile, resource identity,
contract fingerprint and resource/policy revisions. Preserve these. Before
display and acceptance, check the exact draft generation/cursor, connection,
instance/session/account scope, profile, source identity and revision evidence.
A local request generation does not establish current authorization. Reacquire
through the service before acceptance when required; client cache expiry is not
an authorization check. Loss or change of evidence leaves text unchanged.

The proposed distinctions between complete/limited results and unavailable,
unsupported or no-match contexts need typed shared semantics; the renderer
cannot infer them from an empty array or SQL-text heuristics. Reconcile them
with the existing assistance contract before implementing those UI states.
Any incompatible wire changes follow the current-v1 hard cutover policy,
including a new definition identifier, all consumers, generated schema and
fixtures. This is separate from the future statement/result-set abstraction.

Static dot-command names and enum/help arguments belong to a shared local
vocabulary so opening `.help` suggestions does not require remote catalog
availability. `.schema` names still require current service authorization.
Successful local completion does not override session failure or access-loss
cleanup and does not grant rights to execute a command.

### Acceptance scenarios

These are required checks for implementation, not executed proof results:

- Empty draft, one candidate, multiple candidates, no matches and a truncated
  single-candidate response; no false uniqueness or complete-count claims.
- Tab opens completion outside search; Tab accepts history inside search;
  the next Tab after history acceptance invokes grammar completion.
- Tab/Enter acceptance never executes SQL or a dot command; loading and late
  replies cannot consume a key intended for a later draft.
- Completion in the middle of a token, before a `FROM` suffix, after an alias,
  in a second pasted statement, in quotes/comments, and across UTF-8 boundaries.
- CREATE/ALTER/DROP, typed DML, relational scope and settings through the actual
  SQL session route; unsupported grammar is not offered as executable.
- `.help`, `.mode`, `.timer` complete locally; `.schema` respects remote grants;
  dot command definitions/help/dispatch remain consistent.
- Slow metadata, timeout, disconnect, revocation, schema change and connection
  switch while loading or accepting; no stale disclosure, insertion or request
  queue growth, and no SQL/effects dispatched by assistance.
- Esc from every editing mode returns to an empty prompt; Ctrl-G preserves the
  original; undo restores the appropriate text without restoring stale metadata.
- Repeated typing/deletion/paste/completion/clear undo, journal eviction,
  submission boundary, and access-loss cleanup of every retained draft copy.
- Vertical navigation, history boundary transitions, duplicate/multiline search,
  concurrent append, large history and failure fallback.
- Real PTYs with split escape sequences, literal Esc, arrows, Shift-Tab,
  bracketed paste, Ctrl-Z/NUL delivery, signals, narrow/short terminals and
  redirected stdout. Include manual observations in the user's terminal and an
  SSH/multiplexer path; PTYs alone cannot prove desktop key delivery.

## Review outcome

The user requested grammar/catalog completion outside history search, repair of
ineffective completion/undo shortcuts, and Esc clearing in both history search
and statement/dot-command entry. Those requirements guide this review. The
specific menu, history-navigation, undo and contract choices above were accepted
for implementation on 2026-10-24. The implementation preserves eight retained
candidates and bounded metadata scans, reports incomplete coverage, and refreshes
authorization before insertion. The proof ledger distinguishes terminal peers,
real service checks, and remaining qualification limits.
