# Station gRPC capture v1

Status: M16 implementation contract in progress. The finite transport is qualified;
request layout/publication has independent fixtures; response capture, worker
and SDKs are not yet qualified. It composes
[exchange v1](STATION_EXCHANGE_V1.md) and [publication v1](STATION_PUBLICATION_V1.md)
without widening a kernel turn, mailbox value or effect permit.

## One exact finite attempt

A caller publishes immutable call metadata and a finite outgoing protobuf batch.
Metadata fixes the fully qualified method, call shape, descriptor-set SHA-256,
ordered ordinary metadata and credential references. A configured endpoint scope
must authorize that exact method/descriptor/credential use; neither descriptor
bytes nor a reference grants authority. There is no reflection or schema fetch.

The connector copies authorized request material and the frozen endpoint policy
into an independently owned exchange before committing EXI1. One dispatch permits
one connection, one method invocation, exactly the committed outgoing batch and
its request half-close. Each shape uses the same mechanism: unary/server streaming
require one outgoing message; client/bidirectional streaming permit a bounded
batch. Incoming messages cannot add outgoing messages on the same connection.
A locally written byte or HTTP/2 credit does not establish remote acceptance.

The executor and physical connection incarnation belong to that single effect
attempt. A fresh owner can finish recorded local publication or close an uncertain
attempt; it cannot redial or resend any prefix. An explicit new invocation has a
new linked effect and consumes the original finite EXB2 budget and deadline.
Idempotent retry requires the endpoint's declared policy and the same request
bytes/key. It never changes the original attempt's unknown outcome. A connection
is not a transferable ownership capability. Already authorized I/O retains the
kernel's potentially-in-flight semantics after revocation or closure.

## Caller publication

The caller owns a Publication namespace with two records: metadata ID 1 and batch
ID 2. Both must be sealed before admission. Their digests use protocol format 2;
HTTP retains format 1. A new namespace cannot adopt an occupied publication or
change its frozen reference. Publication advances at most one bounded step per
turn and checks the same content commitments on each resume.

`GRQ1` is the bounded mailbox reference, little-endian after its four magic bytes:
resource:u64, namespace:u64, metadata_bytes:u32, metadata_digest:32 bytes,
batch_bytes:u32, batch_digest:32 bytes, endpoint_revision:u64,
reconcile_before_ms:u64, max_attempts:u32, shape:u8, descriptor_digest:32 bytes.
The resource uses the public growing principal/resource range; namespace and
revision identities preserve full-width unsigned values. All fields are validated
before reading an external source. References are not bearer grants. Cross-realm
references and implicit required resource associations are forbidden.

Metadata is bounded canonical UTF-8 JSON generated by the shared Zig codec,
without whitespace: fields are `version` (1), `method`, `shape` (the transport enum
name), `descriptor_digest` (64 lowercase hex characters) and `metadata`. Each
ordered entry has `name`, then `value` with exactly one `literal_hex` or `secret`
variant. Secret objects have `binding`, then full-width unsigned `version`.
Parsing re-encodes and compares exact bytes; duplicates, extra fields and alternate
representations cannot create ambiguous identities.
Each entry has a lowercase gRPC key and either lowercase `literal_hex` byte data
or an immutable
secret binding/version. Literal binary values require `-bin`; ordinary literals
are printable ASCII. Secret interpolation is confined to explicitly authorized
metadata fields; literal credentials and secrets embedded in protobuf are outside
this profile. The transcript retains references and omission counts, never
rendered credential values. SDKs own their input buffers; Zig owns validation,
publication and durable call identity.

`GRB1` encodes a batch: magic, count:u32, then count repetitions of length:u32
and exactly that many original protobuf bytes. There are no trailing bytes,
compression flags or implicit messages. The storage envelope has an independent
65,544-byte bound, accounting for magic/count and four-byte message lengths. Zero-length protobuf messages are real
messages; an empty batch differs from one empty message. The schema digest fixes
interpretation without re-encoding application bytes during capture or replay.

## Capacity and streaming

The first profile admits at most 64 messages per direction, 16 KiB per message,
64 KiB outgoing framed bytes and 256 KiB incoming framed bytes. Each wire message
charges its five-byte gRPC prefix even when empty. Metadata is at most 8 KiB and
64 entries per block. Endpoint limits can be smaller. Identity compression is
the only encoding; compressed messages and unsupported encodings fail visibly
before expansion. These are per-call limits, not total retained collection limits.

Capture uses bounded 4 KiB parts. An incoming message's index/length/SHA-256 header
precedes its contiguous parts; it is not disclosed as complete until its parts
are sealed. Partial application observations remain provisional until terminal
capture and kernel observation agree. The initial caller API waits for terminal
outcome; it does not stream speculative replies into caller mailboxes. Bounded
replay prefixes likewise remain provisional until full transcript coverage verifies.

The transport alternates partial sends and receive consumption under independently
bounded HTTP/2 credit. It uses one fixed 2 MiB allocation budget and a finite
network deadline. Durable capture backpressure stops further message consumption;
capacity refusal never permits dropping accepted messages, deleting history or
releasing obligations. The growing control reserve admits its defined kernel
control commands, not arbitrary capture turns or framework cleanup. Deployment
admission must reserve ordinary capacity for that work before dispatch.

## Capture, completion and recovery

Request metadata, original batch and exact endpoint policy precede the effect
intent. The response log records initial metadata, monotonically indexed incoming
messages, the locally observed request half-close, trailers, timing, omissions
and terminal counts. Directional order is preserved; local callback order does
not invent cross-direction causality. The batch records planned outgoing bytes.
Only the terminal counts record how much this executor actually wrote; a crash
cannot invent those counts or remote durable offsets.

A terminal envelope requires END_STREAM on the exact trailers block, or on the
initial Trailers-Only block. Missing/duplicate status, premature status, malformed
ordering, truncated messages, unqualified compression and budget exhaustion cannot
produce complete success. `OK` additionally requires the cardinality of the
selected response shape; non-OK may legitimately contain no response message.
RPC status is not an application rollback guarantee. A peer can terminate before
the whole outgoing batch is sent; terminal metadata preserves actual counts and
whether local request half-close occurred.

Exchange completion names sealed capture, then the authenticated executor submits
its kernel observation. Closure can win that race; complete orphaned capture is
then evidence, not an observed caller result. Settlement checks the frozen effect,
attempt, executor and deadline. Reply routing uses the original authenticated
caller PID/correlation; termination and name rebinding cannot redirect a late
outcome to a replacement process. Unknown/partial results never trigger redial.

## Reads and lifetime

Use the common current-availability reader for every bounded part. Validate the
protocol format, schema identity, message indices, lengths, digests, directional
counts and final coverage. A retained source, stale cursor or cached manifest
cannot bypass current transcript permissions or retirement. Replay accepts no
socket, reflection or credential resolver and returns explicit gaps on incomplete
or required omitted data.

Caller disposal, other consumer tokens, descendant holds, terminal settlement,
retirement and bounded physical reclamation retain their EXB2/exchange meanings.
Unlimited retention is the default. Unknown remote effects retain their recovery
evidence and finite closure obligation; quota pressure does not discharge either.
SDK disposal requires an authenticated durable call, independently of transcript
read access. A method/schema decoder has no authority over those lifetimes.
