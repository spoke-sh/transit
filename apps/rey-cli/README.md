# rey-cli

Small signed Transit operator client, built on
[transit-client](../../packages/zig/transit-client/README.md). It derives public
keys, signs requests, submits mutations, and reads a PID-scoped view. It has no
raw Ursula or provider access; operators still need current Transit grants.

The executable keeps its historical `rey-cli` name for compatibility. Its role
is Transit protocol administration; it contains no trading application logic.
`kubectl transit` instead observes Kubernetes resources, while Board exposes
shared read-only system inspection. These tools have different credentials and
authority boundaries.

## Build and use

From the repository root in `nix develop`, run `just build::debug apps`, then:

```sh
zig-out/bin/rey-cli public-key PRIVATE_SEED_FILE
zig-out/bin/rey-cli sign PRIVATE_SEED_FILE REQUEST.json
zig-out/bin/rey-cli submit PRIVATE_SEED_FILE REQUEST.json http://127.0.0.1:8080
zig-out/bin/rey-cli view PRIVATE_SEED_FILE READ.json http://127.0.0.1:8080
```

Seed files contain 32 cryptographically generated bytes as hex; protect them
with owner-only permissions or secret mounts. Seeds are not argv values or logs.
Save a mutation request before submitting; retry that request after a lost
response, not a new sequence. Fixed unit-test keys are fixtures only.

`REQUEST.json` is an unsigned v2 `Request`, including realm, principal, mutation
sequence, and command. `sign` emits its `SignedRequest`; `submit` signs and sends
it and prints a receipt. `READ.json` uses `sequence: 0` and
`command: {"inspect": PID}`; `view` prints the authenticated bounded process view.
See the [wire profile](../../contracts/TRANSIT_V2.md) and
[service contract](../../contracts/SERVICE_V2.md) for exact formats and grants.
The CLI is intentionally small; it is not yet a general registry, transcript,
or history browser.

## Source and verification

[main.zig](main.zig) owns argument parsing and secret-file handling.
`just test::service` exercises the CLI through real signed ingress. Complete
setup and caller workflows are available under [examples](../../examples/README.md).

## Inspection queries

`rey-cli inspect SEED QUERY.json URL` uses the public bounded inspection client.
For example, `{"realm":72,"principal":1,"resource":"processes"}` discovers the
processes allowed by that principal. `sign-inspection SEED QUERY.json` emits a
signed envelope for other transports. See [inspection v1](../../contracts/INSPECTION_V1.md).

## Diagnostics

The CLI uses [bounded telemetry](../../packages/zig/telemetry/README.md) on stderr.
`LOG_LEVEL=debug LOG_FORMAT=json` includes client attempts and lifecycle records;
default verbosity reports failures. Signed requests, public-key output and receipts
remain machine-readable stdout; secrets, request bodies and URLs are excluded
from diagnostics. An uncertain submission still requires the same saved request.

## State queries

`rey-cli state SEED QUERY.json URL` reads the signed state-resource API;
`sign-state SEED QUERY.json` emits its envelope. For example,
`{"realm":72,"principal":1,"kind":"resources"}` lists authorized metadata.
Use `kind: "associations"` with `pid`, or `kind: "entries"` with `resource` for
bounded KV reads. Value reads require a resource read grant independently of
PID inspection. See [state v1](../../contracts/STATE_V1.md) for pagination,
capabilities and lifecycle outcomes. Mutations use the existing `submit` command
with the nested `state` command family.
